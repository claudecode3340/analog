Before you can do machine learning on your own computer, you need four things working together: a place to type commands (Terminal), a copy of Python with the right libraries, a code editor, and the course files. This lesson installs all of them on your Mac, one small step at a time, and tells you exactly what you should see after every step, so you always know whether it worked.

By the end of this lesson you can

  • open Terminal, read its prompt, and move around your folders with pwd, ls, cd and mkdir;
  • install the Xcode Command Line Tools and uv, then make a private Python environment for this course;
  • install NumPy, pandas, matplotlib, scikit-learn, statsmodels, ISLP, JupyterLab and PyTorch, and check that each one imports;
  • open a notebook in VS Code (or JupyterLab), choose the right kernel and run a cell with Shift + Enter;
  • download the course data pack and any lesson as a notebook, and fall back to Google Colab if something on your Mac breaks;
  • fix the six most common setup errors by yourself.

How to use this lesson. Do it with your Mac open next to this page. Go in order. After each step, compare your screen with the grey "What you should see" box. If yours looks different, stop there and use the troubleshooting table near the end before going on. Plan on about an hour, most of it waiting for downloads. You only do this once.

The big picture: how the pieces fit

Here is everything you are about to install, and how each piece talks to the next. Don't worry if the names mean nothing yet: each one gets its own step below, and you can come back to this picture whenever you feel lost.

Think of a kitchen. Terminal is you giving instructions out loud. uv is the assistant who goes shopping. The .venv is one labelled cupboard holding exactly the ingredients for this course, so they never get mixed up with anything else on the Mac. VS Code is the worktop where you cook, and notebooks are your recipe cards with space to write results in.

Why not just "install Python"? Because different projects need different versions of the same libraries, and a Mac already has a few copies of Python inside it that macOS itself uses. If you install things into those, you can break other software, and you lose track of what is where. A virtual environment (the .venv folder) is the professional answer: one self-contained Python per project. Every ML engineer works this way, so learning it now is part of the job.

Step 0 · Which Mac do you have?

Click the Apple logo in the top-left corner of the screen and choose About This Mac. Look at the first line under the picture:

  • Chip: Apple M1, M2, M3, M4 (or Pro / Max / Ultra versions): you have an Apple Silicon Mac. This lesson is written for you. Everything works, including fast PyTorch on the Mac's own graphics chip.
  • Processor: … Intel Core i5 / i7 / i9: you have an Intel Mac. Almost everything is the same. The few differences are marked with Intel: in the steps below; the biggest one is PyTorch.

Also note the macOS version written in large letters (for example "Sonoma 14.5" or "Sequoia 15.1"). Anything from macOS 13 (Ventura) onward is fine. Step 1 · Open Terminal

Terminal is an app that lets you control your Mac by typing short commands instead of clicking. It looks old-fashioned, but it is how programmers install software, run programs and manage code. You will use it a little every day, and in a week it will feel normal.

  1. Press ⌘ Cmd + Space. A search bar called Spotlight appears in the middle of the screen.
  2. Type Terminal. The first result shows a small black window icon.
  3. Press Return. A window opens with a line of text and a blinking block.
  4. So that you never have to search again: right-click (or two-finger click) the Terminal icon in the Dock at the bottom of the screen → Options → Keep in Dock.

(The other way to find it: Finder → Applications → Utilities → Terminal.)

What you should see

Last login: Sat Oct 17 09:12:04 on ttys000
you@MacBook-Air ~ %

Your name and your Mac's name will be different. The window may be white rather than black; both are fine.

Reading the prompt

The line you@MacBook-Air ~ % is called the prompt. It is Terminal saying "I'm ready, type a command". Each piece means something:

PieceWhat it meansExample
youyour user name on this Macasha, rahul, …
@MacBook-Air"at" this computer's name@Ashas-MacBook-Pro
~the folder you are in right now. The squiggle, called tilde, is short for your home folder, /Users/youlater it may say ml-course
%end of the prompt: your typing starts after it. (Some guides on the internet show $ instead; it means the same.)never type the % yourself

The program reading your commands is called zsh (said "zee-shell"). It is the Mac's standard shell. You'll see its name in some error messages, such as zsh: command not found.

Six habits that make Terminal friendly

  • Type exactly. Spaces matter, and commands are written in lower case. uv --version has a space before the two dashes and none after.
  • Press Return to run what you typed. Nothing happens until you do.
  • Copy and paste are fine. Select a command in this page, ⌘ + C, click in Terminal, ⌘ + V, then Return. Copy only the command, never the prompt.
  • Up arrow ↑ brings back the previous command, so you can fix a typo and run it again.
  • Tab completes names. Type cd Doc and press Tab: zsh finishes it to cd Documents/.
  • Ctrl + C stops whatever is running and gives you a fresh prompt. (Ctrl, not ⌘: this is the one place on a Mac where Control matters.)

Step 2 · Your first commands: where am I, what is here, go there

Your Mac's files are arranged like an upside-down tree. At the very top is the root, written /. Inside it is a folder Users, inside that your home folder you, and inside that the folders you know from Finder: Desktop, Documents, Downloads. A path is the list of folders from the top down to a place, joined with slashes: /Users/you/Documents means "start at the root, go into Users, then you, then Documents". Terminal is always "standing" in one folder, called the current folder (or working directory). Four commands are enough to move around:

Two more you will meet: ls -a lists all items, including hidden ones whose names start with a dot (such as .zshrc, a settings file, and later .venv). clear wipes the screen when it gets messy (your files are not touched). And open . opens the current folder in a Finder window: the single dot . means "this folder here".

Step 4 · Install uv, the Python manager

uv is a small, very fast program that does three jobs: it downloads the exact version of Python you ask for, it creates virtual environments, and it installs Python libraries into them. Older guides use separate tools for each job (pyenv, venv, pip, conda); uv does all three and is 10–100 times faster. It is what many ML teams use today.

Type (or paste) this exactly

curl -LsSf https://astral.sh/uv/install.sh | sh

Every piece, one by one:

  • curl: a program that downloads a file from a web address (client for URLs).
  • -LsSf: four one-letter options squeezed together, the same as -L -s -S -f. -L follow redirects (if the address says "moved, look over there", follow it); -s silent (no progress bar); -S but still show an error if something goes wrong; -f fail quietly on a server error instead of saving an error page as if it were the script.
  • https://astral.sh/uv/install.sh: the address of uv's official installer script, from Astral, the company that makes uv.
  • |: the pipe (Shift + \). It sends the output of the command on its left straight into the command on its right.
  • sh: the shell, which runs the script it receives. So the whole line means "download uv's installer and run it".

What you should see (version numbers will be newer)

downloading uv 0.9.5 aarch64-apple-darwin
no checksums to verify
installing to /Users/you/.local/bin
  uv
  uvx
everything's installed!

To add $HOME/.local/bin to your PATH, either restart your shell or run:

    source $HOME/.local/bin/env (sh, bash, zsh)

aarch64-apple-darwin means "Apple Silicon Mac". Intel: you will see x86_64-apple-darwin instead. Both are right.

Only pipe scripts into sh from sources you trust. Running a downloaded script gives it the same power over your account as you have. uv's official site is trustworthy; a random forum post is not. When in doubt, ask before you paste.

Restart Terminal, then check

The installer put uv in a hidden folder, ~/.local/bin, and told your shell to look there for programs. The list of folders the shell searches for programs is called the PATH. Your open Terminal window read the PATH when it started, so it doesn't know about the change yet. Quit Terminal completely (⌘ + Q), open it again from the Dock, and type:

Type this

uv --version

What you should see

uv 0.9.5 (d5f39331a 2025-10-21)

Any version number means success. If you get zsh: command not found: uv, you didn't fully restart Terminal; quit with ⌘Q (closing the window is not enough) and try again. Still failing? Run source $HOME/.local/bin/env, then uv --version again.

If you already use Homebrew

Homebrew is a popular installer for Mac software. If you have it (brew --version prints a number), brew install uv works just as well. If you don't have Homebrew, you don't need it for this course.

Step 5 · Make the course folder and its private Python

Now you make one folder for the whole course and give it its own Python. Type each line and press Return after it:

Type this

cd ~
mkdir ml-course
cd ml-course
uv venv --python 3.12
  • cd ~: go to your home folder first, so the course folder ends up in a predictable place, /Users/you/ml-course. From now on, ~/ml-course is its short name.
  • mkdir ml-course: make the folder. cd ml-course: walk into it.
  • uv venv: "uv, make a virtual environment here". It creates a folder named .venv (the dot makes it hidden in Finder).
  • --python 3.12: put Python version 3.12 inside it. If your Mac doesn't have 3.12, uv downloads it for you (about 20 MB). We use 3.12 because every library in this course supports it fully.

What you should see

Using CPython 3.12.12
Creating virtual environment at: .venv
Activate with: source .venv/bin/activate

You may also see a line like Downloading cpython-3.12.12-macos-aarch64-none (16.3MiB) first. That is uv fetching Python. CPython is the name of the standard Python program.

Activate the environment, and what (.venv) means

The environment exists, but your Terminal isn't using it yet. Activating it tells this Terminal window: "when I say python, I mean the Python inside .venv".

Type this (you must be inside ~/ml-course)

source .venv/bin/activate
  • source: run the commands in a file inside the current shell, so their changes stick to this window.
  • .venv/bin/activate: the path to a small script uv made, in the bin folder of .venv. It puts .venv/bin at the front of your PATH.

What you should see

(.venv) you@MacBook-Air ml-course %

The (.venv) at the start of the prompt is the sign that the environment is active. Look for it every time before you install or run anything. If it's not there, you are using the wrong Python.

Prove which Python you're now using:

Type this

which python
python --version

What you should see

/Users/you/ml-course/.venv/bin/python
Python 3.12.12

which answers "which program will run if I type this name?". The answer is inside your .venv: exactly right.

The two lines you'll type at the start of every work session, in every new Terminal window:

cd ~/ml-course
source .venv/bin/activate

Activation lasts only for that window. Close the window and it's gone (that is normal, nothing is lost). To leave the environment without closing the window, type deactivate.

Step 7 · Check that everything imports

To import a library means to load it into Python so you can use it. If every import works, the installation worked. You can run a tiny Python program straight from Terminal:

Type (or paste) this as one line

python -c "import numpy, pandas, sklearn, statsmodels, ISLP; print('all good')"
  • python: start the Python inside .venv (because it's active).
  • -c: "the code to run comes next, in quotes", instead of from a file.
  • import numpy, pandas, sklearn, statsmodels, ISLP: load five libraries. Note that scikit-learn is imported as sklearn.
  • ; separates two Python statements on one line. print('all good') prints a message, which only happens if every import before it worked.

What you should see

all good

It may take 5–10 seconds the first time, because Python prepares each library on first import. Later imports are faster.

If it fails, Python stops at the first problem and prints an error ending in a line like ModuleNotFoundError: No module named 'ISLP'. Read the last line; it names the culprit. Then:

The last line saysWhat it meansWhat to do
No module named 'numpy' (or any of them, even the first one)Python can't find the libraries. Almost always: the environment isn't active, so you're using a different Python.Look for (.venv). If missing: cd ~/ml-course then source .venv/bin/activate, then try again.
No module named 'ISLP' but the others workedThat one package didn't install (often a network hiccup, or the Intel PyTorch problem).Run uv pip install ISLP on its own and read its last lines. On Intel, use the Intel command above.
No module named 'sklearn'scikit-learn isn't installed.uv pip install scikit-learn (install with the long name, import with the short one).
zsh: command not found: pythonNo environment is active and macOS only knows python3.Activate the environment. Inside it, python always exists.
a long error mentioning numpy and "compiled using NumPy 1.x"Two libraries disagree about NumPy versions (mostly Intel Macs).uv pip install "numpy<2", then check again.

A more informative check prints each library's version. You'll paste this into a notebook in Step 9, and you can run it right here in the page now. It uses the same code your Mac will run:

import sys
import numpy, pandas, matplotlib, sklearn, statsmodels, ISLP

print("Python      ", sys.version.split()[0])
for lib in [numpy, pandas, matplotlib, sklearn, statsmodels, ISLP]:
    print(f"{lib.__name__:12}", lib.__version__)
print("all good")
What you see: one line per library with its version number. In this page the versions are the ones built into the browser; on your Mac they will usually be a little newer, which is fine. Don't worry about understanding every word of this code yet: for loops and the f"..." text formatting are taught in Python I.

Step 8 · PyTorch, and your Mac's graphics chip

PyTorch is the library for building and training neural networks; you start it in month 3. ISLP already brought PyTorch with it, but we also want torchvision, its companion for images. Install both now so it's done (uv will skip whatever is already there):

Type this (with (.venv) active)

uv pip install torch torchvision

What you should see

Resolved 30 packages in 1.20s
Prepared 1 package in 2.05s
Installed 1 package in 38ms
 + torchvision==0.24.0

If both were already present you'll see Audited 2 packages, which means "nothing to do".

Apple Silicon Macs have a built-in graphics chip (GPU) that PyTorch can use through Apple's MPS (Metal Performance Shaders) system. Training on it is often 5–20 times faster than on the main processor. Check that PyTorch can see it:

Type this

python -c "import torch; print(torch.__version__, torch.backends.mps.is_available())"

What you should see on Apple Silicon

2.9.0 True

True means PyTorch can use the GPU. Intel: you'll see 2.2.2 False. That is expected: Intel Macs have no MPS. PyTorch then uses the main processor (CPU), which is fine for the small networks in this course; Colab gives you a GPU when you want one.

The cell below is a PyTorch cell. Cells like this are marked to run only on your Mac, because PyTorch is too big for the browser. The output shown was made on a computer without an Apple chip, so it says mps available: False; on your Apple Silicon Mac it should say True.

import torch

print("torch version :", torch.__version__)
print("mps available :", torch.backends.mps.is_available())
device = "mps" if torch.backends.mps.is_available() else "cpu"
x = torch.ones(3, device=device)   # three 1s, stored on the GPU if there is one
print("computed on   :", device, "->", (x * 2).tolist())
What you see: the version, whether the GPU is usable, and a tiny calculation (three 1s doubled) done on whichever device is available. If this prints [2.0, 2.0, 2.0] on your Mac, PyTorch works end to end.

Step 9 · Install VS Code and run your first notebook

VS Code (Visual Studio Code) is a free code editor from Microsoft, and the most used one in the world. You'll write Python files and notebooks in it. A notebook (a file ending in .ipynb, short for IPython notebook) is a document made of cells: text cells and code cells. You run one code cell at a time and its output appears right underneath it, just like in this page.

Install it

  1. In your web browser, go to code.visualstudio.com and click the big Download for macOS button. (It's a "Universal" download that works on both Apple Silicon and Intel.)
  2. A file like VSCode-darwin-universal.zip appears in your Downloads folder. Double-click it: it unzips into an app called Visual Studio Code.
  3. Open a Finder window, click Applications in the sidebar, and drag Visual Studio Code from Downloads into Applications. (This matters: an app run from Downloads can't update itself properly.)
  4. Open it from Applications (or Spotlight: ⌘ + Space, type "Visual Studio Code"). macOS asks "Are you sure you want to open it?" because it came from the internet. Click Open.
  5. Right-click its Dock icon → Options → Keep in Dock.

Add the Python and Jupyter extensions

An extension is an add-on that teaches VS Code a new skill. You need two, both made by Microsoft:

  1. Click the Extensions icon in the left sidebar (four small squares, one flying off), or press ⇧ Shift + ⌘ + X.
  2. In the search box type Python. Click the one called Python whose publisher is Microsoft (it has a blue tick and many millions of installs). Click Install. It also installs "Pylance" and "Python Debugger" automatically; that's expected.
  3. Search Jupyter and install the Jupyter extension by Microsoft the same way.

Open the course folder and make a notebook

  1. File → Open Folder…, then go to your home folder (in the window's sidebar, or press ⇧ + ⌘ + H), click ml-course once, then Open. If asked "Do you trust the authors of the files in this folder?", click Yes, I trust the authors (you are the author).
  2. Press ⇧ + ⌘ + P to open the Command Palette (a search box for every VS Code action). Type new jupyter and choose Create: New Jupyter Notebook.
  3. Top right of the notebook, click Select Kernel → Python Environments… → choose the one that says .venv and Python 3.12 (its path ends in ml-course/.venv/bin/python). A kernel is the Python program that actually runs a notebook's cells; choosing .venv means it uses the libraries you just installed.
  4. Click in the first cell and type print("hello from my Mac"). Press Shift + Enter. The output appears under the cell, with a small green tick, and a new empty cell opens below.
  5. Paste the version-check code from Step 7 into the new cell and run it. You should see your Mac's version numbers and all good.
  6. Save with ⌘ + S; call it test.ipynb. It's now a file in ~/ml-course.

Plan B · Google Colab, when your Mac won't cooperate

Google Colab runs notebooks on Google's computers, in your browser, for free. Nothing to install. Use it if your setup is stuck and you want to keep learning while you fix it, or when you want a free GPU for PyTorch.

  1. Go to colab.research.google.com and sign in with a Google account.
  2. File → Upload notebook and choose a lesson's .ipynb, or File → New notebook.
  3. In the first cell, install what Colab doesn't already have, then run it: !pip install ISLP. The ! at the start means "run this as a Terminal command, not as Python".
  4. To use a data file: click the folder icon on the left, then the upload icon, and choose the CSV file from your ml-course folder.
  5. For PyTorch with a GPU: Runtime → Change runtime type → T4 GPU.

Colab forgets everything (installed packages, uploaded files, variables) when the session ends, usually after about 90 minutes of inactivity. Download your notebook (File → Download → .ipynb) before you stop, and re-run the install cell next time.

Check yourself

Your prompt reads you@MacBook-Air ml-course %. What does ml-course tell you?

  1. The name of your Mac
  2. The folder Terminal is currently in
  3. That the environment is active
  4. The command you just ran
The part just before % is the current folder (its last part only; pwd prints the full path). The Mac's name comes after the @. An active environment shows (.venv) at the start of the prompt, which isn't there, so it is not active.

You open a brand-new Terminal window and type python -c "import pandas". It says zsh: command not found: python. What is the most likely cause?

  1. pandas isn't installed
  2. uv isn't installed
  3. You haven't gone to ~/ml-course and activated the environment in this new window
  4. Your Mac is Intel
Activation lasts only for the window where you did it. A fresh window needs cd ~/ml-course and source .venv/bin/activate again. If pandas were the problem, Python would at least start and then say ModuleNotFoundError.

What does cd .. do?

  1. Moves you up one folder, to the folder that contains the current one
  2. Moves you to your home folder
  3. Lists the hidden files
  4. Goes back to the previous command
.. always means "the parent folder". Home is cd ~ (or plain cd). Hidden files are shown by ls -a. The previous command comes back with the ↑ key.

In curl -LsSf https://astral.sh/uv/install.sh | sh, what does the | do?

  1. It separates two unrelated commands
  2. It saves the download to a file called sh
  3. It is part of the web address
  4. It sends what curl downloaded straight into sh, which runs it
The pipe connects the output of the left command to the input of the right one. Nothing is saved to disk; the script flows from curl into the shell.

A notebook in VS Code says ModuleNotFoundError: No module named 'sklearn', but in your activated Terminal the import check prints all good. What should you do first?

  1. Reinstall scikit-learn
  2. Check the kernel (top right of the notebook) and choose the .venv Python 3.12 one
  3. Restart the Mac
  4. Install Anaconda
The library exists in .venv (Terminal proved it), so the notebook must be using a different Python. The kernel picker decides which Python runs the notebook.

On an Apple Silicon Mac, torch.backends.mps.is_available() returns True. What does that mean?

  1. PyTorch isn't installed correctly
  2. You must use Google Colab
  3. PyTorch can run calculations on the Mac's built-in GPU
  4. Your Mac is Intel
MPS is Apple's GPU system; True is the good result. On an Intel Mac it would be False and PyTorch would use the CPU.

You type -LsSf after curl. How many separate options is that?

Four one-letter options squeezed together: -L, -s, -S, -f. Note that -s and -S are different options: capital letters matter.

In two or three sentences, explain to a friend why we make a .venv instead of installing libraries into the Python that comes with the Mac.

macOS uses its own Python for itself, and installing into it can break things or need administrator rights. A virtual environment is a private, self-contained Python for one project, so the exact library versions for this course live in one folder, never clash with other projects, and can be deleted and rebuilt in minutes if something goes wrong.
Terminal: what do pwd, ls, cd and mkdir do?
pwd prints the current folder; ls lists its contents; cd NAME moves into a folder; mkdir NAME makes a new folder.
What do ~, . and .. mean in a path?
~ your home folder (/Users/you); . the current folder; .. the folder above (the parent).
The two commands that start every work session
cd ~/ml-course then source .venv/bin/activate
What does (.venv) at the start of the prompt tell you?
The course's virtual environment is active: python and installs now use ~/ml-course/.venv.
Command to create a virtual environment with Python 3.12 using uv
uv venv --python 3.12 (run inside the project folder; creates .venv)
Command to install a library into the active environment with uv
uv pip install NAME, for example uv pip install pandas
How do you stop a running program in Terminal?
Ctrl + C (Control, not Command)
What is a notebook "kernel"?
The Python program that runs the notebook's cells. Choose the .venv one so the notebook sees your libraries.
ModuleNotFoundError in a notebook, but the import works in the activated Terminal. Fix?
The notebook is using the wrong kernel: select the .venv (Python 3.12) kernel.
What is MPS in PyTorch?
Metal Performance Shaders: Apple's way for PyTorch to use the GPU on Apple Silicon Macs. Check with torch.backends.mps.is_available().
Why does zsh say no matches found for uv pip install numpy<2?
zsh treats < [ ] * ? as special characters. Quote it: "numpy<2".
