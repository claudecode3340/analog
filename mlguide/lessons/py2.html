1 · Dictionaries: look things up by name

A list finds things by position: marks[2]. Often you want to find things by name instead: "the horsepower of this car", "the learning rate of this model". A dictionary (type dict) stores key: value pairs, like a real dictionary stores word: meaning. You write it with curly braces:

# the first car in ISLP's Auto data set
car = {"name": "chevrolet chevelle malibu", "mpg": 18.0, "cylinders": 8, "horsepower": 130}
print(car["mpg"])            # look up by key, with square brackets
print(car["name"].title())
car["weight"] = 3504         # add a new key: value pair
car["mpg"] = 18.5            # change the value of an existing key
print(car)
print(len(car), "horsepower" in car, "price" in car)
Read the output: 18.0; then the name in Title Case; then the whole dictionary, now with 'weight': 3504 added at the end and mpg changed to 18.5 (assigning to a key that exists replaces its value; to a new key, adds it). len counts the pairs (5). in checks the keys: "horsepower" in car is True, "price" in car is False.

Keys must be unique (one meaning per word), and are usually strings or numbers. Values can be anything, including lists and other dictionaries. Asking for a key that isn't there is an error:

print(car["Horsepower"])     # capital H: a different key!
Read the error: KeyError: 'Horsepower'. Keys are matched exactly, including capitals. You'll see this error constantly with pandas, where column names are dictionary-like keys. Fix: car["horsepower"], or car.get("Horsepower", "not found") if a missing key is expected.

Looping over a dictionary

settings = {"learning_rate": 0.01, "epochs": 20, "batch_size": 32}
for key, value in settings.items():
    print(f"{key:>14} = {value}")
Read the output: one line per pair, the keys right-aligned in 14 characters so the = signs line up. .items() gives each pair as two values, which the loop catches in two names, key and value (this "catching two at once" is unpacking, explained in section 3). Dictionaries keep the order in which you inserted the keys.

2 · Sets: unique values

A set is an unordered collection with no duplicates. Use it to find the distinct values in a column, or to ask "is this in here?" very quickly even for millions of items.

cylinders = [8, 8, 4, 6, 4, 4, 8, 3, 5, 4]
distinct = set(cylinders)
print(distinct, len(distinct))
print(sorted(distinct))           # a sorted list of the distinct values
distinct.add(12)                  # sets use add, not append
print(4 in distinct, 7 in distinct)
a, b = {"mpg", "weight", "year"}, {"weight", "year", "origin"}
print(a & b, a | b, a - b)       # in both; in either; in a but not b
Read the output: the set {3, 4, 5, 6, 8} with 5 distinct values (the order a set prints in isn't guaranteed, which is why we use sorted to get a tidy list). in works as for lists. The last line shows set algebra, like Venn diagrams: & intersection, | union, - difference. These three sets may print their items in a different order on your Mac; that's normal for sets. An empty set is written set(), because {} is an empty dictionary.

3 · Tuples and unpacking

A tuple is like a list that can't be changed: written with round brackets, (3, 4). Use it for a small, fixed group of values that belong together: a point (x, y), an image size (height, width), or several results returned from one function. NumPy array shapes are tuples, so you'll see them every day.

Unpacking means catching the parts of a tuple (or list) in several names at once: x, y = (3, 4) sets x = 3 and y = 4. The number of names must match the number of parts.

point = (3.0, 4.0)
x, y = point                       # unpacking
print(x, y, (x ** 2 + y ** 2) ** 0.5)

def lo_hi(xs):
    """Return the smallest and largest value."""
    return min(xs), max(xs)        # two values, returned as one tuple

result = lo_hi([62, 75, 81, 70])
print(result, type(result))
low, high = lo_hi([62, 75, 81, 70])
print("range:", high - low)

a, b = 1, 2
a, b = b, a                        # swap in one line
print(a, b)
Read the output: 3.0 4.0 5.0 (the distance from the origin, \(\sqrt{3^2+4^2}=5\)). lo_hi returns (62, 81), a tuple: writing return min(xs), max(xs) with a comma packs both into one tuple. Unpacking it straight into low, high gives a range of 19. The swap works because the right side (b, a) is built first, then unpacked.
shape = (506, 13)       # rows, columns
shape[0] = 500          # tuples can't be changed
Read the error: TypeError: 'tuple' object does not support item assignment. That's the point of a tuple: once made, it stays as it is. If you need to change things, use a list.

4 · while loops: repeat until done

A for loop runs once per item; you know in advance how many times. A while loop repeats as long as a condition is true, which is what you want when you don't know how many steps it will take: "keep training while the error is still too big".

error = 1.0
steps = 0
while error > 0.01:          # check the condition before every trip
    error = error / 2        # pretend each training step halves the error
    steps = steps + 1
print(f"stopped after {steps} steps, error = {error}")
Read the output: stopped after 7 steps, error = 0.0078125. Trace it: 1 → 0.5 → 0.25 → 0.125 → 0.0625 → 0.03125 → 0.015625 → 0.0078125. After 6 halvings the error (0.0156) is still above 0.01, so one more trip runs; after the 7th it's 0.0078, the condition is false, and the loop stops. Change the tolerance to 0.001 and predict the number of steps first (hint: \(2^{10}=1024\)).

The endless loop. If nothing inside a while loop ever makes the condition false (say you forgot error = error / 2), it runs forever. In this page a cell is stopped after a minute; in a notebook on your Mac, press the ■ stop button (or Ctrl + C in Terminal). Always check: what changes on every trip, and will it eventually make the condition false?

Two keywords control any loop: break leaves the loop at once, and continue skips to the next trip. Use them sparingly; they're handy for "stop when found":

losses = [0.90, 0.61, 0.45, 0.38, 0.36, 0.37, 0.41]
for epoch in range(len(losses)):
    if epoch > 0 and losses[epoch] > losses[epoch - 1]:
        print(f"loss went up at epoch {epoch}: stop early")
        break
    print(f"epoch {epoch}: loss {losses[epoch]}")
Read the output: epochs 0 to 4 print their loss; at epoch 5 the loss (0.37) is higher than at epoch 4 (0.36), so the loop prints the warning and breaks; epoch 6 is never reached. This is the idea behind early stopping, a regularisation method you'll meet in month 3.

The condition is checked before each trip, so a start that is already small enough gives 0 steps. 5 · enumerate, zip and range, in depth

In Python I you walked two lists together with for i in range(len(y)) and y[i], y_hat[i]. It works, but it's clumsy and easy to get wrong. Two helpers do it better:

  • enumerate(xs) gives pairs (index, item): use it when you need the position and the item.
  • zip(a, b) gives pairs (a[0], b[0]), (a[1], b[1]), …: use it to walk two (or more) lists side by side, like a zip fastener joining two rows of teeth.
names = ["Asha", "Ben", "Chen"]
marks = [62, 75, 81]
for i, name in enumerate(names):
    print(i, name)
for name, mark in zip(names, marks):
    print(f"{name} scored {mark}")
print(list(enumerate(names, start=1)))
print(list(zip(names, marks)))
Read the output: enumerate numbers the names 0, 1, 2. zip pairs each name with its mark. Both give tuples, which the loop unpacks into two names. start=1 makes enumerate count from 1, handy for printing "rank 1, 2, 3". Wrapping them in list(...) shows every pair at once: [(1, 'Asha'), (2, 'Ben'), (3, 'Chen')] and [('Asha', 62), ('Ben', 75), ('Chen', 81)].

list(zip([1, 2, 3], ["a", "b"])) gives…

  1. an error, because the lists have different lengths
  2. [(1, 'a'), (2, 'b')]
  3. [(1, 'a'), (2, 'b'), (3, None)]
zip stops as soon as the shortest list runs out, silently. That's convenient, but it can hide a bug: if your predictions list is accidentally shorter than your targets, zip won't complain. In real code, check len(y) == len(y_hat) first (or use zip(a, b, strict=True), which raises an error on a length mismatch).
print(list(zip([1, 2, 3], ["a", "b"])))
Read the output: [(1, 'a'), (2, 'b')]: the 3 had no partner, so it was dropped.

range deserves a second look too. It doesn't store its numbers in memory; it works them out as the loop asks for them, so range(1_000_000_000) costs nothing until you loop over it. (Underscores inside a number are allowed for readability.) A few more of its tricks:

r = range(10, 0, -3)              # count down in steps of 3
print(list(r), len(r))
print(list(range(0)))             # zero numbers: a loop over it never runs
print(list(reversed(range(5))))   # 4, 3, 2, 1, 0
print(9 in range(0, 10, 3))       # is 9 one of 0, 3, 6, 9?
Read the output: [10, 7, 4, 1] 4: it starts at 10 and keeps subtracting 3 while it stays above the stop value 0. range(0) is empty, [], so a loop over it runs zero times (the reason for i in range(len(xs)) is safe on an empty list). reversed walks any sequence backwards. in works on ranges: True. Rule of thumb: use for x in xs when you need only the items, enumerate when you also need positions, zip for several lists side by side, and range when you need plain counting.

With zip, the MSE loop reads almost like the formula \(\frac1n\sum (y_i-\hat y_i)^2\):

y     = [3, 5, 7]
y_hat = [2.5, 5, 8]
total = 0
for yi, yhi in zip(y, y_hat):
    total += (yi - yhi) ** 2
print("MSE:", total / len(y))
Read the output: MSE: 0.4166666666666667, the same as in Python I, with no index bookkeeping. The names yi and yhi mirror \(y_i\) and \(\hat y_i\).

The mean absolute error is \(\mathrm{MAE}=\frac1n\sum_i |y_i-\hat y_i|\): like MSE, but with the size of each error instead of its square, so large errors aren't punished as heavily. abs(x) gives the size of x (abs(-3) is 3).     best_i = 0
    for i, x in enumerate(xs):

We keep the position of the best value so far and replace it only when we find something strictly smaller, so the first of two equal minimums wins, exactly like NumPy's np.argmin, which the check compares against.

6 · Comprehensions: build a list in one line

In Python I you built lists with the pattern "start empty, loop, append". It's so common that Python has a short form, the list comprehension:

Read a comprehension right to left, then left

[ expression for name in list if condition ]

"For each name in the list, keep it if the condition holds, and collect the expression." The if part is optional. [x ** 2 for x in [1, 2, 3]] is [1, 4, 9].

marks = [62, 35, 81, 40, 90]

# the long way
curved = []
for m in marks:
    curved.append(m + 5)

# the same, as a comprehension
curved2 = [m + 5 for m in marks]
print(curved, curved2, curved == curved2)

print([m for m in marks if m >= 40])           # filter: keep passes only
print([round(m / 100, 2) for m in marks])       # transform
print({m: m >= 40 for m in marks})             # a dictionary comprehension
Read the output: both ways give [67, 40, 86, 45, 95], and == confirms the lists are equal. The filter keeps [62, 81, 40, 90]. The transform gives fractions. The last line uses curly braces with key: value to build a dictionary comprehension: each mark maps to whether it passes. A comprehension should fit on one readable line; if it doesn't, use a normal loop.

7 · Writing functions well

Functions are how you organise every project. Five habits make them clear and safe.

Docstrings and keyword arguments

Start every function with a docstring: a sentence in triple quotes saying what it takes and what it returns. Then anyone (including you, in a month) can read help(fn). When calling a function with many knobs, name them: keyword arguments (epochs=5) can be given in any order and make the call self-explaining.

def train(data, lr=0.01, epochs=10, verbose=False):
    """Pretend to train a model on data.

    lr is the learning rate, epochs the number of passes over the data.
    Returns a short description of what was done.
    """
    msg = f"trained on {len(data)} samples, lr={lr}, epochs={epochs}"
    if verbose:
        print("training...")
    return msg

print(train([1, 2, 3]))
print(train([1, 2, 3], epochs=5))              # skip lr, set epochs by name
print(train([1, 2, 3], verbose=True, lr=0.1))  # any order, by name
help(train)
Read the output: the first call uses every default. The second sets only epochs; without keywords you'd have to write train(data, 0.01, 5), and a reader couldn't tell what 0.01 and 5 mean. The third gives two keywords in a different order and turns on the extra print. help(train) prints the function's signature and docstring. This is exactly how you'll call library functions: LinearRegression(fit_intercept=False), train_test_split(X, y, test_size=0.2, random_state=0).

Returning several values

Return a tuple, and unpack it at the call. Here is a function returning the mean and the standard deviation (a measure of spread, explained in the probability lesson; here, \(\sigma = \sqrt{\frac1n\sum (x_i-\bar x)^2}\), read sigma):

Worked example · mean and standard deviation of 62, 75, 81, 70
  1. Mean: \(\bar x = 288/4 = 72\).
  2. Deviations \(x_i-\bar x\): \(-10,\ 3,\ 9,\ -2\). Squared: \(100,\ 9,\ 81,\ 4\).
  3. Mean of the squares: \((100+9+81+4)/4 = 194/4 = 48.5\).
  4. Square root: \(\sigma=\sqrt{48.5}\approx 6.964\).
\(\bar x = 72,\ \sigma \approx 6.964\)

Write mean_std(xs) that returns two values, the mean and the standard deviation \(\sqrt{\frac1n\sum_i (x_i-\bar x)^2}\). Example: m, s = mean_std([62, 75, 81, 70]) gives m = 72.0 and s ≈ 6.964. Give it a docstring.

def mean_std(xs):
    """Return the mean and the standard deviation of xs."""
    m = sum(xs) / len(xs)
    return m

import numpy as np

assert mean_std.__doc__, "keep the docstring"

After computing m, compute the mean of the squared deviations with a comprehension: sum([(x - m) ** 2 for x in xs]) / len(xs). Take its square root with ** 0.5.

End with return m, s.

def mean_std(xs):
    """Return the mean and the standard deviation of xs."""
    m = sum(xs) / len(xs)
    var = sum([(x - m) ** 2 for x in xs]) / len(xs)
    s = var ** 0.5
    return m, s

The function follows the worked example step by step. The check compares with NumPy's np.std, which divides by \(n\) by default, as we did. A name created inside a function exists only inside it, while the function runs. This is called scope. It's a good thing: functions can't accidentally overwrite your variables.

The mutable default trap (a classic interview question). A default value is created once, when the def runs, not on every call. With a list as default, every call shares the same list:

The fit / predict pattern

scikit-learn models follow one pattern: make the object with its settings, fit it to data (it learns its numbers and stores them with a trailing underscore, like coef_), then predict. Here is the simplest possible model in that style, one that ignores \(x\) and always predicts the mean of the training targets. It's a genuinely useful baseline: any real model must beat it.

class MeanModel:
    """Predicts the mean of the training targets, whatever the input."""

    def fit(self, y):
        self.mean_ = sum(y) / len(y)   # learned from data: trailing underscore
        return self                    # returning self allows model.fit(y).predict(...)

    def predict(self, n):
        return [self.mean_] * n        # n copies of the mean

sales = [22.1, 10.4, 9.3, 18.5, 12.9]
model = MeanModel().fit(sales)
print(model.mean_)
print(model.predict(3))
Read the output: the mean of the five sales figures, 14.64, then a list of three copies of it. [value] * n repeats a one-item list n times. This class has no __init__ because it has no settings; that's allowed. When you meet class Net(nn.Module): in PyTorch, it will be the same idea with more methods.

10 · Mini-project: k-nearest neighbours from scratch

You have already computed the mean squared error of predictions against targets stored in lists (section 5). Now you have every tool needed to build a real machine-learning method in about fifteen lines. The k-nearest neighbours (KNN) classifier, which ISLP introduces in section 2.2.3, predicts the class of a new point like this:

  1. measure the distance from the new point to every training point;
  2. take the k closest ones (its "neighbours");
  3. let them vote: predict the class that most of them have.

No equations to fit, no training step: the training data is the model. The only knob is \(k\).

Distance here is the ordinary straight-line (Euclidean) distance. For two points \(\mathbf a=(a_1,a_2)\) and \(\mathbf b=(b_1,b_2)\):

Euclidean distance
\[d(\mathbf a,\mathbf b)=\sqrt{(a_1-b_1)^2+(a_2-b_2)^2}\]

Read: "the distance between a and b is the square root of (a-one minus b-one) squared plus (a-two minus b-two) squared". It's Pythagoras. Example: from \((4, 4.5)\) to \((4.5, 6)\): \(\sqrt{0.5^2+1.5^2}=\sqrt{0.25+2.25}=\sqrt{2.5}\approx1.581\).

The data

Twelve training points, each with two measurements \((x_1, x_2)\) and a class, "blue" or "orange" (the colours ISLP uses in its KNN figures). The new point to classify is \((4, 4.5)\).

def vote(labels):
    counts = {}
    for lab in labels:
        counts[lab] = counts.get(lab, 0) + 1
    return max(counts, key=counts.get)

To predict a number instead of a class (KNN regression, ISLP section 3.5), replace the vote with the mean of the neighbours' values.

KNN with \(k=1\) is a nearest-neighbour quantiser: the input space is cut into Voronoi cells around the training points, like the decision regions of a minimum-distance detector for a signal constellation (QPSK, 16-QAM). A received symbol is decided as the nearest constellation point; KNN with \(k=1\) decides a new point's class the same way. Larger \(k\) smooths those regions, trading variance for bias.
