Real data work means combining arrays of different shapes (subtract every column's mean from a 1,000 × 10 matrix), generating random numbers you can reproduce exactly, and multiplying matrices. This lesson gives you those three tools: broadcasting, seeded random generators, and NumPy's linear algebra. 1. Broadcasting: arithmetic between different shapes

In NumPy I you added arrays of the same shape, and an array plus a single number. The second case is already a small miracle: x + 10 behaves as if the 10 were copied into an array the same shape as x. NumPy generalises this idea. Whenever two shapes are “compatible”, it stretches the smaller one, virtually, to match the larger one, and then works element by element. This is called broadcasting. Nothing is actually copied in memory: NumPy just reuses the same numbers as it walks along.

Case 1: a scalar

123456A, shape (2, 3)+1010, shape ()→10101010101010 stretched to (2, 3)=111213141516(2, 3)

Case 2: a row vector added to every row

A 1-D array of length 3 can be added to a (2, 3) matrix: it is added to each row. Picture the row being copied downwards (the blue copy is virtual).

123456A, (2, 3)+102030v, (3,)→102030102030v stretched down to (2, 3)=112233142536(2, 3)

Case 3: a column vector added to every column

To add a different number to each row, you need a column of shape (2, 1). It is copied across.

123456A, (2, 3)+100200c, (2, 1)→100100100200200200c stretched across to (2, 3)=101102103204205206(2, 3)

Case 4: both stretch, (3, 1) + (1, 4) gives (3, 4)

Both arrays can stretch at once. A column of 3 and a row of 4 make a full 3 × 4 table, like a times table: entry \([i, j]\) is \(c_i + r_j\).

01020c, (3, 1)+1234r, (1, 4)=12341112131421222324c + r, (3, 4)

The rules, precisely

NumPy broadcasting, three rules

1. Write the two shapes one above the other, aligned on the right. If one shape is shorter, pad it on the left with 1s.
2. Compare column by column. Two sizes are compatible if they are equal, or if one of them is 1. Otherwise: error.
3. The result's size in each column is the larger of the two; every size-1 axis is stretched to match.

Read: line the shapes up from the right; a 1 can stretch to anything; equal sizes stay; anything else is a mismatch.

Worked example · four shape pairs through the rules
Decide the result shape of (a) (3, 4) with (4,); (b) (3, 1) with (1, 4); (c) (3, 4) with (3,); (d) (5, 1, 3) with (4, 1).
  1. (a) Pad (4,) on the left to (1, 4). Compare (3, 4) with (1, 4): first column 3 vs 1, OK (stretch the 1); second column 4 vs 4, OK. Result (3, 4).This is “subtract a row of column means from a data matrix”.
  2. (b) (3, 1) with (1, 4): 3 vs 1 OK, 1 vs 4 OK. Both stretch. Result (3, 4).
  3. (c) Pad (3,) to (1, 3). Compare (3, 4) with (1, 3): first column OK, but second column 4 vs 3: not equal and neither is 1. Error.The 3 lines up with the columns (there are 4 of them), not the rows. To add one number per row you need shape (3, 1).
  4. (d) Pad (4, 1) to (1, 4, 1). Compare (5, 1, 3) with (1, 4, 1): 5 vs 1 OK, 1 vs 4 OK, 3 vs 1 OK. Result (5, 4, 3).
(a) (3, 4) · (b) (3, 4) · (c) ValueError · (d) (5, 4, 3)

A has shape (3, 4). What happens with A - np.array([1, 2, 3])?

  1. It subtracts 1 from row 0, 2 from row 1, 3 from row 2
  2. It subtracts from the first three columns only
  3. ValueError: the shapes cannot be broadcast
Aligned on the right, the length-3 vector faces the 4 columns: 4 vs 3, incompatible. NumPy never guesses which axis you meant. Option 1 is what you probably wanted; you get it by making the vector a column, shape (3, 1), as the cell after this one shows.
A = np.arange(12).reshape(3, 4)
A - np.array([1, 2, 3])
Read the error: “operands could not be broadcast together with shapes (3,4) (3,)”. NumPy tells you both shapes. Line them up from the right in your head and you see the 4 versus 3.

Making a column: [:, None], reshape, keepdims

Three ways to turn a 1-D array of length 3 into a (3, 1) column. They all do the same thing:

CodeMeaning
v[:, None] (or v[:, np.newaxis])keep all of axis 0, insert a new axis of length 1 after it
v.reshape(-1, 1)reshape to “as many rows as needed, 1 column”
A.sum(axis=1, keepdims=True)a reduction that keeps the collapsed axis with length 1, giving (3, 1) instead of (3,)
A = np.arange(12).reshape(3, 4)
v = np.array([1, 2, 3])
print(v[:, None].shape, v.reshape(-1, 1).shape)
print(A - v[:, None])                 # 1 from row 0, 2 from row 1, 3 from row 2
row_sums = A.sum(axis=1, keepdims=True)
print(row_sums.shape)                 # (3, 1), ready to broadcast
print(A / row_sums)                   # each row divided by its own sum
Read the output: after subtracting, row 0 starts at −1, row 1 at 2, row 2 at 5. The last array has rows that each add up to 1 (check row 1: \(4+5+6+7=22\), and \(4/22=0.182\)). “Divide each row by its total” is exactly how the softmax function of deep learning turns scores into probabilities (Prince Chapter 5).
Pick two shapes. They are lined up from the right, each axis is checked, and the stretched grids are drawn (virtual copies are faded). Try (3,4) + (3,) and read why it fails; then change the second shape to (3,1).

Broadcasting is how you build a DFT matrix. The \(N\times N\) DFT matrix has entries \(W[k,n]=e^{-j2\pi kn/N}\). With k = np.arange(N)[:, None] (a column) and n = np.arange(N) (a row), np.exp(-2j*np.pi*k*n/N) gives the whole matrix in one line: k*n broadcasts (N, 1) with (N,) to (N, N). Every “table of f(i, j)” is built this way. (Python writes the imaginary unit as j, as electrical engineers do: 2j is \(2j\).)

N = 4
k = np.arange(N)[:, None]        # shape (4, 1)
n = np.arange(N)                 # shape (4,)
W = np.exp(-2j * np.pi * k * n / N)   # (4, 1) with (4,) gives (4, 4)
print(np.round(W.real).astype(int))   # the real parts: cosines, 1, 0 or -1
x = np.array([1., 2., 3., 4.])
print(W @ x)                      # the DFT of x (the @ product is in section 4)
print(np.fft.fft(x))              # NumPy's FFT agrees
Read the output: both lines give \(X[0]=10\), \(X[1]=-2+2j\), \(X[2]=-2\), \(X[3]=-2-2j\) (up to tiny rounding such as -0.j). The matrix product with the broadcast-built DFT matrix and the FFT agree.

ISLP's lab uses the same idea under another name: np.multiply.outer(np.cos(y), 1 / (1 + x**2)) (In[49]) builds the table \(f[i,j]=\cos(y_i)/(1+x_j^2)\) for a contour plot. With broadcasting that is np.cos(y)[:, None] * (1 / (1 + x**2)).

x = np.linspace(-np.pi, np.pi, 50)
y = x
f1 = np.multiply.outer(np.cos(y), 1 / (1 + x**2))   # ISLP's way
f2 = np.cos(y)[:, None] * (1 / (1 + x**2))           # broadcasting
print(f1.shape, np.allclose(f1, f2))
Read the output: (50, 50) True: a 50 × 50 table, identical both ways. You will plot it in the plotting lesson.

Silent broadcasting bugs. A (n,) vector minus an (n, 1) column gives an (n, n) matrix, with no error. This often happens when one array came out of a model or a reduction as a column and the other did not. If a result is unexpectedly large or square, print the shapes. A habit that saves hours: print(a.shape, b.shape) before combining arrays you did not create yourself.

y_true = np.array([1., 2., 3.])
y_pred = np.array([[1.1], [1.9], [3.2]])   # came out of some model as a column
err = y_true - y_pred
print(err.shape)               # (3, 3)! not (3,)
print(np.mean(err**2))         # a wrong "MSE", and no error message
print(np.mean((y_true - y_pred.ravel())**2))   # the right MSE: flatten first
Read the output: the wrong version averages the squares of all nine differences between every target and every prediction, and reports 1.42; the right one compares each prediction with its own target and gives 0.02. ravel() flattens the column to shape (3,).

2. Centring and standardising a data matrix

Many ML methods work better when every variable is on a comparable scale. Horsepower is in the hundreds, acceleration around 15, and a method that measures distances (like k-nearest neighbours) would otherwise care almost only about horsepower. The fix is to standardise each column: subtract its mean and divide by its standard deviation.

Centring and standardising column \(j\)
\[\tilde x_{ij}=x_{ij}-\bar x_j,\qquad z_{ij}=\frac{x_{ij}-\bar x_j}{s_j}\]

Read: “x-tilde i j” is the centred value: the original minus its column's mean \(\bar x_j\) (“x-bar sub j”). “z i j” is the standardised value (a z-score): how many standard deviations \(s_j\) the value lies above its column's mean. After standardising, every column has mean 0 and standard deviation 1.

Worked example · standardising a 3 × 2 matrix by hand
\(\bX=\begin{pmatrix}1&10\\2&20\\3&60\end{pmatrix}\): 3 observations, 2 variables.
  1. Column means (axis 0 disappears): \(\bar x_1=(1+2+3)/3=\mathbf{2}\), \(\bar x_2=(10+20+60)/3=\mathbf{30}\). As an array, [2, 30], shape (2,).
  2. Centre: broadcasting subtracts the row [2, 30] from every row: \(\begin{pmatrix}1-2&10-30\\2-2&20-30\\3-2&60-30\end{pmatrix}=\begin{pmatrix}-1&-20\\0&-10\\1&30\end{pmatrix}\).(3, 2) minus (2,): aligned on the right, 2 matches 2, and the 3 rows are covered by stretching.
  3. Standard deviations (dividing by \(n=3\)): column 1: \(\sqrt{(1+0+1)/3}=\sqrt{0.667}=\mathbf{0.816}\). Column 2: \(\sqrt{(400+100+900)/3}=\sqrt{466.7}=\mathbf{21.60}\).
  4. Divide each centred column by its own standard deviation (broadcasting again): column 1 becomes \(-1/0.816=-1.225,\ 0,\ 1.225\); column 2 becomes \(-20/21.6=-0.926,\ -10/21.6=-0.463,\ 30/21.6=1.389\).
\(\mathbf Z=\begin{pmatrix}-1.225&-0.926\\0&-0.463\\1.225&1.389\end{pmatrix}\), each column with mean 0 and standard deviation 1
X = np.array([[1., 10.], [2., 20.], [3., 60.]])
mu = X.mean(axis=0)            # shape (2,)
sd = X.std(axis=0)             # shape (2,)
Z = (X - mu) / sd              # (3, 2) with (2,): broadcast down the rows
print(mu, sd)
print(Z)
print(Z.mean(axis=0), Z.std(axis=0))   # 0 and 1 (up to rounding)
Read the output: every number of the worked example appears: means [2. 30.], standard deviations [0.816 21.602], and the matrix \(\mathbf Z\). The last line confirms mean 0 and standard deviation 1 for both columns. (A -0. is a tiny negative rounding error, something like \(-10^{-17}\), printed with 3 decimals.)

Standardise with the training set's numbers. When you split data into a training and a test set (ISLP Chapter 5), compute mu and sd on the training rows only, and apply those same numbers to the test rows. Using the test set's own mean leaks information about it into your model. scikit-learn's StandardScaler does exactly this with fit then transform.

To standardise rows instead (one mean per observation), reduce along axis 1 and keep the dimension, so the shapes broadcast across the columns:

R = (X - X.mean(axis=1, keepdims=True)) / X.std(axis=1, keepdims=True)
print(R)            # each row now has mean 0, std 1
Read the output: each row has only two numbers, so after standardising every row is [-1. 1.]: one value one standard deviation below the row mean, the other one above.

3. Random numbers you can reproduce

Machine learning uses randomness everywhere: simulated data, random train/test splits, shuffled mini-batches, initial weights of a neural network, bootstrap resamples. A computer does not produce truly random numbers; it runs a deterministic formula, a pseudo-random number generator, whose output only looks random. The starting point of that formula is the seed. Same seed, same sequence, every time, on every computer.

You have met this before: a linear-feedback shift register (LFSR) generates a pseudo-noise (PN) sequence for spread spectrum. Load the same initial state and you get the same chip sequence, which is exactly why the receiver can de-spread. A NumPy seed is the initial state of a (much better) generator.

The modern way: a Generator object

ISLP (and this guide) uses rng = np.random.default_rng(seed). It returns a Generator object; you ask it for numbers with its methods. Here is ISLP's own demonstration (In[32]): two generators with the same seed give identical numbers.

Two generators are created with the same seed, 1303, and each draws two normal numbers with scale=5. What do you expect?

  1. Exactly the same two numbers from both
  2. Different numbers, because they are random
  3. Similar but not identical numbers
The seed fixes the whole sequence. Both generators start in the same state and run the same formula, so the output is identical to the last digit. ISLP prints [4.09 -1.07] twice.
rng = np.random.default_rng(1303)
print(rng.normal(scale=5, size=2))
rng2 = np.random.default_rng(1303)
print(rng2.normal(scale=5, size=2))
print(rng.normal(scale=5, size=2))     # rng has moved on: new numbers
Read the output: the first two lines are identical, [ 4.095 -1.075], exactly ISLP's numbers. The third line is different, because rng continued along its sequence. Re-run the cell: you get exactly the same three lines again, because the cell re-creates the generators from the seed.
New in this lesson · keyword arguments

In rng.normal(loc=0, scale=5, size=2) the arguments are given by name. These are keyword arguments: you can give them in any order and leave out any that have defaults. normal's signature is normal(loc=0.0, scale=1.0, size=None): by default mean 0, standard deviation 1, one number. Arguments given without names are positional: matched by order. ISLP explains this on p. 46. So rng.normal(50, 1, 10) and rng.normal(size=10, loc=50, scale=1) mean the same.

The methods you will use

\(\mathcal N(\mu,\sigma^2)\) is read “normal with mean mu and variance sigma squared”: the bell curve centred at \(\mu\) whose width is \(\sigma\). The probability lesson teaches it properly; here you only need “numbers that cluster around loc with spread scale”. Note that scale is the standard deviation \(\sigma\), not the variance.

rng = np.random.default_rng(3)
y = rng.standard_normal(10)                  # ISLP In[33]
print(np.mean(y), y.mean())
print(np.var(y), y.var(), np.mean((y - y.mean())**2))   # ISLP In[34]: three equal ways
X = rng.standard_normal((10, 3))             # a 10 x 3 matrix of N(0,1)
print(X.mean(axis=0))                        # ISLP In[37]: column means, near 0
print(rng.uniform(0, 1, size=4))
print(rng.integers(1, 7, size=10))           # ten dice rolls (7 is excluded)
Read the output: with seed 3, the mean of y is about −0.113 and the variance about 2.724, the same as ISLP prints (−0.11 and 2.72). The column means of X are near 0 but not exactly 0: ten samples are not many. The dice rolls are whole numbers from 1 to 6.

choice and permutation: shuffles, splits and bootstrap samples

rng = np.random.default_rng(0)
perm = rng.permutation(10)            # a random order of 0..9
print(perm)
train_idx, test_idx = perm[:7], perm[7:]   # a 70/30 split of 10 rows
print(train_idx, test_idx)
data = np.array([3, 8, 1, 9, 4])
print(rng.choice(data, size=5, replace=True))    # a bootstrap sample: repeats allowed
print(rng.choice(data, size=3, replace=False))   # 3 distinct elements
print(rng.choice([0, 1], size=12, p=[0.8, 0.2])) # 1 with probability 0.2
Read the output: the permutation contains every index exactly once, so the first 7 and last 3 never overlap: a clean split. A bootstrap sample (ISLP Chapter 5) has the same size as the data but is drawn with replacement, so some values repeat and others are missing. In the last line about one draw in five is a 1.

ISLP builds a correlated dataset this way (In[28]–[30]). np.corrcoef(x, y) returns the 2 × 2 correlation matrix; the off-diagonal entry is the correlation between x and y.

rng = np.random.default_rng(1303)
x = rng.normal(size=50)
y = x + rng.normal(loc=50, scale=1, size=50)    # y = x + independent N(50, 1) noise
print(np.corrcoef(x, y))
Read the output: 1s on the diagonal (every variable is perfectly correlated with itself) and about 0.67 off the diagonal. ISLP shows 0.69 because it drew x without a seed; with a different draw you get a slightly different number. In theory the correlation is \(1/\sqrt2\approx0.71\), since y is x plus noise of equal variance.

The old way, and why to avoid it. Older code (and part of ISLP's lab, In[28]) calls np.random.normal(...) directly, using a hidden global generator seeded by np.random.seed(0). Any other code that draws random numbers silently changes your sequence. Use one rng = np.random.default_rng(seed) per experiment. Note also that the same seed gives different numbers in the old and new systems, and occasionally across NumPy versions (ISLP warns about this on p. 47).

Why seeds matter for experiments. When you compare two models, you want the difference in their scores to come from the models, not from a lucky random split. Fix the seed, and anyone (including you next week) can reproduce your numbers exactly. Then, to check that a conclusion is not a fluke of one seed, repeat with several seeds and look at the spread.

# The average of n uniform samples gets closer to the true mean (0.5) as n grows,
# and with fixed seeds this whole table is reproducible.
for n in [10, 100, 1000, 100000]:
    means = [np.random.default_rng(s).uniform(size=n).mean() for s in range(5)]
    print(f"n={n:6d}: means over 5 seeds = {np.round(means, 3)}")
Read the output: with 10 samples the five seeds give quite different means; with 100,000 they all agree to two or three decimals. The spread shrinks like \(1/\sqrt n\): a preview of the standard error you will meet in ISLP Chapter 3.

4. Linear algebra: dot products and the @ operator

The full theory of vectors and matrices is the subject of the next maths lesson. Here you learn the NumPy code, with just enough of the maths to check every number.

The dot product

Dot product of two vectors of length \(n\)
\[\mathbf a\cdot\mathbf b=\sum_{i=1}^{n}a_i b_i=a_1b_1+a_2b_2+\dots+a_nb_n\]

Read: “a dot b” means “multiply matching entries, then add them all up”. For \(\mathbf a=(1,2,3)\), \(\mathbf b=(4,5,6)\): \(4+10+18=32\). It is (a * b).sum(), and NumPy writes it a @ b or np.dot(a, b).

A dot product is an FIR filter output, and a correlator. One output sample of an FIR filter is \(y[n]=\sum_k h[k]x[n-k]\): a dot product of the taps with a window of the input. A matched-filter receiver computes the dot product of the received block with the known pulse. A linear regression prediction \(\hat y=\beta_0+\beta_1x_1+\dots+\beta_px_p\) is the same operation: a dot product of a coefficient vector with a feature vector.

Matrix times vector

A matrix times a vector is a stack of dot products: each row of the matrix dotted with the vector gives one entry of the result.

Matrix–vector product
\[(\mathbf A\mathbf x)_i=\sum_{j=1}^{n}a_{ij}x_j\qquad\text{shapes: }(m\times n)\,(n)\to(m)\]

Read: entry \(i\) of \(\mathbf A\mathbf x\) is row \(i\) of \(\mathbf A\) dotted with \(\mathbf x\). The number of columns of \(\mathbf A\) must equal the length of \(\mathbf x\).

Worked example · a 3 × 2 matrix times a vector, every number
\(\mathbf A=\begin{pmatrix}2&1\\1&3\\0&4\end{pmatrix}\) (shape 3 × 2), \(\mathbf x=\begin{pmatrix}1\\2\end{pmatrix}\) (length 2). Compute \(\mathbf A\mathbf x\).
  1. Shapes: (3 × 2) times (2) gives length 3. The inner sizes, 2 and 2, match.
  2. Row 0 (yellow) dotted with \(\mathbf x\) (blue):
    211304A·12x
    \(2\cdot1+1\cdot2=\mathbf 4\).
  3. Row 1: \(1\cdot1+3\cdot2=1+6=\mathbf 7\).
  4. Row 2: \(0\cdot1+4\cdot2=\mathbf 8\).
\(\mathbf A\mathbf x=\begin{pmatrix}2\cdot1+1\cdot2\\1\cdot1+3\cdot2\\0\cdot1+4\cdot2\end{pmatrix}=\begin{pmatrix}4\\7\\8\end{pmatrix}\)

For the same A (3 × 2) and x = np.array([1, 2]), what does A * x (star, not @) give?

  1. [4, 7, 8], the same as A @ x
  2. a 3 × 2 array [[2, 2], [1, 6], [0, 8]]
  3. a ValueError
* is elementwise with broadcasting: the length-2 x is stretched down the 3 rows and multiplied entry by entry. No sum happens. Summing each row of that result, (A * x).sum(axis=1), would give [4, 7, 8]: that is literally what a matrix–vector product is.
A = np.array([[2, 1], [1, 3], [0, 4]])
x = np.array([1, 2])
print(A * x)                    # elementwise (broadcast), shape (3, 2)
print((A * x).sum(axis=1))      # sum each row: the matrix-vector product
print(A @ x)                    # the same, the proper way
print(np.dot(A, x))             # older spelling of the same thing
a, b = np.array([1, 2, 3]), np.array([4, 5, 6])
print(a @ b, np.dot(a, b), (a * b).sum())   # dot product: 32 three ways
Read the output: first the 3 × 2 elementwise array from the prediction, then [4 7 8] three times, then 32 32 32.
Press Next row to step through the product: the highlighted row of A is multiplied entry by entry with x, and the products are added into one entry of the result. Move the sliders to change x and watch every entry respond.

Matrix times matrix

\(\mathbf A\mathbf B\) is “\(\mathbf A\) times each column of \(\mathbf B\)”. Entry \([i,j]\) is row \(i\) of \(\mathbf A\) dotted with column \(j\) of \(\mathbf B\). The shapes must chain: \((m\times k)(k\times n)\to(m\times n)\). The inner \(k\)s must be equal, and they disappear.

1234A@5678B=19224350[1, 0]: 3·5 + 4·7 = 43
A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])
print(A @ B)           # [[1*5+2*7, 1*6+2*8], [3*5+4*7, 3*6+4*8]]
print(B @ A)           # different! matrix products do not commute
print(A * B)           # elementwise: a different thing again
X = np.ones((100, 3)); W = np.ones((3, 5))
print((X @ W).shape)   # (100, 3) @ (3, 5) -> (100, 5)
print((X.T @ X).shape) # (3, 100) @ (100, 3) -> (3, 3): the "X transpose X" of least squares
Read the output: \(\mathbf A\mathbf B=\begin{pmatrix}19&22\\43&50\end{pmatrix}\) but \(\mathbf B\mathbf A=\begin{pmatrix}23&34\\31&46\end{pmatrix}\): order matters. A * B is [[5 12] [21 32]]. The two shapes follow the chaining rule.

Interview classic: “What is the shape of \(\bX\T\bX\) if \(\bX\) is \(n\times p\)?” Answer: \(p\times p\), because \((p\times n)(n\times p)\). And “what is the difference between * and @ in NumPy?”: elementwise (with broadcasting) versus matrix product.

5. np.linalg: inverse, determinant, solve, norm, least squares

The submodule np.linalg holds the standard linear-algebra routines. We check each on an example small enough to do by hand.

Determinant and inverse of a 2 × 2 matrix

The 2 × 2 determinant and inverse
\[\mathbf A=\begin{pmatrix}a&b\\c&d\end{pmatrix},\qquad \det\mathbf A=ad-bc,\qquad \mathbf A^{-1}=\frac{1}{ad-bc}\begin{pmatrix}d&-b\\-c&a\end{pmatrix}\]

Read: “A inverse” is the matrix that undoes \(\mathbf A\): \(\mathbf A^{-1}\mathbf A=\mathbf I\), the identity. Recipe: swap the diagonal entries, flip the signs of the off-diagonal ones, divide by the determinant. If \(\det\mathbf A=0\) there is no inverse (the matrix is singular).

Worked example · inverting \(\begin{pmatrix}4&7\\2&6\end{pmatrix}\) by hand
\(a=4,\ b=7,\ c=2,\ d=6\).
  1. Determinant: \(ad-bc=4\cdot6-7\cdot2=24-14=\mathbf{10}\). Not zero, so the inverse exists.
  2. Swap \(a\) and \(d\), negate \(b\) and \(c\): \(\begin{pmatrix}6&-7\\-2&4\end{pmatrix}\).
  3. Divide by 10: \(\mathbf A^{-1}=\begin{pmatrix}0.6&-0.7\\-0.2&0.4\end{pmatrix}\).
  4. Check two entries of \(\mathbf A^{-1}\mathbf A\): row 0 times column 0 is \(0.6\cdot4+(-0.7)\cdot2=2.4-1.4=1\); row 0 times column 1 is \(0.6\cdot7+(-0.7)\cdot6=4.2-4.2=0\). The identity is appearing.
\(\det\mathbf A=10,\quad \mathbf A^{-1}=\begin{pmatrix}0.6&-0.7\\-0.2&0.4\end{pmatrix}\)
A = np.array([[4., 7.], [2., 6.]])
print(np.linalg.det(A))         # 10, give or take a rounding error
Ainv = np.linalg.inv(A)
print(Ainv)
print(Ainv @ A)                 # the identity (up to rounding)
print(np.allclose(Ainv @ A, np.eye(2)))
Read the output: the determinant may print as 10.000000000000002 rather than 10. Floating-point numbers carry about 16 significant digits, and the last one can wobble. That is why you compare floats with np.allclose, never with ==.

Solving a linear system

Two equations, two unknowns: \(2x+y=5\) and \(x+3y=10\). In matrix form \(\mathbf A\mathbf v=\mathbf b\) with \(\mathbf A=\begin{pmatrix}2&1\\1&3\end{pmatrix}\), \(\mathbf v=\begin{pmatrix}x\\y\end{pmatrix}\), \(\mathbf b=\begin{pmatrix}5\\10\end{pmatrix}\).

Worked example · solve by hand, then check in NumPy
\(\mathbf A=\begin{pmatrix}2&1\\1&3\end{pmatrix}\), \(\mathbf b=\begin{pmatrix}5\\10\end{pmatrix}\).
  1. \(\det\mathbf A=2\cdot3-1\cdot1=\mathbf 5\).
  2. \(\mathbf A^{-1}=\tfrac15\begin{pmatrix}3&-1\\-1&2\end{pmatrix}\).
  3. \(\mathbf v=\mathbf A^{-1}\mathbf b=\tfrac15\begin{pmatrix}3\cdot5-1\cdot10\\-1\cdot5+2\cdot10\end{pmatrix}=\tfrac15\begin{pmatrix}5\\15\end{pmatrix}=\begin{pmatrix}1\\3\end{pmatrix}\).
  4. Check in the original equations: \(2(1)+3=5\) ✓ and \(1+3(3)=10\) ✓.
\(x=1,\ y=3\)
A = np.array([[2., 1.], [1., 3.]])
b = np.array([5., 10.])
v = np.linalg.solve(A, b)       # solves A v = b directly
print(v)
print(np.linalg.inv(A) @ b)     # same answer, but slower and less accurate for big systems
print(A @ v)                    # gives b back: the check
Read the output: [1. 3.] twice, then [ 5. 10.], which is \(\mathbf b\): the solution satisfies both equations.

Prefer solve to inv. To find \(\mathbf v\) in \(\mathbf A\mathbf v=\mathbf b\), np.linalg.solve(A, b) is faster and more accurate than np.linalg.inv(A) @ b. Compute an explicit inverse only when you really need the matrix itself (for example its diagonal, for standard errors in Chapter 3).

Norms: the length of a vector

L2 (Euclidean) and L1 norms
\[\|\mathbf x\|_2=\sqrt{\sum_i x_i^2},\qquad \|\mathbf x\|_1=\sum_i |x_i|\]

Read: “the two-norm of x” is its ordinary length (Pythagoras); “the one-norm” adds up absolute values (the taxi-cab distance). For \((3,4)\): \(\sqrt{9+16}=5\) and \(3+4=7\). The distance between two points is the norm of their difference. Ridge and lasso regression (ISLP Chapter 6) penalise these two norms.

x = np.array([3., 4.])
print(np.linalg.norm(x), np.sqrt((x**2).sum()))     # 5.0 both
print(np.linalg.norm(x, 1), np.abs(x).sum())        # 7.0 both
p, q = np.array([1., 1.]), np.array([4., 5.])
print(np.linalg.norm(p - q))                        # distance between two points: 5.0
M = np.array([[3., 4.], [6., 8.]])
print(np.linalg.norm(M, axis=1))                    # the length of each row: 5 and 10

Least squares: the best line through points

Fitting a straight line \(y\approx\beta_0+\beta_1x\) to data is the topic of ISLP Chapter 3. In matrix form you stack the equations \(\beta_0+\beta_1x_i\approx y_i\) for all points into \(\bX\bbeta\approx\by\), with the design matrix \(\bX\) (a column of ones and a column of \(x\)) from NumPy I. There are more equations than unknowns, so usually no exact solution exists; least squares picks the \(\bbeta\) (“bold beta”) that makes the sum of squared errors smallest. Its solution satisfies the normal equations:

Least squares solution
\[\hat\bbeta=(\bX\T\bX)^{-1}\bX\T\by\]

Read: “beta-hat equals the inverse of X-transpose-X, times X-transpose-y”. The hat means “estimated from data”. In NumPy: np.linalg.lstsq(X, y) or, by the formula, np.linalg.solve(X.T @ X, X.T @ y).

Worked example · a line through three points
Points \((0,1),\ (1,3),\ (2,4)\). So \(\bX=\begin{pmatrix}1&0\\1&1\\1&2\end{pmatrix}\), \(\by=\begin{pmatrix}1\\3\\4\end{pmatrix}\).
  1. \(\bX\T\bX=\begin{pmatrix}1&1&1\\0&1&2\end{pmatrix}\begin{pmatrix}1&0\\1&1\\1&2\end{pmatrix}=\begin{pmatrix}1+1+1&0+1+2\\0+1+2&0+1+4\end{pmatrix}=\begin{pmatrix}3&3\\3&5\end{pmatrix}\).
  2. \(\bX\T\by=\begin{pmatrix}1+3+4\\0\cdot1+1\cdot3+2\cdot4\end{pmatrix}=\begin{pmatrix}8\\11\end{pmatrix}\).
  3. Invert \(\begin{pmatrix}3&3\\3&5\end{pmatrix}\): determinant \(15-9=6\), inverse \(\tfrac16\begin{pmatrix}5&-3\\-3&3\end{pmatrix}\).
  4. \(\hat\bbeta=\tfrac16\begin{pmatrix}5\cdot8-3\cdot11\\-3\cdot8+3\cdot11\end{pmatrix}=\tfrac16\begin{pmatrix}7\\9\end{pmatrix}=\begin{pmatrix}1.167\\1.5\end{pmatrix}\).
best line \(\hat y=1.167+1.5x\)
x = np.array([0., 1., 2.])
y = np.array([1., 3., 4.])
X = np.column_stack([np.ones(3), x])
beta, rss, rank, sv = np.linalg.lstsq(X, y, rcond=None)   # four outputs; we want the first
print(beta, rss)
print(np.linalg.solve(X.T @ X, X.T @ y))   # the normal equations: same answer
print(np.polyfit(x, y, 1))                 # polyfit returns [slope, intercept]: note the order!
print(X @ beta)                            # fitted values: 1.167, 2.667, 4.167
Read the output: all three methods give intercept 1.167 and slope 1.5. lstsq returns four things; beta, rss, rank, sv = ... unpacks them into four names. The second is the residual sum of squares, [0.167]: the fitted values miss the data by \(-1/6, +1/3, -1/6\), and \(1/36+1/9+1/36=1/6\). rcond=None just silences a warning about a default. Beware that np.polyfit lists the highest power first, so slope before intercept.

6. Vectorising a double loop: pairwise distances

The k-nearest-neighbours method (ISLP 2.2) predicts for a new point by looking at the training points closest to it. So it needs the distance from every test point to every training point. With \(m\) test points and \(n\) training points, each with \(d\) features, the obvious code is a double loop. Broadcasting does it in one line.

Distance matrix
\[D_{ij}=\|\mathbf a_i-\mathbf b_j\|_2=\sqrt{\sum_{k=1}^{d}(a_{ik}-b_{jk})^2}\]

Read: entry \(i,j\) is the straight-line distance between test point \(i\) (row \(i\) of \(\mathbf A\), shape \(m\times d\)) and training point \(j\) (row \(j\) of \(\mathbf B\), \(n\times d\)). \(D\) has shape \(m\times n\).

The trick is to give the two arrays different “slots” so that every pair meets:

  1. A[:, None, :] has shape \((m, 1, d)\): each test point sits in its own slice along axis 0.
  2. B[None, :, :] has shape \((1, n, d)\): the training points lie along axis 1.
  3. Subtracting broadcasts \((m,1,d)\) with \((1,n,d)\) to \((m,n,d)\): every test point minus every training point, every feature.
  4. Square, then .sum(axis=2) over the \(d\) features gives \((m, n)\); np.sqrt gives the distances.

A has shape (2, 3) (two test points with 3 features), B has shape (4, 3). What is the shape of A[:, None, :] - B[None, :, :]?

  1. (2, 3)
  2. (2, 4, 3)
  3. ValueError
(2, 1, 3) with (1, 4, 3): 2 vs 1 OK, 1 vs 4 OK, 3 vs 3 OK, giving (2, 4, 3). Summing the squares over the last axis then gives the 2 × 4 distance matrix.
A = np.array([[0., 0., 0.], [1., 1., 1.]])                  # 2 test points
B = np.array([[0., 0., 1.], [3., 4., 0.], [1., 1., 1.], [2., 0., 0.]])   # 4 training points
diff = A[:, None, :] - B[None, :, :]
print(diff.shape)
D = np.sqrt((diff**2).sum(axis=2))
print(D)
# the slow, obvious way, for comparison:
D_loop = np.zeros((2, 4))
for i in range(2):
    for j in range(4):
        D_loop[i, j] = np.sqrt(((A[i] - B[j])**2).sum())
print(np.allclose(D, D_loop))
Read the output: row 0 holds the distances from the origin to the four training points: 1, 5, 1.732, 2. Row 1 holds the distances from (1, 1, 1): its distance to the third training point is 0, because they are the same point. The loop version agrees.

Now nearest neighbours take two more lines. D.argmin(axis=1) gives, for each test point (row), the column of the closest training point. np.argsort(D, axis=1)[:, :k] gives the \(k\) closest.

print(D.argmin(axis=1))                # nearest training point for each test point
print(np.argsort(D, axis=1))           # all training points, nearest first
y_train = np.array([10., 20., 30., 40.])
k = 2
nn = np.argsort(D, axis=1)[:, :k]      # indices of the 2 nearest, shape (2, 2)
print(nn)
print(y_train[nn].mean(axis=1))        # k-NN regression prediction for each test point
Read the output: test point 0 is closest to training point 0, test point 1 to training point 2. y_train[nn] is fancy indexing with a 2-D index array: it returns a (2, 2) array of the neighbours' y-values, and the row means are the 2-NN predictions. You have just written k-nearest-neighbours regression.
Drag the three red test points. The table is the distance matrix D (rows: test points; columns: training points). Each row's smallest entry is highlighted, and a line joins each test point to its nearest neighbour. That highlight is exactly D.argmin(axis=1).

How much faster is the vectorised version? Time it on 300 test points and 1,000 training points:

import time
rng = np.random.default_rng(0)
A = rng.standard_normal((300, 5)); B = rng.standard_normal((1000, 5))

t0 = time.perf_counter()
D_vec = np.sqrt(((A[:, None, :] - B[None, :, :])**2).sum(axis=2))
t_vec = time.perf_counter() - t0

t0 = time.perf_counter()
D_slow = np.array([[np.sqrt(((a - b)**2).sum()) for b in B] for a in A[:30]])  # only 30 rows!
t_slow = (time.perf_counter() - t0) * 10       # scale up to 300 rows
print(f"vectorised: {t_vec*1000:.0f} ms   loops (estimated): {t_slow*1000:.0f} ms")
print(np.allclose(D_vec[:30], D_slow))
Read the output: the loop version would take many times longer, and we only ran a tenth of it. (time.perf_counter() reads a stopwatch: we read it before and after and subtract.) The price of broadcasting is memory: the intermediate array has \(m\times n\times d\) = 1.5 million numbers. For very large problems you process the test points in blocks (“batches”), just like block processing of a long signal.

    A = np.asarray(A, float); b = np.asarray(b, float)
    a, bb, c, d = A[0, 0], A[0, 1], A[1, 0], A[1, 1]
    det = a * d - bb * c
    if det == 0:
        raise ValueError("singular matrix: no unique solution")
    inv = np.array([[d, -bb], [-c, a]]) / det
    return inv @ b

The matrix \(\begin{pmatrix}1&2\\2&4\end{pmatrix}\) has determinant \(4-4=0\): its second row is twice the first, so the two equations are not independent. (In real code with floats you would test abs(det) < 1e-12 rather than == 0.)

Distances (m, n), then np.argsort(D, axis=1)[:, :k], then y_train[nn], then the mean along axis 1.

def knn_predict(X_train, y_train, X_test, k):
    D = np.sqrt(((X_test[:, None, :] - X_train[None, :, :])**2).sum(axis=-1))
    nn = np.argsort(D, axis=1)[:, :k]
    return y_train[nn].mean(axis=1)

Three lines, no loops, and it matches scikit-learn exactly. Notice the test points come first in the subtraction, so the rows of D are test points. This is the KNN regression of ISLP §3.5.

9. Quiz

What is the shape of np.ones((4, 1)) + np.ones(5)?

  1. ValueError
  2. (4, 5)
  3. (4, 1)
  4. (5, 4)
Pad (5,) to (1, 5). Compare (4, 1) with (1, 5): each axis has a 1 on one side, so both stretch: (4, 5).

X is (100, 3). Which line divides each row by its own maximum?

  1. X / X.max(axis=1)
  2. X / X.max(axis=0)
  3. X / X.max(axis=1, keepdims=True)
X.max(axis=1) has shape (100,), which faces the 3 columns: a broadcasting error. Option 2 divides each column by its maximum. With keepdims=True the maxima are (100, 1) and broadcast across each row.

Why does ISLP create rng = np.random.default_rng(1303) before generating data?

  1. So that re-running the code gives exactly the same numbers
  2. To make the numbers more random
  3. To make the code run faster
The seed fixes the generator's starting state, so results are reproducible. It does not change the statistical quality of the numbers or the speed.

What is a @ b for a = np.array([1, 2, 3]) and b = np.array([4, 5, 6])?

\(1\cdot4+2\cdot5+3\cdot6=4+10+18=32\).

What is the determinant of \(\begin{pmatrix}1&2\\3&4\end{pmatrix}\)?

\(ad-bc=1\cdot4-2\cdot3=4-6=-2\).

X is \(n\times p\) with \(n=200\), \(p=5\). What is the shape of X.T @ X?

  1. (200, 200)
  2. (5, 5)
  3. (200, 5)
(5, 200) @ (200, 5): the inner 200s cancel, leaving (5, 5). X @ X.T would be (200, 200).

To solve \(\mathbf A\mathbf v=\mathbf b\) in NumPy, which is preferred?

  1. np.linalg.solve(A, b)
  2. np.linalg.inv(A) @ b
  3. b / A
solve is faster and more accurate. inv works but does more work and amplifies rounding errors. b / A is elementwise division, not a linear solve.

What is np.linalg.norm([3, 4])?

\(\sqrt{3^2+4^2}=\sqrt{25}=5\).

Explain in your own words why A[:, None, :] - B[None, :, :] produces every pairwise difference between rows of A and rows of B.

A becomes (m, 1, d) and B becomes (1, n, d). By the broadcasting rules each size-1 axis stretches, so the result is (m, n, d): position [i, j, :] holds A[i] − B[j]. A's rows are repeated along the new second axis and B's rows along the new first axis, so every row of A meets every row of B exactly once.
