The rhythm of every lesson

Every lesson follows the same steps, so you always know what comes next:

  1. Why it matters: one short paragraph at the top.
  2. The idea in plain words, then the precise version. Every new symbol is read out loud for you, for example “\(\hat{y}\) is read y-hat: our guess for \(y\)”.
  3. A worked example small enough for pencil and paper, with every intermediate number shown, in the style of the DIP guide.
  4. The book's own figures, each with a caption that tells you what to look at.
  5. Code you can run (predict first, then run, then explain), and interactive figures you can drag.
  6. Practice: exercises checked automatically, the book's exercises with layered solutions, a quiz, and flashcards.
  7. A checklist of “I can…” statements. Tick the lesson done only when they are all true.

Predict first, then run

Some cells are locked behind a question. Guessing what code will do before you run it is one of the best-proven ways to learn: being surprised makes the correction stick. A wrong guess costs nothing. If you're short on time you can skip the question.

Errors are normal, and this guide explains them

When code fails, Python prints an error message. The last line of the message is the important one. This guide adds a plain-English explanation underneath. This next cell fails on purpose so you can see what an error looks like:

print(total)   # we never created anything called total
Fix it: put a new line total = 10 at the top, then run again.

Exercises that check themselves

Yellow-bordered boxes are exercises. Write the code, press Check, and hidden tests run against it. If a test fails, you get a message saying what was expected. Hints open one at a time, and the full solution is always one click away. Try to get there without it first: struggling a little is exactly when you learn most.

Complete the function double so it returns twice the number it is given. For example double(4) should give 8. (A function is a named machine: a value goes in, a value comes out. You will learn them properly in Python I. For now, replace ... with the right expression.)

def double(x):

assert double(4) == 8, f"double(4) should be 8, got {double(4)}"
assert double(-1.5) == -3.0, "it should work for negative decimals too"

return sends a value back out of the function. Which expression means “x times 2”?

In Python, multiplication is the star: x * 2.

def double(x):
    return x * 2

Whatever number arrives as x, return x * 2 sends back twice it. The checks tried 4 and -1.5 to make sure it works for any number, not just one.

Worked examples with every number shown

Maths is always shown the way the DIP guide does it: what is given, then numbered steps, each with the numbers written out. Highlights show which numbers combine. Some examples reveal one step at a time so you can try the next step yourself first.

Worked example · the average of four exam marks
Given marks \(x_1=62,\ x_2=75,\ x_3=81,\ x_4=70\). Find the mean \(\bar{x}\) (read x-bar).
  1. Write the formula and say it out loud: \[\bar{x}=\frac{1}{n}\sum_{i=1}^{n}x_i\] “Add up every \(x_i\) for \(i\) from 1 to \(n\), then divide by \(n\).” Here \(n=4\) marks.The big \(\Sigma\) (sigma) is just a short way to write “add these up”.
  2. Add them: \(62+75+81+70 = \mathbf{288}\).
  3. Divide by \(n\): \(\bar{x} = \dfrac{288}{4} = \mathbf{72}\).
\(\bar{x}=72\)
Drag one mark far to the right, to 100. The mean moves towards it, but only by a quarter of the distance, because it is shared between four marks.
The mean (average)
\[\bar{x}=\frac{1}{n}\sum_{i=1}^{n}x_i\]

Add all \(n\) values, divide by how many there are.

Every exercise from the books appears in a card like the one below. Work it on paper first. Then open the layers one at a time: a hint, the final answer (to check yourself), the full step-by-step solution, and common mistakes. Press Mark solved when you could do it alone.

Find the mean of \(4,\ 8,\ 15,\ 16,\ 23\).

Hint

Add the five numbers, then divide by 5.

Final answer

\(\bar{x}=13.2\)

Full solution
  1. Sum: \(4+8+15+16+23=66\).
  2. Divide by \(n=5\): \(66/5=13.2\).
Common mistakes

Dividing by 4 (one less than the count). The mean divides by \(n\), the number of values.

Making it stick: quizzes, flashcards, tests

Reading something feels like learning, but pulling it back out of your memory is what makes it last. So every lesson ends with a short quiz, and every lesson adds flashcards to one deck. The deck uses FSRS-6, the same memory model as your COMSYS Formula Drill. It shows each card again just before you would forget it. Ten minutes a day with the deck keeps months of work alive. In your own words: why does this guide ask you to predict a cell's output before running it?

Making a guess and then seeing the real answer creates a small surprise when you're wrong. Surprise makes the correction memorable, so you learn more than you would by just reading the output.
What does the mean \(\bar{x}\) of \(n\) numbers equal?
\(\bar{x}=\frac{1}{n}\sum_{i=1}^n x_i\): add them all, divide by how many there are.
In a Python error message, which line should you read first?
The last line: it names the error type and the reason.
How do you run a code cell from the keyboard?
Click inside it and press Shift + Enter.

How much, how often

The plan assumes about 15–18 hours a week: roughly two hours on weekdays and a longer weekend session. Each lesson shows its estimated time at the top. A good daily routine is:

  1. 10 minutes: flashcards that are due.
  2. 90 minutes: one lesson, typing every cell yourself rather than only pressing Run.
  3. 20 minutes: the lesson's exercises without opening the solutions.

The trap to avoid: watching yourself understand. If you read a solution and think “yes, that makes sense”, you have not learned it yet. You have learned it when you can close the solution and produce it yourself.
