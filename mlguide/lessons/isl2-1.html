Every method in this guide, from a straight line to a deep network, is an attempt to answer one question: given some inputs, how do we learn the rule \(f\) that turns them into an output? This lesson sets up that question precisely, \(Y = f(X) + \varepsilon\), and explains why even a perfect model still makes mistakes. Everything else in ISLP and Prince is built on these few pages.

The story: advertising budgets and sales

A company sells one product in 200 different markets (think of 200 cities). In each market it spent some money on TV adverts, some on radio adverts and some on newspaper adverts, and it recorded how many units it sold. This is the Advertising data set. The company cannot change sales directly. It can change the three budgets. So the useful question is: if we know the budgets, can we predict sales, and which budget actually matters?

The budgets are the input variables. The book calls them by many names: predictors, independent variables, features, or just variables. Sales is the output variable, also called the response or dependent variable. In machine learning you will mostly hear “features” and “target”: they mean the same things.

The model: \(Y = f(X) + \varepsilon\)

Here is the one idea the whole book rests on. We assume the response is made of two parts added together. One part depends on the inputs through some fixed rule \(f\). The other part is random noise that the inputs cannot explain.

The general model (ISLP 2.1)
\[Y = f(X) + \varepsilon\]

Read: “Y equals f of X plus epsilon.” The response is a systematic part, \(f(X)\), plus a random error, \(\varepsilon\) (the Greek letter epsilon). \(f\) is fixed but unknown. \(\varepsilon\) has mean zero and is independent of \(X\).

SymbolSay it as / meaningTiny example
\(f\)“f”: the true rule linking inputs to the response. It exists, but nobody tells us what it is.\(f(16\text{ years}) \approx 50\) thousand dollars
\(f(X)\)“f of X”: the systematic part, what X tells us about Ythe height of the blue curve in Figure 2.2
\(\varepsilon\)“epsilon”: the error term, everything X cannot explaina person earns 54 where \(f\) says 50: \(\varepsilon=+4\)
\(\E(\varepsilon)=0\)“the expected value of epsilon is zero”: on average the errors cancel outerrors \(+4, -3, -1\): mean \(0\)

Two properties of \(\varepsilon\) matter. First, its mean is zero, so \(f(X)\) is the average value of \(Y\) for a given \(X\). Second, it is independent of \(X\): knowing the inputs tells you nothing about which way the error will go. If it did, that information would belong inside \(f\).

The Income data shows this picture clearly. It records years of education and income (in thousands of dollars) for 30 people. The data are simulated: the authors chose a true \(f\) and added noise, so for once we can see the true \(f\).

With two inputs, \(f\) is no longer a curve but a surface over a plane. Figure 2.3 shows income as a function of education and seniority (years in the job). Each red dot is a person; the vertical black stick joining it to the blue surface is that person's \(\varepsilon\).

In essence, statistical learning is a set of approaches for estimating \(f\). The rest of the chapter asks three questions: why do we want \(f\), how do we estimate it, and how do we judge an estimate (the next lesson, ISLP 2.2).

Why estimate \(f\)? Prediction

Often the inputs are cheap to measure but the output is expensive, slow or dangerous to find out. Then we want to predict \(Y\) from \(X\). Since the error averages to zero, the best guess we can make from \(X\) is our estimate of \(f(X)\):

Prediction (ISLP 2.2)
\[\hat Y = \hat f(X)\]

Read: “Y-hat equals f-hat of X.” The hat means estimate. \(\hat f\) (f-hat) is our estimate of the unknown \(f\), built from data; \(\hat Y\) (Y-hat) is the resulting prediction of \(Y\).

Example: if our estimate is the TV line from above, \(\hat f(\text{TV}) = 7.033 + 0.0475\,\text{TV}\), then for a market spending 100 thousand dollars on TV, \(\hat Y = 7.033 + 0.0475 \times 100 = 7.033 + 4.75 = 11.78\) thousand units.

When prediction is the only goal, \(\hat f\) can be a black box: we do not care what is inside as long as the predictions are accurate. The book's example: \(X\) is a set of measurements from a patient's blood sample, \(Y\) is the risk of a severe reaction to a drug. We want to predict \(Y\) so we can avoid giving the drug to high-risk patients. Nobody needs to understand the formula inside \(\hat f\) to use it.

Reducible and irreducible error

How accurate can \(\hat Y\) be? Two different things make it wrong.

  • \(\hat f\) is not exactly \(f\). We learned it from a limited data set with an imperfect method. This error is reducible: a better method or more data could shrink it.
  • Even \(f\) itself is not \(Y\). If we somehow knew \(f\) perfectly, so \(\hat Y = f(X)\), we would still be wrong by \(\varepsilon\), because \(\varepsilon\) cannot be predicted from \(X\). This error is irreducible: no method, however clever, can remove it.

Why is the irreducible error bigger than zero? Because \(\varepsilon\) contains (i) variables that matter but were never measured (the patient's genes, if we only measured blood), and (ii) variation that cannot be measured at all (the drug batch varies slightly; the patient feels different today).

New in this lesson · three rules for expected values

\(\E(Z)\), read “the expected value of Z”, is the long-run average of a random quantity \(Z\) (see Probability). You need three rules:

  1. Constants pass straight through: if \(c\) is a fixed number, \(\E(c) = c\) and \(\E(cZ) = c\,\E(Z)\). Example: \(\E(3)=3\); if \(\E(Z)=2\) then \(\E(5Z)=10\).
  2. The expectation of a sum is the sum of the expectations: \(\E(A + B) = \E(A) + \E(B)\). Example: \(\E(Z + 3) = \E(Z) + 3\).
  3. Variance: \(\Var(Z) = \E\big[(Z - \E Z)^2\big]\), the average squared distance from the mean. If \(\E(Z) = 0\) this is simply \(\Var(Z) = \E(Z^2)\).

Now we can split the expected squared prediction error into the two parts. The book says “it is easy to show”; here is every line. Fix one input value \(X\) and one estimate \(\hat f\), so the only randomness left is \(\varepsilon\).

Derivation · the reducible / irreducible split (ISLP 2.3)
\(Y = f(X) + \varepsilon\), \(\hat Y = \hat f(X)\), with \(X\) and \(\hat f\) held fixed. \(\E(\varepsilon) = 0\). Write \(a = f(X) - \hat f(X)\): this is just a fixed number (how far our estimate is from the truth at this \(X\)).
  1. Write out the prediction error: \[Y - \hat Y = f(X) + \varepsilon - \hat f(X) = \underbrace{f(X) - \hat f(X)}_{a} + \varepsilon = a + \varepsilon.\]Substitute the model for \(Y\) and regroup.
  2. Square it, expanding \((a+\varepsilon)^2\) like \((u+v)^2 = u^2 + 2uv + v^2\): \[(Y-\hat Y)^2 = a^2 + 2a\varepsilon + \varepsilon^2.\]
  3. Take expectations of each term (rule 2): \[\E(Y-\hat Y)^2 = \E(a^2) + \E(2a\varepsilon) + \E(\varepsilon^2).\]
  4. \(a\) is a constant, so (rule 1) \(\E(a^2) = a^2\) and \(\E(2a\varepsilon) = 2a\,\E(\varepsilon) = 2a \times 0 = 0\).This is where “the error has mean zero” is used: the cross term disappears.
  5. Because \(\E(\varepsilon) = 0\), rule 3 gives \(\E(\varepsilon^2) = \Var(\varepsilon)\).
  6. Put the pieces back: \[\E(Y-\hat Y)^2 = a^2 + 0 + \Var(\varepsilon) = \underbrace{[f(X)-\hat f(X)]^2}_{\text{reducible}} + \underbrace{\Var(\varepsilon)}_{\text{irreducible}}.\]
\(\E(Y-\hat Y)^2 = [f(X)-\hat f(X)]^2 + \Var(\varepsilon)\)
Expected squared prediction error (ISLP 2.3)
\[\E(Y-\hat Y)^2 = \E[f(X)+\varepsilon-\hat f(X)]^2 = \underbrace{[f(X)-\hat f(X)]^2}_{\text{Reducible}} + \underbrace{\Var(\varepsilon)}_{\text{Irreducible}}\]

Read: “The expected squared difference between Y and Y-hat equals the squared gap between f and f-hat, plus the variance of epsilon.” The first part shrinks as \(\hat f\) gets closer to \(f\). The second part never goes away.

Worked example · both parts with numbers, and a check by brute force
At some \(X\): the truth is \(f(X) = 50\), our estimate is \(\hat f(X) = 47\). The error \(\varepsilon\) takes only three values: \(-4\) with probability \(\tfrac14\), \(0\) with probability \(\tfrac12\), \(+4\) with probability \(\tfrac14\).
  1. Reducible part: \(a = f(X) - \hat f(X) = 50 - 47 = \mathbf{3}\), so \(a^2 = \mathbf{9}\).
  2. Check the error has mean zero: \(\E(\varepsilon) = (-4)\cdot\tfrac14 + 0\cdot\tfrac12 + 4\cdot\tfrac14 = -1 + 0 + 1 = 0\). ✓
  3. Irreducible part: \(\Var(\varepsilon) = \E(\varepsilon^2) = 16\cdot\tfrac14 + 0\cdot\tfrac12 + 16\cdot\tfrac14 = 4 + 0 + 4 = \mathbf{8}\).
  4. Formula: \(\E(Y-\hat Y)^2 = 9 + 8 = \mathbf{17}\).
  5. Brute force, without the formula. \(Y - \hat Y = a + \varepsilon = 3 + \varepsilon\) takes the values \(3-4 = -1\), \(3+0 = 3\), \(3+4 = 7\). Squared: \(1, 9, 49\). Weighted by the probabilities: \(1\cdot\tfrac14 + 9\cdot\tfrac12 + 49\cdot\tfrac14 = 0.25 + 4.5 + 12.25 = \mathbf{17}\). ✓The two routes agree, which is what the derivation promised.
  6. Now imagine a perfect estimate, \(\hat f(X) = 50\). Then \(a = 0\) and \(\E(Y-\hat Y)^2 = 0 + 8 = 8\). Even a perfect model has expected squared error 8.
reducible \(= 9\), irreducible \(= 8\), total \(= 17\); the best possible is \(8\).

Let us check the same thing by simulation, with normal noise this time: \(f(X)=50\), \(\hat f(X)=47\), \(\varepsilon \sim N(0, 5^2)\) (read “epsilon is normally distributed with mean 0 and standard deviation 5”). The formula predicts \(3^2 + 5^2 = 9 + 25 = 34\). np.random.default_rng(0) makes a seeded random generator, so you get the same numbers every time (see NumPy II).

We draw 100,000 values of \(\varepsilon\), form \(Y\), and average \((Y-\hat Y)^2\). Then we repeat with a perfect \(\hat f(X) = 50\). Roughly what two averages will print?

  1. 9 and 0
  2. 34 and 34
  3. 34 and 25
  4. 25 and 0
The first average estimates \(9 + 25 = 34\). With a perfect estimate the reducible part is 0 but the irreducible part \(\Var(\varepsilon) = 25\) remains. Option 1 forgets the noise entirely, which is the most common misunderstanding of what “a perfect model” can do.
rng = np.random.default_rng(0)
f_X, sigma = 50.0, 5.0
eps = rng.normal(0, sigma, size=100_000)    # 100,000 draws of the noise
Y = f_X + eps
for fhat_X in [47.0, 50.0]:
    avg_sq_err = np.mean((Y - fhat_X) ** 2)
    theory = (f_X - fhat_X) ** 2 + sigma ** 2
    print(f"fhat = {fhat_X}: simulated {avg_sq_err:.2f}   formula {theory:.2f}")
Read the output: the simulated averages land within a few hundredths of 34 and 25. They are not exact because 100,000 draws is a lot, but not infinitely many. Change sigma to 1 and run again: the irreducible part falls to 1 and the total to 10.
The blue curve is the true \(f\) (an Income-like S-shape); the orange line is \(\hat f\). At the chosen \(x_0\) the green dots are 200 possible values of \(Y\). Switch \(\hat f\) to “the true f”: the reducible part drops to 0 but the total does not. Then slide the noise \(\sigma\) down: only now does the total shrink. With the straight line, move \(x_0\) to 13 or 21, where the line misses the S-curve badly, and watch the reducible part (red bar) grow.

You already know this from communications. The irreducible error is the noise floor: no receiver, however clever, can recover a symbol more precisely than the channel noise allows, and \(\Var(\varepsilon)\) plays exactly the role of the noise power. The reducible error is like a mismatch between the true channel and your channel estimate: better estimation (more pilot symbols, a better estimator) shrinks it. The book's sentence “the irreducible error will always provide an upper bound on the accuracy of our prediction” is the ML version of “you cannot beat the noise floor”.

The focus of the whole book is on methods that make the reducible error small. Keep in mind that in practice we never know \(\Var(\varepsilon)\), so we never know how close to the best possible we already are.

Why estimate \(f\)? Inference

Sometimes we do not mainly want predictions. We want to understand how \(Y\) depends on \(X\). This is inference. Now \(\hat f\) cannot be a black box: we need to look inside it. Typical questions:

  • Which predictors are associated with the response? Often only a few of many inputs really matter, and finding them is valuable in itself.
  • What is the relationship between the response and each predictor? Positive (more \(X\), more \(Y\)) or negative? Does the effect of one predictor depend on the value of another?
  • Is the relationship linear, or more complicated? A straight-line summary is easy to explain, but may be wrong.

For Advertising, inference questions are: Which media are associated with sales? Which media generate the biggest boost in sales? How much do sales rise for a given increase in TV advertising?

Situation (from the book)GoalWhy
Direct-marketing campaign: who will respond to a mailing, from demographic variables?PredictionThe company only wants an accurate list of likely responders, not an understanding of each variable.
Advertising: which media matter, and by how much?InferenceThe answer is a statement about the relationship itself.
Which brand will a customer buy, from price, store location, discounts, competitor price…?InferenceThe interest is in how price is associated with the probability of buying.
House prices from crime rate, zoning, distance to river, air quality, schools…Both“How much is a river view worth?” is inference; “is this house over- or under-valued?” is prediction.

The goal decides the method. Linear models are easy to interpret, so they are good for inference, but they may predict less accurately. Highly non-linear methods (later chapters) may predict very well but are hard to interpret.

How do we estimate \(f\)? The training data

Every method starts from \(n\) observed data points, the training data, so called because we use them to train (teach) the method how to estimate \(f\). We need notation for “the value of the \(j\)-th predictor for the \(i\)-th observation”.

Our goal is to find a function \(\hat f\) such that \(Y \approx \hat f(X)\) for any observation \((X, Y)\), including ones we have not seen. Most methods are one of two kinds: parametric or non-parametric.

Parametric methods: assume a shape, then fit numbers

A parametric method works in two steps.

Step 1. Assume a shape for \(f\). The simplest assumption is that \(f\) is linear in \(X\):

The linear model (ISLP 2.4)
\[f(X) = \beta_0 + \beta_1 X_1 + \beta_2 X_2 + \cdots + \beta_p X_p\]

Read: “f of X equals beta-nought plus beta-one X-one plus … plus beta-p X-p.” \(\beta_0\) (beta-nought) is the intercept, the value when every input is 0. Each \(\beta_j\) (beta-j) is the change in \(f\) when \(X_j\) rises by 1 and the other inputs stay fixed.

The assumption turns an impossible problem (find any function of \(p\) variables) into an easy one: find just \(p + 1\) numbers \(\beta_0, \beta_1, \dots, \beta_p\), the parameters or coefficients. For Advertising, \(p = 3\), so 4 numbers.

Step 2. Fit (train) the model. Use the training data to choose the parameters so that \(Y \approx \beta_0 + \beta_1X_1 + \cdots + \beta_pX_p\). The most common way is (ordinary) least squares: choose the \(\beta\)s that make the sum of squared vertical gaps between the data and the fitted surface as small as possible. (Chapter 6 shows other ways to fit the same linear model.)

A first taste of least squares (preview of Chapter 3)

For a single predictor the least-squares line \(\hat y = \hat\beta_0 + \hat\beta_1 x\) has a closed-form answer:

Least-squares line, one predictor (proved in ISLP 3.1)
\[\hat\beta_1 = \frac{\sum_{i=1}^n (x_i-\bar x)(y_i-\bar y)}{\sum_{i=1}^n (x_i-\bar x)^2}, \qquad \hat\beta_0 = \bar y - \hat\beta_1 \bar x\]

\(\hat\beta_1\) is read beta-one-hat: our estimate of the slope. \(\bar x\) (x-bar) and \(\bar y\) (y-bar) are the means. The slope is “how x and y move together” divided by “how much x moves on its own”.

Worked example · least-squares line through three points by hand
Points \((x, y)\): \((1, 2)\), \((2, 3)\), \((3, 5)\).
  1. Means: \(\bar x = \frac{1+2+3}{3} = 2\), \(\bar y = \frac{2+3+5}{3} = \frac{10}{3} \approx 3.333\).
  2. Deviations: \(x_i - \bar x = -1, 0, 1\); \(y_i - \bar y = -\tfrac43, -\tfrac13, \tfrac53\).
  3. Numerator: \((-1)(-\tfrac43) + (0)(-\tfrac13) + (1)(\tfrac53) = \tfrac43 + 0 + \tfrac53 = \mathbf{3}\).
  4. Denominator: \((-1)^2 + 0^2 + 1^2 = \mathbf{2}\).
  5. Slope: \(\hat\beta_1 = 3/2 = \mathbf{1.5}\). Intercept: \(\hat\beta_0 = \tfrac{10}{3} - 1.5 \times 2 = 3.333 - 3 = \mathbf{0.333}\).
  6. Fitted values: \(\hat y = 0.333 + 1.5x\) gives \(1.833, 3.333, 4.833\). Residuals \(y - \hat y\): \(0.167, -0.333, 0.167\). They add to 0, as least-squares residuals always do when there is an intercept.
\(\hat y = 0.333 + 1.5\,x\)
x = np.array([1.0, 2.0, 3.0]); yy = np.array([2.0, 3.0, 5.0])
b1 = np.sum((x - x.mean()) * (yy - yy.mean())) / np.sum((x - x.mean()) ** 2)
b0 = yy.mean() - b1 * x.mean()
print("by the formula:", round(b0, 4), round(b1, 4))
print("np.polyfit    :", np.round(np.polyfit(x, yy, 1)[::-1], 4))   # polyfit gives [slope, intercept]
Both give intercept 0.3333 and slope 1.5. [::-1] reverses the array, because np.polyfit returns the highest power first (slope, then intercept).

With several predictors we let NumPy solve the least-squares problem directly. We add a column of ones to \(X\) (it multiplies \(\beta_0\)) and call np.linalg.lstsq, which finds the \(\beta\) that minimises the sum of squared errors (see NumPy II). With the column of ones, the first three rows become

\[\begin{pmatrix} 1 & 230.1 & 37.8 & 69.2\\ 1 & 44.5 & 39.3 & 45.1\\ 1 & 17.2 & 45.9 & 69.3\end{pmatrix}\begin{pmatrix}\beta_0\\ \beta_1\\ \beta_2\\ \beta_3\end{pmatrix} \approx \begin{pmatrix}22.1\\10.4\\9.3\end{pmatrix}\] 
X1 = np.column_stack([np.ones(len(X)), X])          # add the column of 1s for beta_0

The price of assuming a shape. The chosen form will usually not match the true \(f\) exactly. If it is far from the truth, the estimate is poor however much data we have. We can choose more flexible models that can take many shapes, but they have more parameters, and very flexible models can overfit: they follow the errors, the noise, too closely.

Non-parametric methods: let the data choose the shape

A non-parametric method makes no explicit assumption about the form of \(f\). It looks for an \(\hat f\) that gets as close to the data points as possible without being too rough or wiggly.

  • Advantage: because no shape is assumed, it can fit a much wider range of true \(f\)s. There is no risk of having picked a completely wrong form.
  • Disadvantage: since the problem is not reduced to a few parameters, it needs far more observations to estimate \(f\) accurately.

The book's example is a thin-plate spline (Chapter 7): a smooth surface that bends to follow the data, with a knob that sets how smooth it must be. SciPy has it: RBFInterpolator with kernel='thin_plate_spline' and a smoothing value. Large smoothing forces a smooth surface; smoothing=0 forces the surface through every point exactly. We first rescale both predictors to mean 0 and standard deviation 1, because education (10–22) and seniority (20–188) are on very different scales and the spline measures distance.

We fit a smooth spline (smoothing=1) and a rough one (smoothing=0) to the 30 people, and print each one's training MSE. Which statement will be true?

  1. The rough spline's training MSE is (essentially) 0
  2. Both training MSEs are around 46, like the plane
  3. The smooth spline has the smaller training MSE
With smoothing=0 the surface is forced through every training point, so every training error is 0 (you will see a number like \(10^{-26}\), which is zero up to rounding). The smooth spline is allowed to miss points, so its training MSE is larger, about 16.5. Whether zero training error is good is the next question.
from scipy.interpolate import RBFInterpolator
Z = np.column_stack([E, S])
Zs = (Z - Z.mean(axis=0)) / Z.std(axis=0)        # rescale both columns
smooth = RBFInterpolator(Zs, I, kernel='thin_plate_spline', smoothing=1)
rough  = RBFInterpolator(Zs, I, kernel='thin_plate_spline', smoothing=0)
print("training MSE, smooth spline:", round(np.mean((I - smooth(Zs)) ** 2), 2))
print("training MSE, rough spline :", np.mean((I - rough(Zs)) ** 2))
The rough spline “makes zero errors on the training data”, exactly as the book says about Figure 2.6. Z.mean(axis=0) takes the mean down each column (see NumPy II on axes).

How can we show that the rough fit is worse if its training error is zero? Pretend some people are new. Hide person 1, fit on the other 29, predict person 1, record the squared error; then do the same for person 2, and so on for all 30. The average is an honest estimate of the error on people the model has not seen. (This trick is called leave-one-out cross-validation; ISLP 5.1 teaches it properly.)

Which of the three fits will have the smallest error on the hidden people?

  1. The rough spline (zero training error)
  2. The plane (only 3 parameters)
  3. The smooth spline
The smooth spline wins (about 52.7). The plane is too rigid to follow the S-shape (about 57.2), and the rough spline chases noise, so its hidden-person error is the worst (about 75.6) despite its perfect training score.
def hidden_error(fit_predict):
    errs = []
    for i in range(30):
        keep = np.arange(30) != i                  # everyone except person i
        pred = fit_predict(Zs[keep], I[keep], Zs[i:i+1])
        errs.append((pred[0] - I[i]) ** 2)
    return np.mean(errs)

def plane(Ztr, ytr, Znew):
    bb, *_ = np.linalg.lstsq(np.column_stack([np.ones(len(Ztr)), Ztr]), ytr, rcond=None)
    return np.column_stack([np.ones(len(Znew)), Znew]) @ bb

print("plane        :", round(hidden_error(plane), 1))
for s in [1, 0]:
    tps = lambda Ztr, ytr, Znew: RBFInterpolator(Ztr, ytr, kernel='thin_plate_spline', smoothing=s)(Znew)
    print("spline s =", s, ":", round(hidden_error(tps), 1))
Read the output: plane ≈ 57.2, smooth spline ≈ 52.7, rough spline ≈ 75.6. Lowest training error (rough: 0) and lowest error on new people (smooth) are different models. Zero training error is a warning sign, not a trophy. Any method flexible enough can pass through every training point. What matters is accuracy on new observations. Chapter 5 discusses how to choose the right amount of smoothness.

The trade-off between prediction accuracy and interpretability

Some methods are restrictive (inflexible): they can produce only a small range of shapes. Linear regression can only make lines and planes. Others, like thin-plate splines, are flexible: they can produce a huge range of shapes. Why would anyone choose a restrictive method?

  • For inference, restrictive models are far easier to interpret. A linear model tells you directly “one more year of education goes with 5.9 thousand dollars”. A very flexible spline or boosted model can be so complicated that you cannot say how any single predictor relates to the response.
  • Even for prediction, flexible is not automatically better. Surprisingly, a less flexible method often predicts more accurately, because very flexible methods can overfit. You just saw this with the rough spline.

Supervised versus unsupervised learning

Everything so far is supervised learning: for every observation \(x_i\) we also have its response \(y_i\), and the response “supervises” the fit by telling the method when it is wrong. Linear regression, logistic regression (Chapter 4), GAMs, boosting and support vector machines are all supervised, and so is most of this book.

In unsupervised learning we observe the measurements \(x_i\) but no response. We cannot fit a regression because there is nothing to predict. We are “working blind”. What we can do is look for structure: relationships between variables, or groups among observations. The main tool is cluster analysis (clustering): decide, from \(x_1, \dots, x_n\) alone, whether the observations fall into distinct groups. Example: market segmentation. We measure customers' postcode, family income and shopping habits, and hope to find groups such as big spenders and small spenders, without ever being told who spends what.

Let us try it: make two data sets like Figure 2.8, hide the true labels, and ask K-means (a clustering method from Chapter 12, in scikit-learn) to find three groups. Then we compare its groups with the hidden truth.

K-means will be asked to find 3 groups in each data set. Which agreement with the hidden truth do you expect?

  1. 100% on both
  2. About 100% on the separated data, clearly less on the overlapping data
  3. About 33% on both, because it does not know the labels
Well-separated clusters are found almost perfectly. With overlap, points in the overlap zone are closer to the wrong centre and get assigned wrongly. The method never needed labels: the structure was in the \(x\) values themselves.
from sklearn.cluster import KMeans
rng = np.random.default_rng(1)
def make_groups(centres, spread):
    pts = [rng.normal(c, spread, size=(50, 2)) for c in centres]
    return np.vstack(pts), np.repeat([0, 1, 2], 50)

fig, axes = plt.subplots(1, 2, figsize=(9, 3.6))
for ax, (centres, sd, title) in zip(axes, [([(3, 9), (9, 6), (3, 3)], 0.9, 'separated'),
                                           ([(3, 6), (5.5, 4.5), (3, 3)], 0.9, 'overlapping')]):
    Xc, truth = make_groups(centres, sd)
    found = KMeans(n_clusters=3, n_init=10, random_state=0).fit_predict(Xc)
    # match each found cluster to the true group it overlaps most, then count agreement
    agree = sum(np.bincount(truth[found == k]).max() for k in range(3)) / len(truth)
    ax.scatter(Xc[:, 0], Xc[:, 1], c=found, cmap='viridis', s=14)
    ax.set_title(f"{title}: {agree:.0%} agree with truth")
Colours are the clusters K-means found, not the truth. On separated data agreement is 100%; on overlapping data it drops (read the exact figure in the title). The cluster numbers 0, 1, 2 are arbitrary, so we match each found cluster to the true group it shares most points with before counting. np.bincount counts how many times each label appears.

With two variables you can look at one scatterplot. With \(p\) variables there are \(p(p-1)/2\) different pairs, so \(p(p-1)/2\) scatterplots. For \(p = 10\) that is \(10 \times 9 / 2 = 45\) plots; for \(p = 100\) it is \(4{,}950\). Looking by eye stops working fast, which is why automated clustering matters (Chapter 12).

Count the scatterplots for \(p = 4\) variables A, B, C, D.
  1. Each variable can be paired with the \(p - 1 = 3\) others: \(4 \times 3 = 12\) ordered pairs.
  2. But (A, B) and (B, A) are the same plot with the axes swapped, so every plot was counted twice: \(12 / 2 = 6\).
  3. List them to check: AB, AC, AD, BC, BD, CD. Six. ✓
\(p(p-1)/2 = 4 \cdot 3/2 = 6\)

Some problems sit in between. If we have \(n\) observations but only \(m < n\) of them have a response (responses are expensive, predictors cheap), we have a semi-supervised problem: we want a method that uses the \(m\) labelled and the \(n - m\) unlabelled observations. It is beyond the scope of ISLP, but very common in practice (and in computer vision, where labelling images is expensive).

Regression versus classification

Variables are either quantitative (numbers: age, height, income, house value, a stock price) or qualitative, also called categorical: they take one of \(K\) classes (married or not; brand A, B or C; default yes or no; a leukaemia diagnosis of AML, ALL or none).

Problems with a quantitative response are regression problems. Problems with a qualitative response are classification problems. The line is not perfectly crisp:

  • Logistic regression (Chapter 4) is used for a two-class (binary) response, so it is a classification method despite its name. But it estimates class probabilities, which are numbers, so it can be seen as a regression method too.
  • K-nearest neighbours (next lesson) and boosting (Chapter 8) work for both kinds of response.
  • Whether the predictors are quantitative or qualitative matters much less: most methods handle both once qualitative predictors are coded as numbers (Chapter 3).
people = pd.DataFrame({'age': [23, 35, 41], 'income': [31.5, 52.0, 47.2],
                       'married': ['no', 'yes', 'yes'], 'brand': ['A', 'C', 'B']})
for col in people.columns:
    kind = 'quantitative' if pd.api.types.is_numeric_dtype(people[col]) else 'qualitative'
    task = 'regression' if kind == 'quantitative' else 'classification'
    print(f"{col:8s} {str(people[col].dtype):8s} {kind:13s} -> as a response: {task}")
pandas stores numbers as int64/float64 and text as object. A quick dtype check is a first guess at which variables are qualitative. It is only a first guess: a column of numbers like cylinders (4, 6, 8) or a code like origin (1, 2, 3) can be qualitative, as you will see in the lab.

Numbers are not always quantitative. A PIN code is a number but it is a label: PIN 560002 is not “twice” 280001. Before choosing regression or classification, ask: does arithmetic on this value make sense?

\(\E(2a\varepsilon) = 2a\,\E(\varepsilon) = 0\), because \(a = f(X)-\hat f(X)\) is fixed and \(\E(\varepsilon) = 0\).
Prediction vs inference
Prediction: accurate \(\hat Y\), \(\hat f\) may be a black box. Inference: understand how \(Y\) relates to each \(X_j\); \(\hat f\) must be interpretable.
\(x_{ij}\)
The value of predictor \(j\) for observation \(i\) (row \(i\), column \(j\)). In NumPy: X[i-1, j-1].
The two steps of a parametric method
1. Assume a form for \(f\) (e.g. linear). 2. Fit its parameters to the training data (e.g. least squares).
Main advantage and disadvantage of non-parametric methods
+ No risk of assuming the wrong shape. − Need many more observations.
Overfitting
A fit that follows the noise in the training data too closely; low training error, poor accuracy on new data.
Flexibility vs interpretability (Fig. 2.7)
More flexible methods are generally less interpretable: lasso/least squares (high interpretability) … boosting/deep learning (low).
Supervised vs unsupervised
Supervised: each \(x_i\) has a response \(y_i\). Unsupervised: only \(x_i\); look for structure, e.g. clustering.
Number of pairwise scatterplots for \(p\) variables
\(p(p-1)/2\).
Regression vs classification
Decided by the response: quantitative → regression; qualitative (categorical) → classification.
