Two ideas solve a surprising share of all interview problems. The first is the hash map (a Python dictionary or set): it lets you remember what you have seen and look it up instantly, which turns many O(n²) searches into a single O(n) pass. The second is two pointers: two index variables walking through a list, so that one pass does the work of two nested loops. This lesson teaches both slowly, with hand traces and a step-by-step animation, and then gives you ten problems to make them yours.

You'll use Python II Coding practice 1

By the end of this lesson you can

  • explain in plain words how a dictionary finds a key in O(1) average time, and what “hashable” means;
  • use the three hash-map patterns: counting, seen-so-far look-up (complements) and grouping by a signature;
  • use the two two-pointer patterns: from both ends of a sorted list, and read/write pointers moving the same way;
  • pick the right pattern from the words of a problem, and solve ten problems with it, tracing each by hand.

How a dictionary finds a key in one step

A list finds a value by checking its items one after another: up to \(n\) checks, so O(n). A dictionary does something cleverer. Understanding it in plain words will help you trust it.

  1. Python keeps a table of numbered slots, say 8 of them (they are often called “buckets”).
  2. To store the key "cat", Python first computes a number from the key, called its hash: hash("cat"), some big whole number. It takes the remainder after dividing by the number of slots, for example hash("cat") % 8 = 5, and puts the pair into slot 5.
  3. To look up "cat" later, Python computes the same hash, goes straight to slot 5, and checks that the key stored there really is "cat". No scanning at all.
  4. If two keys land in the same slot (a collision), Python tries another slot by a fixed rule. When the table is about two-thirds full, Python makes it bigger and re-places every key, so collisions stay rare.

So a look-up, an insert, or key in d costs one hash calculation plus one or two slot checks, whatever the size of the dictionary: O(1) on average. (In the very worst case, if every key collided, it would be O(n). With Python's hash functions that practically never happens, and interviewers accept “O(1) average”.) A set is the same table holding keys without values.

In hardware terms: a hash table is like a look-up-table ROM whose address is computed from the data itself, an address decoder fed by a checksum of the key. The CRC you compute for a frame is exactly this kind of function: it squashes a long input into a short number. Computing the address is O(1), and reading one memory word is O(1).

There is one rule. A key must never change after it is stored, or its hash (and so its slot) would become wrong. Numbers, strings and tuples cannot change, so they can be keys; such values are called hashable. Lists can change, so they cannot be keys. The next cell fails on purpose to show you the error.

groups = {}
groups[("a", "e", "t")] = ["tea"]     # a tuple as key: fine
print(groups)
groups[["a", "e", "t"]] = ["eat"]     # a list as key: not allowed
Read the error: TypeError: unhashable type: 'list'. When you want a list-like key (for example the sorted letters of a word), turn it into a tuple with tuple(...) or into a string with "".join(...).

Pattern 1: counting with a dictionary

When to use it: the problem talks about “how many times”, “most frequent”, “appears exactly once”, “same letters” or “anagram”. One pass builds a dictionary from each item to its count; then you answer the question by reading the dictionary.

Worked example · counting the letters of “banana”
Build counts by doing counts[ch] = counts.get(ch, 0) + 1 for each character of "banana".
  1. ch = "b": get returns 0 (not there yet), so store 1. counts = {b: 1}
  2. ch = "a": get 0, store 1. counts = {b: 1, a: 1}
  3. ch = "n": get 0, store 1. counts = {b: 1, a: 1, n: 1}
  4. ch = "a": get 1, store 2. counts = {b: 1, a: 2, n: 1}The second “a” finds the first one's count and adds to it.
  5. ch = "n": get 1, store 2. counts = {b: 1, a: 2, n: 2}
  6. ch = "a": get 2, store 3. counts = {b: 1, a: 3, n: 2}
counts = {b: 1, a: 3, n: 2}, built with six O(1) updates: O(n) time, and O(k) space for k different characters.
def count_items(items):
    counts = {}
    for x in items:
        counts[x] = counts.get(x, 0) + 1
    return counts

mine = count_items("banana")
print(mine)
print(mine == dict(Counter("banana")))     # check against the library
count_items([3, 1, 3, 3, 2])
Read the output: the same function counts the characters of a string or the numbers in a list, because you can loop over both. The comparison with Counter prints True. Try count_items("Mississippi"): notice that "M" and "m" would be different keys.

Pattern 2: “have I already seen what I need?”

When to use it: the problem asks for a pair (or a match) with some property, such as “two numbers that add up to a target”. The brute force tries every pair: O(n²). The trick is to walk through the list once, and for each item ask a dictionary whether its partner has already gone past. For a sum, the partner of x is target - x, called its complement.

Worked example · two numbers adding to 10 in [3, 8, 4, 6, 1]
Keep seen, a dictionary from value to the index where we saw it. At each position i, compute need = 10 - nums[i]. If need is in seen, we are done.

Why check before storing? So that an item can never pair with itself. For target 8 and the list [4, 1], the 4 must not find its own entry.

Pattern 3: grouping by a signature

When to use it: “group together the items that are the same in some sense”. Choose a signature: a hashable value that is equal for two items exactly when they belong together. Use it as a dictionary key whose value is the list of items in that group. For anagrams the signature is the sorted letters: "".join(sorted("tea")) is "aet", and so is the signature of “eat” and of “ate”.

def by_last_digit(nums):
    groups = {}
    for x in nums:
        key = x % 10                           # the signature: the last digit
        if key not in groups:
            groups[key] = []                   # first member of a new group
        groups[key].append(x)
    return groups

by_last_digit([12, 7, 42, 17, 30, 2])
Read the output: 12, 42 and 2 share the key 2; 7 and 17 share the key 7; 30 is alone under 0. The groups appear in the order their first member was met, because dictionaries remember insertion order.

Two pointers

In Coding practice 1 you reversed a list with two pointers that started at the two ends. The same idea comes in two common shapes.

Shape A: from both ends of a sorted list

Problem: in a sorted list, find two numbers that add up to a target. Put L at the smallest item and R at the largest, and look at their sum:

  • sum too small: the only way to make it bigger is a bigger left item, so L += 1;
  • sum too big: the only way to make it smaller is a smaller right item, so R -= 1;
  • sum equal: found.

Why it never misses the answer. Suppose nums[L] + nums[R] is too small. Then nums[L] plus any item between L and R is also too small, because those items are no bigger than nums[R]. So nums[L] cannot be part of any answer, and throwing it away is safe. The same argument works on the right. Each step throws away one item for good, so there are at most \(n-1\) steps: O(n) time and O(1) space.

Shape B: read and write pointers moving the same way

Problem: change a list in place, keeping some items and dropping or moving others. A read pointer r visits every item. A write pointer w marks where the next kept item should go. w never overtakes r, so we never overwrite an item before reading it. Everything before w is finished.

Sorted list [1, 3, 4, 6, 8, 11], target 10. The first sum is 1 + 11 = 12. Which pointer moves first?

  1. L moves right
  2. R moves left
  3. Both move
12 is too big, so we need a smaller sum. Only a smaller right item can give one, so R moves left (to 8). Moving L right would make the sum even bigger. Step through the widget to see the whole search: it ends at 4 + 6.
Press Next to move one step at a time. In “pair sum”, watch each pointer move only when the sum tells it to. Then try “move zeros”: w (green) lags behind r, and every non-zero is swapped back to position w. “two-sum (dict)” and “count letters” show the dictionary growing by one entry per step: the hash-map patterns from above.
def remove_value(nums, bad):
    """Remove every copy of `bad` in place; return how many items are kept."""
    w = 0
    for r in range(len(nums)):
        if nums[r] != bad:
            nums[w] = nums[r]       # keep it: copy it to the write position
            w += 1
    del nums[w:]                    # cut off the leftovers after the last kept item
    return w

xs = [3, 2, 2, 3, 4, 2]
print(remove_value(xs, 2), xs)
Read the output: 3 items are kept, and xs itself is now [3, 3, 4]. Trace it on paper: w goes 0→1 (copy 3), stays at 1 for both 2s, goes 1→2 (copy 3), 2→3 (copy 4), and stays for the last 2. del nums[w:] deletes everything from position w to the end.

What to say in an interview: name the trade-off. “The brute force is O(n²) time and O(1) space. With a hash map I can do it in O(n) time but O(n) space. If the input were sorted, two pointers would give O(n) time and O(1) space.” Interviewers love hearing the three options compared, even when you only code one.

First clean both phrases: make them lower-case and drop the spaces. a.lower().replace(" ", "") does both.

Count the letters of each cleaned phrase into a dictionary (Pattern 1), then compare the two dictionaries with ==. Two dictionaries are equal when they have the same keys with the same values.

A neat variation uses one dictionary: add 1 for every letter of a, subtract 1 for every letter of b, and check that every count ends at 0.

def is_anagram(a, b):
    a = a.lower().replace(" ", "")
    b = b.lower().replace(" ", "")
    if len(a) != len(b):              # quick exit: different lengths can never match
        return False
    counts = {}
    for ch in a:
        counts[ch] = counts.get(ch, 0) + 1    # +1 for every letter of a
    for ch in b:
        counts[ch] = counts.get(ch, 0) - 1    # -1 for every letter of b
    for v in counts.values():
        if v != 0:
            return False
    return True

The idea. Anagrams have identical letter counts. This solution uses one dictionary: add 1 for each letter of a, subtract 1 for each letter of b. If every count ends at 0, the letters balance exactly. (Building two dictionaries and comparing them, or Counter(a) == Counter(b), is just as good.)

def first_unique(s):
    counts = {}
    for ch in s:                       # pass 1: how often does each character appear?
        counts[ch] = counts.get(ch, 0) + 1
    for i, ch in enumerate(s):         # pass 2: the first one with count 1, in string order
        if counts[ch] == 1:
            return i
    return -1

The idea. “Appears once” depends on the whole string, so pass 1 collects the counts, and pass 2 respects the order. Two O(n) passes are still O(n).

At position i, the partner you need has the value target - nums[i]. How could you know instantly whether that value appeared earlier?

Keep seen = {} mapping value → index. In the loop: if need is in seen, return (seen[need], i); otherwise store seen[nums[i]] = i. Check first, store second.

def two_sum(nums, target):
    seen = {}                              # value -> index where we saw it
    for i, x in enumerate(nums):
        need = target - x                  # the complement of x
        if need in seen:
            return (seen[need], i)         # seen[need] < i because it was stored earlier
        seen[x] = i                        # store AFTER checking, so x cannot pair with itself
    return None

The idea. Pattern 2. While walking left to right, the dictionary holds every value to the left of the current position. If the current value's complement is among them, the pair is complete. The earlier index always comes first, so i < j happens automatically.

def group_by_letters(words):
    groups = {}                              # signature -> list of words
    for w in words:
        key = "".join(sorted(w))             # e.g. "tea" -> "aet"
        if key not in groups:
            groups[key] = []
        groups[key].append(w)
    return list(groups.values())             # dicts keep insertion order

The idea. Two words are anagrams exactly when their sorted letters are equal, so the sorted letters make a perfect dictionary key. The dictionary does the grouping for us.

Keep depth: how many brackets are open right now. ( adds one, ) takes one away.

There are two ways to fail: depth drops below 0 at some moment (a ) with nothing to close, so return False at once), or depth is not 0 at the end. Only comparing the total numbers of ( and ) is not enough: ")(" has one of each.

def is_balanced(s):
    depth = 0                     # number of brackets open right now
    for ch in s:
        if ch == "(":
            depth += 1
        elif ch == ")":
            depth -= 1
            if depth < 0:         # closed a bracket that was never opened
                return False
    return depth == 0             # nothing may stay open

The idea. The depth is a running count of open brackets. Balanced means it never dips below zero and it ends at exactly zero. This is a counting solution where the count is one number instead of a dictionary.

Comparing only the totals would wrongly say yes: two opens and two closes. The order matters, and the running depth sees the order.

Deal with the empty list first. Then compare position by position: position 0 of every word, then position 1, and so on. When must you stop?

Loop i over the positions of the first word. For every other word w: if i == len(w) (that word has run out) or w[i] != words[0][i], return words[0][:i]. If the loop finishes, the whole first word is the prefix.

def common_prefix(words):
    if not words:                        # an empty list counts as False
        return ""
    first = words[0]
    for i in range(len(first)):
        ch = first[i]
        for w in words[1:]:
            if i == len(w) or w[i] != ch:    # w ran out, or disagrees at position i
                return first[:i]
    return first

The idea. Read the words column by column, as if they were written one under another. The prefix ends at the first column where some word disagrees or has no letter left.

Loop while left < right, and compute s = nums[left] + nums[right] each time.

If s == target, return (left, right). If s < target, the sum must grow: left += 1. Otherwise it must shrink: right -= 1. After the loop, return None.

def pair_sum_sorted(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return (left, right)
        elif s < target:
            left += 1          # nums[left] is too small to pair with anything: discard it
        else:
            right -= 1         # nums[right] is too big to pair with anything: discard it
    return None

The idea. Shape A of two pointers. Each step throws away one item that provably cannot be in any answer (see the argument in the teaching section), so we never miss a pair, and the search window shrinks by one every step.

Shape B: a read pointer r visits every position, and the write pointer w marks where the next non-zero should go.

For each r: if nums[r] != 0, swap nums[w] and nums[r], then w += 1. Swapping (rather than copying) leaves the zeros behind automatically. The “move zeros” mode of the widget above shows every step.

def move_zeros(nums):
    w = 0
    for r in range(len(nums)):
        if nums[r] != 0:
            nums[w], nums[r] = nums[r], nums[w]   # bring the non-zero back to position w
            w += 1

The idea. Everything before w is finished: the non-zeros seen so far, in order. Everything from w up to r is zeros. When r meets a non-zero, the swap moves it to the end of the finished part and pushes a zero into the gap.

Where is the largest square? It must come from one of the two ends: the most negative number, or the most positive one.

Use pointers left = 0 and right = n - 1, and a position k going from n - 1 down to 0. At each step put the bigger of nums[left]**2 and nums[right]**2 into result[k], and move inwards the pointer it came from.

range(n - 1, -1, -1) counts down: it starts at n−1, stops before −1, and steps by −1, so it gives n−1, n−2, …, 0.

def sorted_squares(nums):
    n = len(nums)
    result = [0] * n
    left, right = 0, n - 1
    for k in range(n - 1, -1, -1):          # k = n-1, n-2, ..., 0: fill the biggest slots first
        a, b = nums[left] ** 2, nums[right] ** 2
        if a > b:
            result[k] = a
            left += 1
        else:
            result[k] = b
            right -= 1
    return result

The idea. Squaring folds the number line at 0: big negative numbers become big positive ones. In a sorted list the squares are largest at the two ends and smallest somewhere in the middle. So the biggest square not yet used is always at left or at right, and we fill the result from the back. It is the merge from Coding practice 1, run backwards.

Three steps: count the characters (Pattern 1); put the (character, count) pairs in order; take the first k.

Sort the pairs with a key that puts bigger counts first and, among equal counts, earlier letters first: key=lambda p: (-p[1], p[0]). Tuples are compared item by item, so the count decides first and the letter breaks ties.

Finally [ch for ch, c in pairs[:k]] keeps just the characters of the first k pairs. Slicing past the end is safe.

def top_k_chars(text, k):
    counts = {}
    for ch in text:
        counts[ch] = counts.get(ch, 0) + 1
    pairs = sorted(counts.items(), key=lambda p: (-p[1], p[0]))   # count high->low, then letter a->z
    return [ch for ch, c in pairs[:k]]

The idea. Count, then rank. The sort key (-count, ch) turns “count from high to low, then letter from a to z” into one ordinary small-to-large sort: a count of 4 becomes −4, which comes before −2. Slicing pairs[:k] is safe even when k is larger than the list.

Why is key in d for a dictionary O(1) on average, while x in xs for a list is O(n)?

  1. Dictionaries are written in C and lists are not
  2. Dictionaries keep their keys sorted and use a clever search
  3. The dictionary computes the slot from the key's hash and goes straight there
  4. Dictionaries have a size limit
The hash of the key tells Python which slot to check, so there is no scanning. A is false (both are written in C). B describes a different structure (a sorted search would be O(log n)). D is false.

Which of these can be a dictionary key?

  1. ["a", "b"]
  2. ("a", "b")
  3. {"a": 1}
  4. {1, 2} (a set)
Only values that cannot change (hashable ones) can be keys. A tuple cannot change, so it is hashable. Lists, dictionaries and sets can change, so they are not.

In two-sum with a dictionary, why do we check for the complement before storing the current value?

  1. So that a value cannot be paired with itself
  2. Because storing first is slower
  3. To keep the dictionary sorted
  4. It makes no difference
If we stored first, then for target 8 the value 4 would find its own entry and return (i, i). Checking first means the dictionary only holds items strictly to the left. Speed (B) and order (C) are not the reason, and it does make a difference (D).

Sorted list, two pointers, target 15. Right now nums[L] + nums[R] is 11. What happens next?

  1. R moves left
  2. Both pointers move
  3. Return None
  4. L moves right
11 is too small. Only a bigger left item can raise the sum, and nums[L] cannot be part of any answer (even with the largest remaining item it falls short). So L moves right. Moving R left (A) would make the sum smaller still.

In move-zeros, which statement is true at every moment of the loop?

  1. w is bigger than r
  2. Everything before position w is a non-zero, in the original order

This always-true statement (an invariant) is why the algorithm is correct. w never passes r (A is false); the list is not sorted (C); the zeros reach the end only when the loop is over (D).
