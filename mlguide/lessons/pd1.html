Real datasets are tables: rows of cars, patients or days, and columns with names, of different types, with gaps. pandas is the Python library for such tables, and every ISLP lab starts by loading one. This lesson teaches you to load, inspect, slice, summarise, clean and plot a table, so that the Auto, College and Advertising data hold no surprises.

You'll use NumPy I (indexing, masks, axis) · NumPy II (random generators) · matplotlib (figures and axes)

By the end of this lesson you can

  • build a Series and a DataFrame, and load a CSV file with pd.read_csv, handling missing-value codes (na_values) and row labels (index_col);
  • inspect a table with head, shape, columns, dtypes, info and describe;
  • select columns, and rows by label (.loc), by position (.iloc) or by a condition, and say what each returns;
  • sort, add columns, count values, and compute group summaries with groupby;
  • find and drop missing values, convert a table to NumPy arrays, and make the plots the ISLP lab makes (scatter, histogram, box plot, scatter matrix).
We can think of a data frame as a sequence of arrays of identical length; these are the columns.

1. Series and DataFrame

pandas has two main objects. A Series is a 1-D array of values with a label for each position. A DataFrame is a table: several Series side by side, one per column, sharing the same row labels. The row labels are called the index.

index ↓ / columns →mpgcylindershorsepower
chevrolet chevelle malibu18.08130

plymouth satellite18.08150

Each column is a Series with its own dtype (here float, int, int); the bold labels on the left are the index. Compare a NumPy 2-D array: one dtype for everything, and rows and columns known only by number.

2. Loading data with read_csv

A CSV file (comma-separated values) is a plain text table: one line per row, commas between values, column names on the first line. pd.read_csv(filename) reads it into a DataFrame. The file must be in the working folder (or you give its full path). The first rows of Auto.csv look like this:

Auto = pd.read_csv("Auto.csv")       # ISLP In[73]
print(Auto.shape)
Auto.head()
Read the output: 397 cars and 9 columns. head() shows the first 5 rows (head(10) shows 10). The bold numbers 0, 1, 2… on the left are the index: pandas made up row labels because we did not give any.

The horsepower puzzle: a missing-value code

ISLP (In[75]–[76]) notices something odd: the horsepower column has dtype object, which means text, not numbers.

Why would pandas read a column of horsepower numbers as text?

  1. pandas always reads CSV files as text
  2. Somewhere in the column there is a value that is not a number
  3. Horsepower values are too large for integers
A column gets one dtype. If even one entry cannot be read as a number, pandas keeps the whole column as text (dtype object). The other columns became numbers, so option 1 is wrong. The culprit here is ?, which the file uses to mean “unknown”.
print(Auto["horsepower"].dtype)
print(np.unique(Auto["horsepower"])[-5:])     # the last few distinct values, sorted as text
print((Auto["horsepower"] == "?").sum(), "entries are '?'")
Read the output: object; the distinct values end with '95' '96' '97' '98' '?' (sorted as text, so '?' comes last); and 5 entries are '?'. The fix is to tell read_csv that ? means “missing”.

The argument na_values=['?'] turns every ? into np.nan, the “not a number” marker from NumPy I. Now the column can be numeric. The book's whitespace-separated version, Auto.data, needs one more argument saying that the separator is any run of spaces: sep=r"\s+". (ISLP writes delim_whitespace=True; current pandas warns that this spelling is going away, so we use the new one.)

Auto = pd.read_csv("Auto.data", na_values=["?"], sep=r"\s+")   # ISLP In[77]
print(Auto["horsepower"].dtype)
print(Auto["horsepower"].sum())     # 40952.0, as in the book
print(Auto.shape)                   # (397, 9)
Auto_new = Auto.dropna()            # drop every row that has a missing value
print(Auto_new.shape)               # (392, 9): five rows had a '?'
Auto = Auto_new                     # ISLP In[80]: keep the clean version
Read the output: horsepower is now float64 (a float, because nan is a float), its total is 40952 exactly as ISLP prints, and dropping the five incomplete rows leaves 392 cars. r"\s+" is a pattern meaning “one or more spaces or tabs”; the r before the quotes stops Python from interpreting the backslash. Section 9 shows other ways to handle missing values.

4. Selecting columns and rows

Columns

Square brackets with a string pick one column as a Series. With a list of strings they pick several columns as a DataFrame (ISLP In[83]). For column names without spaces, Auto.mpg is a shortcut for Auto["mpg"].

What is the difference between Auto["mpg"] and Auto[["mpg"]]?

  1. None: both are the mpg column
  2. The first is a Series (1-D); the second is a DataFrame with one column (2-D)
  3. The second raises an error
The outer brackets mean “select”; the inner brackets make a list. A list of column names always returns a DataFrame, even a list of one. This matches NumPy's rule: A[:, 2] is 1-D but A[:, 2:3] is 2-D.
print(type(Auto["mpg"]), Auto["mpg"].shape)
print(type(Auto[["mpg"]]), Auto[["mpg"]].shape)
Auto[["mpg", "horsepower"]].head(3)
Read the output: a Series of shape (392,) and a DataFrame of shape (392, 1). The last line shows the two-column table.

Rows: slices and conditions

Quirk to remember: inside plain square brackets a string picks columns, but a slice picks rows. Auto[:3] is the first three rows (ISLP In[81]). A boolean Series picks the rows where it is True (In[82]), exactly like a NumPy mask.

idx_80 = Auto["year"] > 80          # a boolean Series: True for cars built after 1980
print(idx_80.sum(), "cars after 1980")
Auto[idx_80].head(3)
Read the output: 58 cars have year above 80 (the year is stored as two digits, 81 or 82). Their rows keep their original index labels (338, 339…), which is how you can trace them back.

Conditions with .loc, &, | and lambda

.loc accepts a boolean Series for the rows and a list of names for the columns (ISLP In[92]). Combine conditions with & (and), | (or) and ~ (not), with brackets around each, exactly as in NumPy. Text columns (and a text index) have string methods under .str, such as .str.contains("ford").

idx_80 = Auto_re["year"] > 80
print(Auto_re.loc[idx_80, ["weight", "origin"]].shape)                        # ISLP In[92]
both = (Auto_re["year"] > 80) & (Auto_re["mpg"] > 30)
print(Auto_re.loc[both, ["weight", "origin"]].shape)                          # ISLP In[94]
fd = (Auto_re["displacement"] < 300) & (Auto_re.index.str.contains("ford")
                                        | Auto_re.index.str.contains("datsun"))
Auto_re.loc[fd, ["weight", "origin"]].head()                                  # ISLP In[95]
Read the output: 58 cars after 1980; 34 of them also do more than 30 mpg; and the first Ford and Datsun cars with displacement under 300. The origin codes are 1 = America, 2 = Europe, 3 = Japan, so Fords show 1 and Datsuns 3.
New in this lesson · lambda inside .loc

ISLP also writes Auto_re.loc[lambda df: df["year"] > 80, ["weight", "origin"]] (In[93]). lambda df: ... is a one-line function without a name (you met it in the plotting lesson). When .loc receives a function, it calls it with the DataFrame itself and uses the boolean Series it returns. The result is the same as with idx_80. The advantage: it works in the middle of a chain of operations, where the intermediate table has no name of its own.

r1 = Auto_re.loc[lambda df: df["year"] > 80, ["weight", "origin"]]
r2 = Auto_re.loc[Auto_re["year"] > 80, ["weight", "origin"]]
print(r1.equals(r2))
print(Auto_re["origin"].isin([2, 3]).sum(), "European or Japanese cars")   # isin: membership test
Read the output: True, and 147 cars from Europe or Japan. isin is the tidy way to write “equals any of these values” instead of a chain of |.

ISLP's summary, which is worth memorising: for integer-based queries use iloc; for string and Boolean selections use loc; to filter rows with a function, use loc with a lambda.

7. New columns, dropping and renaming

Assigning to a new column name creates the column; the right-hand side is computed for all rows at once, like NumPy arithmetic. One mile per US gallon is 0.4251 kilometres per litre:

Auto_re["kpl"] = Auto_re["mpg"] * 0.4251                       # a new column
Auto_re["power_to_weight"] = Auto_re["horsepower"] / Auto_re["weight"]
print(Auto_re[["mpg", "kpl", "power_to_weight"]].head(3))
terms = Auto_re.columns.drop(["kpl", "power_to_weight"])   # a list of names minus some (ISLP Ch. 3)
print(list(terms))
Auto_re = Auto_re.drop(columns=["kpl", "power_to_weight"])     # remove them again
print(Auto_re.shape)
Read the output: 18 mpg is 7.65 km per litre. columns.drop returns the list of column names without the ones you name; ISLP Chapter 3 uses Boston.columns.drop('medv') to get “every predictor except the response”. df.drop(columns=[...]) returns a new DataFrame without those columns, so we assign it back. df.rename(columns={"old": "new"}) renames in the same style.

Changing a selection: use .loc, and .copy() when you mean a copy. As in NumPy, a selection may or may not share data with the original. Code like sub = Auto[Auto["year"] > 80] followed by sub["mpg"] = 0 makes pandas print a SettingWithCopyWarning: it cannot tell whether you wanted to change Auto too. Two clean rules: to change the original, use one .loc call, Auto.loc[Auto["year"] > 80, "mpg"] = ...; to work on a separate table, write sub = Auto[Auto["year"] > 80].copy().

late = Auto[Auto["year"] > 80].copy()     # an independent copy: no warning, original safe
late["mpg_rounded"] = late["mpg"].round()
print(late.shape, "mpg_rounded" in Auto.columns)
Read the output: the copy has 58 rows and the new column; the original Auto did not gain a column (False).

8. Counting and group summaries

value_counts and categorical columns

s.value_counts() counts how often each distinct value appears, most frequent first. ISLP then turns cylinders into a categorical column (In[106]): a column whose values are labels from a small fixed set, not quantities. Cylinders take only the values 3, 4, 5, 6 and 8, and a 5-cylinder car is not “halfway” between 4 and 6 in any useful sense.

print(Auto["cylinders"].value_counts())
Auto.cylinders = pd.Series(Auto.cylinders, dtype="category")    # ISLP In[106]
print(Auto.cylinders.dtype)
Auto["cylinders"].describe()                                      # ISLP In[113]
Read the output: 199 four-cylinder cars, 103 eight, 83 six, 4 three and 3 five. After the conversion the dtype is category with five categories, and describe() now reports count, number of unique values, the most common value (top, 4) and its frequency (199) instead of a mean. pd.Categorical(values) is another way to build the same kind of column.

groupby: split, apply, combine

groupby: df.groupby("cylinders")["mpg"].mean() does three things: it splits the rows into groups that share a value of cylinders, applies the mean to each group's mpg, and combines the results into one Series indexed by the group values.

Worked example · a groupby by hand
Six cars: cylinders [4, 8, 4, 6, 8, 4], mpg [30, 15, 26, 20, 13, 28]. Find groupby("cylinders")["mpg"].mean().
  1. Split by cylinders: group 4 holds rows 0, 2, 5 with mpg 30, 26, 28; group 6 holds row 3 with 20; group 8 holds rows 1, 4 with 15, 13.
  2. Apply the mean to each group: \((30+26+28)/3=28\); \(20/1=20\); \((15+13)/2=14\).
  3. Combine into a Series indexed by the group values 4, 6, 8, sorted.
4 → 28.0, 6 → 20.0, 8 → 14.0

In the real Auto data, which group of cars will have the highest mean mpg?

  1. 8 cylinders
  2. 6 cylinders
  3. 4 cylinders
Fewer cylinders usually means a smaller engine and better fuel economy: 4-cylinder cars average about 29.3 mpg. (The 5-cylinder group, only 3 cars, is close behind at 27.4; the 3-cylinder group, 4 rotary-engined Mazdas, does only 20.6.)
toy = pd.DataFrame({"cylinders": [4, 8, 4, 6, 8, 4], "mpg": [30, 15, 26, 20, 13, 28]})
print(toy.groupby("cylinders")["mpg"].mean())
print(Auto.groupby("cylinders", observed=True)["mpg"].mean().round(2))
Auto.groupby("origin")[["mpg", "weight"]].agg(["mean", "count"])
Read the output: first the worked example's 28, 20, 14. Then the real data: 4-cylinder cars average 29.28 mpg, 8-cylinder cars 14.96. (observed=True tells pandas to list only categories that actually occur; it silences a warning for categorical columns.) The last table uses agg to compute several summaries per group: Japanese cars (origin 3) average 30.45 mpg and are the lightest, American cars (origin 1) 20.03 mpg and the heaviest.

map and apply: a function on every value

s.map(dictionary) replaces each value by its entry in the dictionary; s.apply(function) calls a function on each value; df.apply(function) calls it on each column (or on each row with axis=1). When a vectorised version exists (arithmetic, .str methods, NumPy functions), prefer it: apply is a Python loop in disguise.

names = Auto["origin"].map({1: "America", 2: "Europe", 3: "Japan"})
print(names.value_counts())
print(Auto["name"].apply(lambda s: s.split()[0]).head(3))   # first word = the maker
num = Auto[["mpg", "horsepower", "weight"]]
num.apply(lambda col: col.max() - col.min())                  # the range of each column
Read the output: 245 American, 79 Japanese and 68 European cars; the makers of the first three cars; and the range of each column (mpg spans 37.6, horsepower 184, weight 3527 pounds).

9. Missing values

pandas marks missing entries as NaN. df.isna() gives a table of True/False; summing it counts the gaps per column, and its mean gives the fraction missing (True counts as 1, as in NumPy). Most summaries such as mean() skip missing values automatically. To deal with them you can drop rows (dropna()), fill them (fillna(value)), or keep them and let later steps handle them.

ISLP (In[99]–[100]) builds a table with about 20% of its entries missing, then prints the percentage missing in each column. It uses rng.choice([0, np.nan], p=[0.8, 0.2], size=A.shape) from NumPy II: adding nan to a number gives nan, so about one entry in five is wiped out.

rng = np.random.default_rng(1)
A = rng.standard_normal((127, 5))
M = rng.choice([0, np.nan], p=[0.8, 0.2], size=A.shape)
A += M
D = pd.DataFrame(A, columns=["food", "bar", "pickle", "snack", "popcorn"])
for col in D.columns:
    template = 'Column "{0}" has {1:.2%} missing values'
    print(template.format(col, np.isnan(D[col]).mean()))
D[:3]
Read the output: each column is missing between about 16% and 30% of its values. pd.DataFrame(array, columns=[...]) turns a NumPy array into a table with column names. The template.format(...) fills {0} with the first argument and {1:.2%} with the second, written as a percentage with 2 decimals. The modern f-string does the same: f'Column "{col}" has {frac:.2%} missing values'.

Each of D's 5 columns is missing about 20% of its values, independently. Roughly how many of the 127 rows survive D.dropna()?

  1. About 100 (80%)
  2. About 40 (a third)
  3. None
A row survives only if all five entries are present: \(0.8^5\approx0.33\), so about 42 rows. The actual count is 35, because these columns happen to be missing a little more than 20% on average. The tempting 80% forgets that a row needs every column to be complete.
print(D.isna().sum())              # gaps per column
print(D.dropna().shape)            # rows with no gaps at all
print(D.mean().round(3))           # means skip NaN automatically
D_filled = D.fillna(D.mean())      # fill each gap with its column's mean
print(D_filled.isna().sum().sum())
Read the output: only about a third of the 127 rows are complete, because a row is dropped if any of its five entries is missing (\(0.8^5\approx0.33\)). Dropping is fine for Auto (5 rows out of 397) but wasteful here. fillna(D.mean()) fills each column's gaps with that column's mean, leaving 0 missing values. (Mean-filling is simple but shrinks the spread of the data; ISLP Chapter 12 shows better methods.)

10. From pandas to NumPy

Models eventually need NumPy arrays. df.to_numpy() (or the older df.values, which ISLP also uses) returns the table's numbers as a 2-D array; a Series gives a 1-D array. You lose the labels, so pick and order your columns first.

X = Auto[["horsepower", "weight"]].to_numpy()
y = Auto["mpg"].to_numpy()
print(type(X), X.shape, X.dtype, y.shape)
X1 = np.column_stack([np.ones(len(X)), X])          # add an intercept column (NumPy I)
beta = np.linalg.lstsq(X1, y, rcond=None)[0]        # least squares (NumPy II)
print(beta.round(4).tolist())
Read the output: a (392, 2) float array and a (392,) vector. The fitted coefficients say: predicted mpg is about 45.64, minus 0.0473 per horsepower, minus 0.0058 per pound of weight. That is a multiple linear regression, the topic of ISLP 3.2, done with tools you now have.

fig, axes = plt.subplots(1, 3, figsize=(13, 3.8))

Read the output: left, mpg falls as horsepower rises, along a curve rather than a straight line (ISLP Chapter 3 fits a quadratic to exactly this). Middle, the mpg histogram with 12 bins. Right, one box per number of cylinders: 4-cylinder cars are the most efficient, 8-cylinder the least. pandas adds its own title “Boxplot grouped by cylinders” above the figure. The ax= argument tells each method which panel to draw in.

A scatter matrix draws every pair of columns against each other, with histograms on the diagonal: the fastest overview of a dataset (ISLP In[110]–[111]).

axs = pd.plotting.scatter_matrix(Auto[["mpg", "displacement", "weight"]], figsize=(6.5, 6.5), alpha=0.5)
Read the output: a 3 × 3 grid. The diagonal shows each variable's histogram; each off-diagonal panel is a scatter plot of one pair. Displacement and weight rise together almost along a line (heavier cars have bigger engines), and both fall with mpg along curves. Strongly related predictors like these cause trouble for regression (collinearity, ISLP §3.3.3). ISLP also runs scatter_matrix(Auto) on all columns; it works, but 64 small panels are hard to read.

df.plot() with no kind draws one line per column against the index, which is the natural plot for time series (prices, sensor readings). For example D[["food", "bar"]].plot() would draw two noisy lines with gaps where values are missing.

13. Quiz

After pd.read_csv("Auto.csv"), the horsepower column has dtype object. Why?

  1. Horsepower is stored as text in every CSV
  2. Some entries are ?, so the column cannot be numeric
  3. pandas reads all integers as objects
One non-numeric entry makes the whole column text. na_values=['?'] fixes it.

What does Auto[["mpg"]] return?

  1. A Series
  2. A float
  3. A DataFrame with one column
A list of column names always gives a DataFrame. Auto["mpg"] gives a Series.

An index has labels a, b, c, d, e in order. How many rows does df.loc["b":"e"] return?

Label slices include both ends: b, c, d, e, so 4 rows. df.iloc[1:4] would return 3 (b, c, d).

Which line keeps cars built after 1980 that also do more than 30 mpg?

  1. Auto[(Auto.year > 80) & (Auto.mpg > 30)]
  2. Auto[Auto.year > 80 and Auto.mpg > 30]
  3. Auto.iloc[Auto.year > 80, Auto.mpg > 30]
Element-wise & with brackets. and fails on a Series (ambiguous truth value). .iloc takes positions, not conditions on columns.

Groups: A has values 10 and 30, B has value 20. What is the mean of B in groupby(...).mean()?

B has one value, 20, so its mean is 20. A's mean would be 20 as well.

df.dropna() on a 100-row table where each of 4 columns is missing 10% of values independently. Roughly how many rows survive?

  1. 90
  2. About 66
  3. 60
A row survives only if all 4 entries are present: \(0.9^4\approx0.66\), so about 66 rows. This is why dropping rows can waste a lot of data.

What does df.std() divide by, for a column of n values?

  1. n, like NumPy
  2. n + 1
  3. n − 1
pandas defaults to the sample standard deviation (ddof=1); NumPy defaults to ddof=0.

Why does ISLP convert cylinders to a categorical column?

  1. It takes only a few distinct values, so it is better treated as qualitative (groups) than as a quantity
  2. To save memory only
  3. Because numbers cannot be plotted
With few distinct values, treating cylinders as groups lets box plots and models handle each level separately (ISLP §3.3.1 on qualitative predictors).

Explain the difference between .loc and .iloc to a classmate, including how slices behave, with an example from Auto.

.loc selects by labels: index labels and column names (or booleans). .iloc selects by integer position, exactly like NumPy. Label slices include the end label; position slices exclude the end position. With Auto indexed by name, Auto_re.loc["amc rebel sst", "mpg"] and Auto_re.iloc[3, 0] both give 16.0, but Auto_re.loc["buick skylark 320":"ford torino"] has 4 rows while Auto_re.iloc[1:4] has 3.
