A program is a list of instructions that Python carries out one line at a time, from top to bottom. The simplest instruction is print(...), which shows whatever you put inside the round brackets.

You already know %. In DSP, circular convolution and the DFT index samples "modulo \(N\)": sample \(n\) of an \(N\)-periodic signal is sample \(n \bmod N\). In Python that is n % N. For example 9 % 8 is 1: index 9 wraps round to index 1 of an 8-point buffer, exactly like a circular buffer in a DSP chip.

Order of operations (BODMAS)

When a line mixes operators, Python follows the order you learned in school as BODMAS: Brackets first, then Orders (powers, **), then Division and Multiplication (/ // % *, left to right), then Addition and Subtraction (left to right).

Worked example · how Python reads 2 + 3 * 4 ** 2 / 8
Find the value of 2 + 3 * 4 ** 2 / 8, one operation at a time.
  1. Powers first: 4 ** 2 = 16. The line becomes 2 + 3 * 16 / 8.O comes before D, M, A, S.
  2. Multiplication and division, left to right: 3 * 16 = 48, then 48 / 8 = 6.0. The line becomes 2 + 6.0.Same level, so we go left to right. Division with / gives a decimal.
  3. Addition last: 2 + 6.0 = 8.0.
2 + 3 * 4 ** 2 / 8 = 8.0
print(2 + 3 * 4 ** 2 / 8)
print((2 + 3) * 4)      # brackets change the order
print(2 + 3 * 4)
print(-3 ** 2)          # careful: this is -(3 ** 2)
print((-3) ** 2)
Read the output: 8.0 matches the worked example. (2 + 3) * 4 is 20 but 2 + 3 * 4 is 14: brackets made the addition happen first. The last two show a trap: -3 ** 2 is -9, because the power is done before the minus sign is applied. If you mean "minus three, squared", write (-3) ** 2, which is 9. When in doubt, add brackets: they cost nothing and make code easier to read.

Decimals are (very slightly) approximate

Numbers with a decimal point are stored in binary with about 16 significant digits, so a few simple decimals can't be stored exactly. One day you'll see this and think something is broken. It isn't:

print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
print(round(0.1 + 0.2, 10) == 0.3)
Read the output: 0.30000000000000004: the error is in the 17th digit. So asking "is it exactly 0.3?" with == says False. Rounding to 10 decimal places first gives True. In ML code we therefore compare decimals with a small tolerance, never with exact ==. (round(x, d) rounds x to d decimal places; == asks "are these equal?" and is explained in section 7.)

This is quantisation error, the same idea as an ADC with a finite number of bits. Python's decimals are IEEE-754 double precision: 53 bits of mantissa, so the relative error is about \(2^{-53}\approx 1.1\times10^{-16}\). Whole numbers (int), on the other hand, are exact and have no maximum size in Python: 2 ** 100 just works, unlike a 32-bit register.

3 · Variables: giving names to values

Typing 62 + 75 + 81 + 70 every time would be tiring. A variable is a name you give to a value so you can use it later. You create one with a single equals sign:

total = 62 + 75 + 81 + 70
count = 4
mean = total / count
print(total, count, mean)
Read the output: 288 4 72.0. The first line worked out the sum (288) and gave it the name total. The third line looked up total and count, divided, and named the result mean. The = lines print nothing themselves; only print shows anything.

Read = out loud as "gets", not "equals": "total gets 62 plus 75 plus 81 plus 70". It is an instruction, an assignment, not a maths equation. Python always does it in two steps:

  1. work out the value on the right;
  2. tie the name on the left to that value.

So x = x + 1, which is nonsense as an equation, makes perfect sense as an instruction: "work out x + 1 using the current x, then let x name the result".

The mental picture: labels on boxes

The best picture for Python is this: values are boxes sitting in the computer's memory, and names are labels (luggage tags) tied to boxes. Assignment ties a label to a box. Two labels can be tied to the same box. Step through the three short programs below, one line at a time, and watch the labels move.

Start with Numbers: before each press of Next line, predict where each label will point. Then do Lists: at step 3 a list changes and both labels see the change. This is the most surprising thing in Python for beginners, and a classic interview question. Finally, A running total shows how a loop builds up a sum; you'll write loops yourself in section 8.

Two short-cuts you'll see everywhere: x += 1 means x = x + 1, and similarly -=, *=, /=. And you can't use a name before it has been given a value: Python then stops with a NameError. This cell fails on purpose:

learning_rate = 0.01

Read the error: the last line says NameError: name 'learning_rat' is not defined. (In a notebook on your Mac, Python even adds a suggestion: Did you mean: 'learning_rate'?) Fix the typo and run again. NameError almost always means a typo, or a cell above that you haven't run yet.

Rules for names

  • Letters, digits and underscores only, not starting with a digit: mean_mark, x2, y_hat are fine; 2x, mean-mark, my mark are not.
  • Capital letters matter: Mark and mark are two different names.
  • Don't use Python's own words (if, for, def, return, class, in, …), and avoid the names of built-in tools such as sum, len, list, print: if you write sum = 10, the real sum stops working until you restart.
  • Choose names that say what the value is: n_samples beats n, and test_error beats e. Python style is lower case with underscores (called snake_case).

Converting between types

Each type's name also works as a converter. This matters because data read from files often arrives as text, and you must turn it into numbers before doing maths.

print(int("42") + 1)       # text to whole number
print(float("72.5") * 2)   # text to decimal
print(str(90) + " marks")  # number to text
print(int(3.9))            # float to int CHOPS OFF the decimals (no rounding)
print(round(3.9))          # round() rounds to the nearest whole number
print(round(3.14159, 2))   # ... or to 2 decimal places
Read the output: 43, 145.0, 90 marks, 3, 4, 3.14. Look at int(3.9): it gives 3, not 4, because int just throws the decimal part away (it truncates towards zero). Use round when you want rounding.

Mixing types that don't fit together is an error. The classic beginner one is joining text and a number with +:

score = 90
print("Your score is " + score)
Read the error: TypeError: can only concatenate str (not "int") to str. Python means: "you asked me to join (concatenate) text with a number, and I don't know whether you want text or maths". Three fixes: "Your score is " + str(score), or print("Your score is", score) with a comma, or (best) an f-string, which comes next.

int + float is fine; str + number is not. Python happily mixes the two number types (2 + 0.5 is 2.5, a float), and True counts as 1 and False as 0 in arithmetic (so True + True is 2, which turns out to be handy for counting). But text and numbers never mix without an explicit conversion.

5 · Strings: working with text

A string is text inside quotes. Single '…' or double "…" quotes both work; pick one and be consistent. Use double quotes when the text contains an apostrophe: "It's working".

name = "Linear Regression"
print(len(name))          # number of characters, spaces included
print(name + "!")         # + joins strings
print("ab" * 3)           # * repeats a string
print(name[0], name[-1])  # first and last character
print(name.upper())
print(name.lower())
print(name.replace("Linear", "Logistic"))
Read the output: 17 characters (6 + 1 space + 10). Joining gives Linear Regression!; "ab" * 3 is ababab. name[0] is L: positions start at 0 (section 6 explains this with lists). name[-1], position −1, means the last character, n. Then three methods.

A method is a tool that belongs to a value, called with a dot: value.method(...). Read name.upper() as "name, give me your upper-case version". The brackets are needed even when empty: they mean "do it now". String methods never change the original string; they give back a new one (strings can't be changed in place). The most useful ones:

f-strings: putting values inside text

An f-string is a string with the letter f just before the opening quote. Inside it, anything in curly braces {…} is worked out and its value is put into the text. It is the cleanest way to print results.

model = "linear regression"
mse = 0.416666667
accuracy = 0.8534
n = 1234567
print(f"The {model} model has MSE {mse}")
print(f"MSE to 2 decimals: {mse:.2f}")
print(f"Accuracy: {accuracy:.1%}")
print(f"Samples: {n:,}")
print(f"[{model:>20}]")      # right-aligned in 20 characters
print(f"2 + 3 = {2 + 3}")     # any expression works inside the braces
Read the output: the first line puts both values in as they are. After a colon inside the braces comes a format spec: :.2f means "as a fixed-point decimal with 2 digits after the point" → 0.42 (rounded). :.1% multiplies by 100 and adds a percent sign, with 1 decimal → 85.3%. :, adds thousands separators → 1,234,567. :>20 right-aligns in a space 20 characters wide (< is left, ^ centre), which makes neat tables. 6 · Lists: many values under one name

Machine learning is about many numbers: a column of house prices, a row of pixel values, a set of predictions. A list holds many values in order, under one name. Write it with square brackets and commas:

marks = [62, 75, 81, 70, 90, 55, 68]
print(marks)
print(len(marks))                 # how many items
print(sum(marks), min(marks), max(marks))
print(sum(marks) / len(marks))    # the mean, for any number of marks
Read the output: the list itself; len (length) is 7; the sum is 501, the smallest 55 and the largest 90; the mean is 501 / 7 = 71.57142857142857. The last line works unchanged whether there are 7 marks or 7 million: that is why we use lists.

Positions start at 0

Each item has a position, called its index. Python counts positions from 0, so the first item is marks[0] and the last of 7 is marks[6]. Think of the index as "how many steps from the start": the first item is zero steps in. Negative indices count from the end: marks[-1] is the last item, marks[-2] the one before it.

item62758170905568
index from the start0123456
index from the end−7−6−5−4−3−2−1

For any item, negative index = positive index − length. For 68: \(6 - 7 = -1\).

Slices: cutting out a piece

A slice picks out a run of items: marks[start:stop] gives the items from position start up to but not including position stop. The best picture: the indices are fence posts between the boxes, and a slice cuts at two posts. marks[1:4] cuts at post 1 and post 4, giving the three boxes in between: [75, 81, 70]. A handy fact follows: a slice [a:b] has b − a items.

  • Leave out start to begin at the start: marks[:3] is the first three, [62, 75, 81].
  • Leave out stop to go to the end: marks[3:] is everything from position 3, [70, 90, 55, 68]. Together, marks[:3] + marks[3:] is the whole list again.
  • A third number is the step: marks[::2] takes every second item, [62, 81, 90, 68]. A step of -1 walks backwards: marks[::-1] is the list reversed.
Blue numbers above the boxes are positions from the start; orange ones below are positions from the end. In slice mode the green line is the start fence post and the dashed red line the stop post: everything between them is taken. if, elif, else

An if statement runs a block of code only when a condition is true:

Two pieces of grammar matter: the colon : at the end of the if line, and the indentation (4 spaces) of the lines that belong to the if. Indentation is grammar in Python. Other languages use curly brackets to group lines; Python uses the spaces at the start of the line. All lines in a block must be indented by the same amount, normally 4 spaces (pressing Tab in a code cell or in VS Code inserts 4 spaces). A block is always introduced by a line ending in a colon.

Worked example · squared errors, the heart of regression
True values \(y = (3,\ 5,\ 7)\). A model predicted \(\hat y = (2.5,\ 5,\ 8)\) (\(\hat y\) is read y-hat: our guess for \(y\)). The error (or residual) for item \(i\) is \(y_i - \hat y_i\). Find each squared error and their sum.
  1. Item 0: \(3 - 2.5 = 0.5\), squared: \(0.25\).
  2. Item 1: \(5 - 5 = 0\), squared: \(0\).
  3. Item 2: \(7 - 8 = -1\), squared: \(1\).Squaring makes every error positive, so a too-high guess and a too-low guess can't cancel out.
  4. Sum of squared errors: \(0.25 + 0 + 1 = 1.25\). Mean squared error: \(1.25 / 3 = 0.41\overline{6}\).
SSE = 1.25, MSE ≈ 0.4167
Mean squared error
\[\mathrm{MSE}=\frac{1}{n}\sum_{i=1}^{n}\left(y_i-\hat y_i\right)^2\]

Read: "M-S-E equals one over n times the sum, for i from 1 to n, of y-i minus y-hat-i, squared". In words: for each item take the error and square it; add them all up; divide by how many items there are. Example above: \((0.25+0+1)/3 = 0.4167\).

y     = [3, 5, 7]        # true values
y_hat = [2.5, 5, 8]      # predictions
total = 0
for i in range(len(y)):          # i = 0, 1, 2
    err = y[i] - y_hat[i]
    print(f"i={i}: error {err:+.1f}, squared {err ** 2:.2f}")
    total = total + err ** 2
print("sum of squared errors:", total)
print("MSE:", total / len(y))
Read the output: one line per item, exactly the numbers of the worked example (the format :+.1f always shows a plus or minus sign). Then SSE 1.25 and MSE 0.4166666666666667. The maths and the code have the same shape: \(\sum\) became a loop with a running total. Python counts from 0 while maths usually counts from 1, so \(y_1\) in a formula is y[0] in code. You've been using functions all along: print, len, sum, round. A function is a named machine: you feed values in, it does a job, and it hands a value back. Writing your own means writing a job once and using it everywhere, with different inputs. Every model you build in this course is a function: inputs go in, a prediction comes out.

11 · Reading error messages without panic

Errors are not failures; they are Python telling you precisely what it couldn't do. Every programmer sees dozens a day. The message is called a traceback, and you read it like this:

  1. Read the last line first. It has the error type (e.g. TypeError) and a short reason.
  2. Then find the line number it points at (line 3) and look at that line of your code. With a SyntaxError, a caret ^ points at the spot.
  3. Ask what the values were at that moment. Add a print just above the failing line if you're not sure.

This guide adds a plain-English hint under each error. Here are four more you'll meet often, each failing on purpose. Read each one, then fix it.

12 · Putting it together: your first ML-flavoured program

Here is everything from this lesson in one small program. It takes a few (TV budget, sales) pairs from ISLP's Advertising data, makes predictions with a straight line, and reports how good they are. In ISLP chapter 3 you'll learn how to find the best line; for now we try two lines and compare their errors, which is the core idea of all model fitting: try settings, measure the error, keep the better one.

from math import sqrt

tv    = [230.1, 44.5, 17.2, 151.5, 180.8]   # TV budget, thousands of dollars
sales = [22.1, 10.4, 9.3, 18.5, 12.9]       # sales, thousands of units

def predict_all(xs, b0, b1):
    return [b0 + b1 * x for x in xs]        # one-line loop (you'll learn this in Python II)

def mse(y, y_hat):
    total = 0
    for i in range(len(y)):
        total += (y[i] - y_hat[i]) ** 2
    return total / len(y)

for b0, b1 in [(5.0, 0.08), (7.0, 0.05)]:
    preds = predict_all(tv, b0, b1)
    err = mse(sales, preds)
    print(f"line: sales = {b0} + {b1} * TV  ->  MSE {err:6.2f}, RMSE {sqrt(err):5.2f}")
Read the output: two lines, one per candidate line. The second, \(7 + 0.05\,\mathrm{TV}\) (close to the least-squares line ISLP finds, \(7.03 + 0.0475\,\mathrm{TV}\)), has the smaller MSE (8.33 against 11.73), so it fits these five points better; its RMSE says its predictions are typically off by about 2.9 thousand units. Two new things appear, both taught in Python II: for b0, b1 in [...] takes two values at a time, and [b0 + b1 * x for x in xs] is a short way to write the append loop. Try: add a third pair (7.0, 0.0475) to the list and see whether it does even better.

Check yourself

What is 23 % 7?

\(7 \times 3 = 21\) and \(23 - 21 = 2\). So 23 // 7 is 3 and 23 % 7 is 2.

What is the value of 2 + 3 * 4?

Multiplication first (BODMAS): \(3 \times 4 = 12\), then \(2 + 12 = 14\). (2 + 3) * 4 would be 20.

After a = [1, 2], b = a, b.append(3), what is a?

  1. [1, 2]
  2. [1, 2, 3]
  3. [1, 2, [3]]
  4. an error
b = a ties a second label to the same list; append changes that one list, so a sees it. Option 1 would be right with b = a.copy(). Option 3 confuses append(3) with append([3]).

xs = [10, 20, 30, 40, 50]. Which expression gives [20, 30, 40]?

  1. xs[2:4]
  2. xs[1:3]
  3. xs[2:5]
  4. xs[1:4]
20 is at position 1 and 40 at position 3. The stop is exclusive, so we need stop = 4: xs[1:4], with 4 − 1 = 3 items. xs[1:3] gives only [20, 30]; xs[2:4] gives [30, 40]; xs[2:5] gives [30, 40, 50].

What is type(7 / 7)?

  1. float
  2. int
  3. bool
  4. str
/ always produces a float, here 1.0. 7 // 7 would be the int 1.

The values are 2, 4, 6, 8, 10 (it stops before 12): five times.

A function computes a result but ends with print(result) instead of return result. What does x = f(...) store in x?

  1. the result
  2. the text that was printed
  3. None
  4. it's an error to call it
Without a return, a function hands back None. The value was only shown on screen, not handed back. Any later maths with x gives a TypeError mentioning NoneType.

With mark = 65, the chain if mark >= 40: … elif mark >= 60: … elif mark >= 75: … runs which branch?

  1. the >= 60 branch
  2. the >= 40 branch
  3. all three
  4. none
Python runs only the first branch whose condition is true, and 65 >= 40 is true, so the others are never checked. This ordering is a bug: test the highest threshold first.

True values \(y = (1, 2)\), predictions \(\hat y = (2, 2)\). What is the MSE?

Errors: \(1-2=-1\) and \(2-2=0\). Squared: 1 and 0. Mean: \((1+0)/2 = 0.5\).

In your own words, what does x = x + 1 do, and why isn't it a contradiction?

= is an instruction ("gets"), not an equation. Python first works out the right side using the current value of x (say 5 + 1 = 6), then moves the label x onto the new value 6. After the line, x is one bigger than before.
