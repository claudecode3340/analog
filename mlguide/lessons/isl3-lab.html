3.6.2 Simple linear regression on the Boston data

The Boston data record medv, the median house value (in $1000s), for 506 neighbourhoods around Boston, with 12 predictors such as rm (average rooms per house), age (share of homes built before 1940) and lstat (percentage of households with low socioeconomic status).

Boston = load_data("Boston")
print(Boston.shape)
Boston.columns
Read the output: 506 rows, 13 columns: 12 predictors plus medv. (The book's printed output also lists a black column, but its later code and outputs use these 12 predictors, as here.) In Jupyter, Boston? would show a description.

First the book builds the design matrix by hand: a column of ones for the intercept and the lstat column.

X = pd.DataFrame({'intercept': np.ones(Boston.shape[0]),
                  'lstat': Boston['lstat']})
X[:4]
Line by line. Boston.shape[0] is the number of rows (506); np.ones(506) is 506 ones. The dictionary {'intercept': ..., 'lstat': ...} becomes a two-column DataFrame. X[:4] shows the first four rows: this is exactly \(\bX\) from lesson 3.2, \(\begin{pmatrix}1&4.98\\1&9.14\\1&4.03\\1&2.94\\\vdots&\vdots\end{pmatrix}\).
y = Boston['medv']
model = sm.OLS(y, X)

summarize(results)
Line by line. sm.OLS(y, X) specifies the model: response y, design matrix X. It does not fit anything yet. model.fit() does the least-squares fitting and returns a results object. summarize(results) (from ISLP) makes the four-column table.

Using transformations: fit and transform

Building \(\bX\) by hand is fine for one predictor, but tedious with many predictors, interactions or polynomials. ISLP borrows an idea from scikit-learn: a transform. A transform is an object created with some settings. It has two main methods: fit(), which looks at the data and does any preliminary computation (for example, checking that the columns exist, or computing means for centring), and transform(), which applies it to produce the model matrix.

design = MS(['lstat'])
design = design.fit(Boston)
X = design.transform(Boston)
X[:4]
Read the output: the same matrix as our hand-made one, with the intercept column added automatically. MS(['lstat']) says “the model uses the column lstat”. fit(Boston) checks that lstat exists in Boston. transform(Boston) builds the matrix.
design = MS(['lstat'])
X = design.fit_transform(Boston)
X[:4]
Read the output: identical. fit_transform does both steps in one call. Note that design itself has changed: it now remembers what it learnt in fit, so we can later call design.transform(new_data) on new data.

The full summary table

The book shows results.summary() without its output. Here it is, because reading it is a core skill.

print(results.summary())
Read the output, top block:
  • Dep. Variable: medv, the response. No. Observations: 506, \(n\).
  • Df Model: 1 is \(p\), the number of predictors; Df Residuals: 504 is \(n-p-1\).
  • R-squared: 0.544: lstat explains 54.4% of the variance in medv. Adj. R-squared: 0.543 is a version that penalises extra predictors (Chapter 6).

  • Log-Likelihood, AIC, BIC: model-comparison criteria (Chapter 6). Date and Time just record when you ran it.
Middle block: the summarize() columns again, plus [0.025, 0.975]: the 95% confidence interval for each coefficient. For lstat, \([-1.026, -0.874]\): \(-0.9500\pm1.965\times0.0387\).
Bottom block (checks of the error assumptions): Omnibus and Jarque-Bera test whether the residuals are normal (tiny p-values here: they are not quite normal; Skew 1.45 says the residuals have a long right tail). Durbin-Watson: 0.892 checks correlated errors: about 2 means none; well below 2 suggests positive correlation between neighbouring rows (here neighbouring rows are nearby suburbs). Cond. No. (condition number) flags numerical collinearity when it is very large (thousands or more).
results.params
Read the output: just the coefficients, as a pandas Series with names: intercept 34.553841, lstat −0.950049. Other useful attributes: results.bse (standard errors), results.tvalues, results.pvalues, results.rsquared, results.resid, results.fittedvalues.

Predictions with confidence and prediction intervals

To predict at new values, make a data frame with the same predictor column, and let design turn it into a model matrix (adding the intercept column).

new_df = pd.DataFrame({'lstat': [5, 10, 15]})
newX = design.transform(new_df)
newX
Read the output: three rows \((1, 5), (1, 10), (1, 15)\). This is why we kept the fitted design: it builds new matrices the same way it built the training one.
new_predictions = results.get_prediction(newX)
print(new_predictions.predicted_mean)
print(new_predictions.conf_int(alpha=0.05))
print(new_predictions.conf_int(obs=True, alpha=0.05))
Read the output:
  • predicted_mean: \(34.5538-0.9500\times5=29.80\), then 25.05 and 20.30.
  • conf_int(alpha=0.05): 95% confidence intervals for the mean medv: at lstat = 10, (24.47, 25.63).
  • conf_int(obs=True, ...): 95% prediction intervals for one neighbourhood: at lstat = 10, (12.83, 37.28).
Same centre (25.05), but the prediction interval is about 21 times wider, because it includes the irreducible error of a single neighbourhood (RSE ≈ 6.2) while the confidence interval only reflects uncertainty in the line. alpha=0.05 means 95% (1 − alpha).
Worked example · the interval at lstat = 10 by hand
From the fit: \(n=506\), RSE \(=6.2158\), \(\bar x=12.653\), \(S_{xx}=25{,}752.4\), \(t_{0.975,504}=1.9647\), \(\hat y_0=25.0533\).
  1. \((x_0-\bar x)^2/S_{xx}=(10-12.653)^2/25{,}752.4=7.039/25{,}752.4=0.000273\). Plus \(1/n=0.001976\): total 0.002250.
  2. CI: SE \(=6.2158\times\sqrt{0.002250}=6.2158\times0.04743=0.2948\). Half-width \(1.9647\times0.2948=0.579\). Interval \([24.47,\ 25.63]\).
  3. PI: SE \(=6.2158\times\sqrt{1.002250}=6.2228\). Half-width \(1.9647\times6.2228=12.226\). Interval \([12.83,\ 37.28]\).
The formulas of lesson 3.2 reproduce statsmodels' intervals exactly.
x, n = Boston['lstat'], len(Boston)
rse = np.sqrt(results.scale)
Sxx = np.sum((x - x.mean()) ** 2)
tq = 1.9647                                   # t quantile with 504 df
base = 1 / n + (10 - x.mean()) ** 2 / Sxx
print(f"RSE = {rse:.4f}, xbar = {x.mean():.3f}, Sxx = {Sxx:.1f}")
print("CI half-width:", round(tq * rse * np.sqrt(base), 3))
print("PI half-width:", round(tq * rse * np.sqrt(1 + base), 3))
Read the output: half-widths 0.579 and 12.226: add and subtract them from 25.053 and you get the intervals above. results.scale is \(\text{RSE}^2\).

Defining functions: drawing the regression line

The book now writes its first function, abline, to add a line with a given intercept and slope to a plot.

def abline(ax, b, m, *args, **kwargs):
    "Add a line with slope m and intercept b to ax"
    xlim = ax.get_xlim()
    ylim = [m * xlim[0] + b, m * xlim[1] + b]
    ax.plot(xlim, ylim, *args, **kwargs)
Line by line.
  • def abline(ax, b, m, ...): ax is an existing plot's axes, b the intercept, m the slope.
  • The string on the next line is the docstring: a description of the function.
  • ax.get_xlim() returns the left and right ends of the x-axis.
  • ylim computes the line's height at both ends: \(m x + b\).
  • *args collects any extra unnamed arguments (like 'r--') and **kwargs any extra named ones (like linewidth=3); both are passed straight on to ax.plot. That lets the caller style the line without abline knowing about styles.
Defining a function prints nothing; it just teaches Python a new word.
ax = Boston.plot.scatter('lstat', 'medv')
abline(ax,
       results.params.iloc[0],
       results.params.iloc[1],
       'r--',
       linewidth=3)
Read the output: the scatter of medv against lstat with the red dashed least-squares line. Boston.plot.scatter is pandas' quick scatter plot, which returns the axes. The call ends up as ax.plot(xlim, ylim, 'r--', linewidth=3): 'r--' means red and dashed. The book writes results.params[0]; current pandas wants .iloc[0] (“position 0”) for positional access, so we use that. Look at the picture: the points curve (high values at small lstat lie above the line, middle values below it): evidence of non-linearity. (matplotlib's built-in ax.axline() could also draw the line, but writing your own function is a skill worth having.)

Variance inflation factors and list comprehensions

A list comprehension builds a list from a loop in one expression: [expression for item in sequence]. The book uses one to compute the VIF of every column.

vals = [VIF(X, i)
        for i in range(1, X.shape[1])]
vif = pd.DataFrame({'vif': vals},
                   index=X.columns[1:])
vif
Line by line. X.shape[1] is the number of columns (13: intercept + 12). range(1, 13) gives 1, …, 12, skipping column 0, the intercept, whose VIF is not of interest. For each i, VIF(X, i) regresses column i on all the other columns and returns \(1/(1-R^2)\). The data frame puts the 12 values next to their names. Read the output: the largest are tax (9.00) and rad (7.45), near the rule-of-thumb limit of 10: property tax and highway access are strongly related. The rest are below 5. The book calls these VIFs “not that exciting”.
vals = []
for i in range(1, X.values.shape[1]):
    vals.append(VIF(X.values, i))
print(np.round(vals, 3))
Read the output: the same 12 numbers, computed with an ordinary for loop and .append. The comprehension is just a more compact way to write this. X.values is the plain NumPy array inside the DataFrame.

3.6.5 Interaction terms

In ModelSpec, a tuple of two names such as ('lstat', 'age') means “include their product as an interaction column”.

X = MS(['lstat',
        'age',
        ('lstat', 'age')]).fit_transform(Boston)
model2 = sm.OLS(y, X)
summarize(model2.fit())
Read the output: the interaction lstat:age has coefficient 0.0042 and p = 0.025: some evidence that the effect of lstat depends on age. The slope of lstat is \(-1.3921+0.0042\times\text{age}\): about −1.39 in a new neighbourhood (age 0) but about \(-1.39+0.42=-0.97\) where age is 100. age's own p-value is 0.971, but by the hierarchical principle we keep it.

3.6.6 Non-linear transformations of the predictors

X = MS([poly('lstat', degree=2), 'age']).fit_transform(Boston)
model3 = sm.OLS(y, X)
results3 = model3.fit()
summarize(results3)
Read the output: two polynomial columns for lstat plus age. The quadratic term, poly(lstat, degree=2)[1], has t = 13.3 and p ≈ 0: the curve is real. Do not try to interpret −179.2 and 73.0 as slopes: by default poly() builds orthogonal polynomials, combinations of lstat and lstat² rescaled so the columns are uncorrelated, which makes least squares numerically stable. With raw=True the columns would be plain lstat and lstat²: different coefficients, identical fitted values. poly() adds no intercept column of its own; MS adds one.
anova_lm(results1, results3)
Read the output. anova_lm compares nested models with the F-test (3.24). Row 0 is results1 (lstat + age, linear); row 1 is results3 (adds the quadratic term).
  • df_resid: \(n-p-1\): 503 and 502.
  • ssr: each model's RSS: 19,168.13 and 14,165.61.
  • df_diff: 1 extra coefficient; ss_diff: the drop in RSS, 5,002.52.
  • F \(=\frac{5002.52/1}{14165.61/502}=\frac{5002.52}{28.218}=177.28\), and Pr(>F) \(=7.5\times10^{-35}\).
The null hypothesis “the quadratic term is not needed” is firmly rejected. Because the models differ by one coefficient, F equals the square of that term's t: \(13.315^2=177.3\). Row 0 shows NaN (“not a number”) because there is no earlier model to compare it with.
ax = subplots(figsize=(6, 4))[1]
ax.scatter(results3.fittedvalues, results3.resid)
ax.set_xlabel('Fitted value')
ax.set_ylabel('Residual')
ax.axhline(0, c='k', ls='--');
Read the plot: compared with the linear fit, the U-shape has largely gone. For a cubic or higher fit, change degree in poly().

3.6.7 Qualitative predictors

The Carseats data: sales of child car seats (in thousands) at 400 stores, with predictors such as price, the competitor's price, local income, advertising budget and ShelveLoc, the quality of the shelf location (Bad, Medium, Good).

Carseats = load_data('Carseats')
print(Carseats['ShelveLoc'].value_counts())
Carseats.columns
Read the output: 96 Bad, 219 Medium, 85 Good shelf locations, and the 11 columns. value_counts() counts each level.
allvars = list(Carseats.columns.drop('Sales'))

final = allvars + [('Income', 'Advertising'),
                   ('Price', 'Age')]
X = MS(final).fit_transform(Carseats)
print(list(X.columns))

summarize(model.fit())
Line by line. list(...) turns the column index into an ordinary list so that + can append the two interaction tuples. MS sees that ShelveLoc, Urban and US are categorical and creates dummy variables automatically (one-hot encoding), dropping the first level of each (Bad, No, No) to avoid the dummy trap. That is why the columns include ShelveLoc[Good] and ShelveLoc[Medium] but no ShelveLoc[Bad].
Read the output:
  • ShelveLoc[Good] 4.85: compared with a bad shelf location, a good one is associated with about 4,850 more seats sold, other things equal. ShelveLoc[Medium] 1.95: medium beats bad by about 1,950 seats, but trails good.
  • Price −0.1008: each extra dollar of price, about 101 fewer seats. CompPrice 0.0929: a pricier competitor helps.
  • Income:Advertising 0.0008 (p = 0.007): advertising works a little better in richer areas. Price:Age (p = 0.42): no evidence of that interaction.
  • Urban[Yes], US[Yes], Education, Population: large p-values.

Pitfall: forgetting the baseline. “ShelveLoc[Medium] = 1.95” compares Medium with Bad, not with the average. To compare Good with Medium, subtract: \(4.85-1.95=2.90\).

Quiz

What does sm.OLS(y, X) do on its own?

  1. Fits the model and prints a summary
  2. Specifies the model; nothing is fitted until .fit()
  3. Adds an intercept column to X
OLS only stores the specification; .fit() computes the estimates. It never adds an intercept: you must include a column of ones (by hand or via MS).

Why does MS create ShelveLoc[Good] and ShelveLoc[Medium] but not ShelveLoc[Bad]?

  1. Bad has too few stores
  2. Bad is not significant
  3. Three dummies would add up to the intercept column (perfect collinearity), so the first level becomes the baseline
With an intercept, a factor with \(L\) levels needs \(L-1\) dummies. Bad is first alphabetically, so it is the baseline.

With medv \(=34.5538-0.9500\times\)lstat, what is the predicted medv at lstat = 10?

\(34.5538-9.500=25.05\) (thousand dollars).

In conf_int(obs=True, alpha=0.05), what does obs=True change?

  1. It gives a prediction interval for one new observation instead of a confidence interval for the mean
  2. It switches from 95% to 99%
  3. It removes outliers
“obs” refers to a new observation, whose interval includes the irreducible error. The level is set by alpha.

anova_lm reports RSS 19,168.13 (503 df) and 14,165.61 (502 df). Compute F.

\(F=\frac{(19168.13-14165.61)/1}{14165.61/502}=\frac{5002.52}{28.218}=177.28\).

A summary shows Durbin-Watson = 0.89. What does that suggest?

  1. Strong collinearity
  2. Positive correlation between neighbouring residuals
  3. A perfect fit
Durbin-Watson near 2 means uncorrelated errors; well below 2 means positive correlation between consecutive residuals (lesson 3.3, problem 2).

Why do the coefficients of poly('lstat', degree=2) differ from those of a model with lstat and lstat², while the fitted values are identical?

Both sets of columns span the same space of quadratic functions of lstat, so least squares finds the same best curve and the same fitted values. poly() uses orthogonal combinations of lstat and lstat² (for numerical stability), so the coefficients are weights on different basis columns and cannot be read as the slope on lstat and the coefficient on lstat².
