This lesson gives you the tools to measure that accuracy (MSE and the error rate), shows why the most flexible model is rarely the best one (the bias–variance trade-off), and introduces your first real classifier, K-nearest neighbours. Bias and variance are the single most asked-about idea in ML interviews.

Why does ISLP teach so many methods instead of one best method? Because on one data set a particular method may work best, while on a similar but different data set another one wins. So a central skill is deciding which method is best for the data in front of you. That needs a way to measure quality. This lesson builds it.

Measuring the quality of fit: the MSE

We need a number that says how close the predictions are to the true responses. In regression, the most common choice is the mean squared error: take each prediction error, square it, and average.

Mean squared error (ISLP 2.5)
\[\MSE = \frac{1}{n}\sum_{i=1}^{n}\big(y_i - \hat f(x_i)\big)^2\]

Read: “MSE equals one over n times the sum, for i from 1 to n, of (y-i minus f-hat of x-i) squared.” \(\hat f(x_i)\) is the prediction for observation \(i\); \(y_i - \hat f(x_i)\) is its error (the residual). Small MSE: predictions close to the truth. Large MSE: at least some predictions far off.

Why square the errors? Squaring makes every error positive, so a +3 and a −3 do not cancel out. It also punishes big errors much more than small ones: one error of 4 costs \(4^2 = 16\), while two errors of 2 (the same total size) cost only \(2^2 + 2^2 = 8\).

The setup cell below loads the data and defines the helpers this lesson uses: three “true” functions like the ones behind the book's Figures 2.9–2.11, a function that simulates data from \(Y = f(X) + \varepsilon\), and a polynomial fitter. np.polynomial.legendre.legvander builds the columns \(1, x, x^2, \dots\) in a numerically safer form (Legendre polynomials); you can think of it as “polynomial of degree \(d\)”.

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
ad = pd.read_csv('Advertising.csv', index_col=0)

def f_curvy(x):  return 4 + 5.5 * np.sin(np.pi * x / 130) ** 2              # like Fig 2.9
def f_linear(x): return 2.5 + 0.1 * x + 0.2 * np.sin(x / 15)                 # like Fig 2.10
def f_wiggly(x): return 12 + 13 * np.exp(-x / 12) - 22 * (x / 100) ** 6 + 2 * np.exp(-((x - 50) / 12) ** 2)  # like Fig 2.11

def simulate(f, n, rng, sigma=1.0):
    x = rng.uniform(0, 100, n)
    return x, f(x) + rng.normal(0, sigma, n)          # Y = f(X) + eps, Var(eps) = sigma^2

def fit_poly(x, y, degree):
    V = np.polynomial.legendre.legvander((x - 50) / 50, degree)
    coef, *_ = np.linalg.lstsq(V, y, rcond=None)
    return lambda z: np.polynomial.legendre.legvander((z - 50) / 50, degree) @ coef
print("ready")
fit_poly returns a function: call it on any array of \(x\) values to get predictions. A function that returns a function is normal in Python; lambda z: ... builds the returned one (see Python II).

Training MSE versus test MSE

The MSE above was computed on the same data used to fit the line. That is the training MSE. But we do not really care how well a method reproduces data it has already seen. The book's examples:

  • A model trained on six months of stock returns: nobody cares how well it “predicts” last week's price. We care about tomorrow's.
  • A diabetes-risk model trained on patients whose diagnosis we already know: we care about future patients.

What we want is accuracy on previously unseen test data \((x_0, y_0)\), observations not used to train the method. With many test observations we compute the test MSE:

Test MSE (ISLP 2.6)
\[\text{Ave}\big(y_0 - \hat f(x_0)\big)^2\]

Read: “the average, over the test observations, of (y-nought minus f-hat of x-nought) squared.” The subscript 0 marks a test point. Same recipe as (2.5), different data: data the method never saw.

We want the method with the lowest test MSE, not the lowest training MSE. If we have a test set, we just compute (2.6). If we do not, it is tempting to pick the method with the lowest training MSE. That is a trap: many methods choose their parameters precisely to make the training MSE small, so their training MSE can be tiny while their test MSE is large.

Seeing the trap: Figures 2.9–2.11

The book simulates data from \(Y = f(X) + \varepsilon\) with a known \(f\) and fits three estimates of increasing flexibility: a straight line (orange), a moderately smooth spline (blue) and a very wiggly spline (green). Flexibility is measured by degrees of freedom: roughly, the number of numbers the fit is free to choose. A straight line has 2 (intercept and slope); a polynomial of degree \(d\) has \(d+1\). The book uses smoothing splines (Chapter 7); we use polynomials, whose degree you can change with one number. The lesson is identical.

The fundamental pattern (true for every data set and every method): as flexibility increases, the training MSE decreases steadily, but the test MSE is U-shaped. Small training MSE with large test MSE is overfitting: the method has found patterns that are only random chance in this training set. Strictly, overfitting means “a less flexible model would have had a smaller test MSE”. We almost always expect training MSE to be below test MSE, overfitting or not, because methods fit the training data on purpose.

In practice we usually have no test set, so the test MSE must be estimated from the training data. The main tool is cross-validation, Chapter 5 (ISLP 5.1).

The bias–variance trade-off

Why is the test MSE U-shaped? Because two different things go wrong, and flexibility pushes them in opposite directions.

  • Variance is how much \(\hat f\) would change if we fitted it on a different training set. Different training data give a different \(\hat f\); ideally it should not move much. Flexible methods follow every point, so moving one point can change \(\hat f\) a lot: high variance. The green wiggly curve in Figure 2.9 has high variance; the orange line has low variance.
  • Bias is the error from approximating a complicated real problem with a simpler model. Linear regression assumes a straight line; if the truth curves, the line is wrong on average however much data we have. Flexible methods have low bias.
The bias–variance decomposition (ISLP 2.7)
\[\E\big(y_0 - \hat f(x_0)\big)^2 = \Var\big(\hat f(x_0)\big) + \big[\text{Bias}\big(\hat f(x_0)\big)\big]^2 + \Var(\varepsilon)\]

Read: “The expected test MSE at x-nought equals the variance of f-hat at x-nought, plus the squared bias of f-hat at x-nought, plus the variance of epsilon.” Here “expected” means averaged over many training sets (each giving its own \(\hat f\)) and over the noise in \(y_0\). The overall expected test MSE averages this over all test points \(x_0\).

SymbolSay it as / meaningTiny example
\(\E\,\hat f(x_0)\)“the expected value of f-hat at x-nought”: the average prediction at \(x_0\) over many training setsfits gave 5, 7, 6, 6: average 6
\(\text{Bias}(\hat f(x_0))\)\(\E\,\hat f(x_0) - f(x_0)\): how far the average fit is from the truth\(6 - 5 = 1\)
\(\Var(\hat f(x_0))\)\(\E\big[(\hat f(x_0) - \E\hat f(x_0))^2\big]\): how much the fit wobbles between training sets\((1+1+0+0)/4 = 0.5\)

The book says the proof is beyond its scope. It needs nothing more than the three expectation rules from ISLP 2.1, so here it is.

Derivation · why (2.7) holds
At a fixed test point \(x_0\): \(y_0 = f(x_0) + \varepsilon_0\), with \(\E\varepsilon_0 = 0\). \(\hat f\) is random because the training set is random, and the new noise \(\varepsilon_0\) is independent of the training set. Write \(m = \E\,\hat f(x_0)\) and drop the “\((x_0)\)” to save ink: \(f, \hat f\).
  1. Add and subtract \(m\) inside the error: \[y_0 - \hat f = \underbrace{(f - m)}_{B} + \underbrace{(m - \hat f)}_{D} + \varepsilon_0.\]\(B\) is a fixed number (the bias, with a minus sign); \(D\) is the random wobble of this fit around its average.
  2. Square, as \((B + D + \varepsilon_0)^2\): \[B^2 + D^2 + \varepsilon_0^2 + 2BD + 2B\varepsilon_0 + 2D\varepsilon_0.\]
  3. Take expectations term by term. \(\E B^2 = B^2\) (constant). \(\E D^2 = \E(\hat f - m)^2 = \Var(\hat f)\). \(\E\varepsilon_0^2 = \Var(\varepsilon)\).
  4. Cross terms: \(\E(2BD) = 2B\,\E(m - \hat f) = 2B(m - m) = 0\). \(\E(2B\varepsilon_0) = 2B\cdot 0 = 0\). \(\E(2D\varepsilon_0) = 2\,\E(D)\,\E(\varepsilon_0) = 0\), because \(D\) and \(\varepsilon_0\) are independent.Independent quantities: the expectation of a product is the product of expectations.
  5. Collect: \(\E(y_0 - \hat f)^2 = B^2 + \Var(\hat f) + \Var(\varepsilon)\), and \(B^2 = (f - m)^2 = (m - f)^2 = [\text{Bias}(\hat f)]^2\).
\(\E(y_0-\hat f(x_0))^2 = \Var(\hat f(x_0)) + [\text{Bias}(\hat f(x_0))]^2 + \Var(\varepsilon)\)

Every term on the right is \(\ge 0\). So the expected test MSE can never fall below \(\Var(\varepsilon)\), the irreducible error. To make the test error small we need a method with both low variance and low bias.

Worked example · bias and variance from four training sets
The truth at \(x_0\) is \(f(x_0) = 5\), and \(\Var(\varepsilon) = 1\). We fit the same method on four different training sets and get \(\hat f(x_0) = 5, 7, 6, 6\).
  1. Average fit: \(m = \frac{5 + 7 + 6 + 6}{4} = \frac{24}{4} = \mathbf{6}\).
  2. Bias: \(m - f(x_0) = 6 - 5 = 1\), so \(\text{Bias}^2 = \mathbf{1}\).
  3. Variance: deviations from \(m\) are \(-1, 1, 0, 0\); squared \(1, 1, 0, 0\); average \(\frac{2}{4} = \mathbf{0.5}\).
  4. Expected test MSE by (2.7): \(0.5 + 1 + 1 = \mathbf{2.5}\).
  5. Check directly: the squared gaps to the truth, \((\hat f - f)^2\), are \(0, 4, 1, 1\), average \(1.5\) (that is bias² + variance). The noise adds \(\Var(\varepsilon) = 1\) on top: \(2.5\). ✓
variance 0.5 + bias² 1 + irreducible 1 = 2.5
fits = np.array([5.0, 7.0, 6.0, 6.0]); f_x0 = 5.0; var_eps = 1.0
bias2 = (fits.mean() - f_x0) ** 2
var = fits.var()                       # divides by n, i.e. the average squared deviation
print("bias^2 =", bias2, " variance =", var, " expected test MSE =", bias2 + var + var_eps)
print("check: mean (fhat - f)^2 + Var(eps) =", np.mean((fits - f_x0) ** 2) + var_eps)
fits.var() divides by \(n\) (here 4), which matches the definition of variance as an average. (Your statistics lessons sometimes divide by \(n-1\) for a sample estimate; in the lab you will see the ddof argument that switches between them.)

More flexibility means the average fit can follow the true curve (bias² falls, from about 1.5 to almost 0), but each individual fit follows its own training noise more (variance rises, slowly at first and then explosively). The test MSE is their sum plus 1.

Darts. Bias is how far the centre of your cluster of darts is from the bullseye. Variance is how spread out the cluster is. A simple model throws a tight cluster in the wrong place; a very flexible model throws a cluster centred on the bullseye but scattered all over the board. You want a tight cluster on the bullseye.

You have met this in estimation theory. For any estimator \(\hat\theta\) of a parameter \(\theta\) (a channel gain, a frequency offset), \(\E(\hat\theta - \theta)^2 = \Var(\hat\theta) + \text{Bias}(\hat\theta)^2\). An unbiased estimator is not automatically best: a slightly biased one with much smaller variance can have smaller mean squared error. (2.7) is the same identity applied to the function value \(\hat f(x_0)\), plus the noise in the new measurement.

It is called a trade-off because getting one of the two small is easy: a curve through every training point has extremely low bias but huge variance; a horizontal line has zero variance but huge bias. The challenge is a method where both are low. In real life \(f\) is unknown, so we cannot compute bias and variance; but the trade-off still guides every choice. If the true \(f\) is linear, linear regression has no bias and is very hard to beat; if \(f\) is very non-linear and we have plenty of data, a flexible method can win (Figure 2.11).

Interview classic: “Explain the bias–variance trade-off.” Say the formula (2.7), define both terms in one sentence each, say which way each moves with flexibility, sketch the U-shaped test error, and give a fix for each side: high variance → simpler model, more data, regularisation (ridge/lasso, Chapter 6); high bias → more flexible model or better features.

The classification setting: the error rate

When the response is qualitative, squared error makes no sense (“blue minus orange”?). Instead we count mistakes. The training error rate is the fraction of training observations classified wrongly:

Training error rate (ISLP 2.8)
\[\frac{1}{n}\sum_{i=1}^{n} I(y_i \ne \hat y_i)\]

Read: “one over n times the sum of I of y-i not-equal-to y-i-hat.” \(\hat y_i\) is the predicted class. \(I(\cdot)\) is an indicator variable: it equals 1 when the statement inside is true (a mistake) and 0 when it is false (correct). Adding up the 1s counts the mistakes; dividing by \(n\) gives the fraction.

The test error rate is the same thing on test observations: \(\text{Ave}\big(I(y_0 \ne \hat y_0)\big)\) (ISLP 2.9). A good classifier is one whose test error rate is small.

Worked example · an error rate by hand
True classes \(y = (A, A, B, B, A, B, A, B)\), predictions \(\hat y = (A, B, B, B, A, A, A, B)\).
  1. Compare position by position: \(I(y_i \ne \hat y_i) = 0, \mathbf{1}, 0, 0, 0, \mathbf{1}, 0, 0\).Positions 2 and 6 disagree.
  2. Sum: \(2\). Divide by \(n = 8\): \(2/8 = \mathbf{0.25}\).
error rate = 0.25 (25% of the observations are misclassified); accuracy = 0.75
y_true = np.array(['A', 'A', 'B', 'B', 'A', 'B', 'A', 'B'])
y_hat  = np.array(['A', 'B', 'B', 'B', 'A', 'A', 'A', 'B'])
mistakes = (y_true != y_hat)          # a Boolean array: True where they differ
print(mistakes.astype(int))           # the indicator I(y != yhat) as 0/1
print("error rate:", mistakes.mean())
Comparing two arrays with != gives an array of True/False. NumPy treats True as 1 and False as 0, so .mean() of a Boolean array is the fraction of Trues: exactly (2.8).

The Bayes classifier and the Bayes error rate

Which classifier has the smallest possible test error rate? One can prove (the book skips the proof) that it is the classifier that assigns each observation to its most likely class, given its predictor values:

The Bayes classifier (ISLP 2.10)
\[\text{assign } x_0 \text{ to the class } j \text{ for which } \Pr(Y = j \mid X = x_0) \text{ is largest}\]

Read: “the probability that Y equals j, given that X equals x-nought.” The bar \(\mid\) means “given”. This is a conditional probability (see Probability). With two classes, the Bayes classifier predicts class 1 if \(\Pr(Y = 1 \mid X = x_0) > 0.5\), and class 2 otherwise.

Figure 2.13 shows a simulated two-class problem in two dimensions. Because the data are simulated, the true conditional probabilities are known everywhere. The orange background marks where \(\Pr(Y = \text{orange} \mid X) > 50\%\), the blue background where it is below. The purple dashed line, where the probability is exactly 50%, is the Bayes decision boundary.

At a point \(x_0\), the Bayes classifier picks the class with probability \(\max_j \Pr(Y = j \mid X = x_0)\), so it is wrong with probability \(1 - \max_j \Pr(Y = j \mid X = x_0)\). Averaging over all \(x\):

Bayes error rate (ISLP 2.11)
\[1 - \E\Big(\max_j \Pr(Y = j \mid X)\Big)\]

Read: “one minus the expected value of the largest class probability.” \(\max_j\) means “the largest over the classes \(j\)”. The expectation averages over the values of \(X\). This is the Bayes error rate, the lowest test error rate any classifier can achieve: the classification version of the irreducible error.

Worked example · a Bayes error rate you can compute by hand
\(X\) takes only three values: \(a\) (probability 0.5), \(b\) (0.3), \(c\) (0.2). The chance of orange at each: \(\Pr(\text{orange}\mid a) = 0.9\), \(\Pr(\text{orange}\mid b) = 0.5\), \(\Pr(\text{orange}\mid c) = 0.2\).
  1. Bayes decisions: at \(a\), orange (0.9 > 0.5); at \(b\), a tie (either class, error 0.5 regardless); at \(c\), blue (\(\Pr(\text{blue}\mid c) = 0.8\)).
  2. Largest class probability at each value: \(0.9,\ 0.5,\ 0.8\).
  3. Average over \(X\): \(\E\max = 0.5 \times 0.9 + 0.3 \times 0.5 + 0.2 \times 0.8 = 0.45 + 0.15 + 0.16 = \mathbf{0.76}\).
  4. Bayes error rate: \(1 - 0.76 = \mathbf{0.24}\).Even knowing the true probabilities, we are wrong 24% of the time, because at each \(x\) the less likely class still happens sometimes.
Bayes error rate = 0.24

For the book's simulated data the Bayes error rate is about 0.13 (the text quotes 0.133 on p. 36 and 0.1304 on p. 37). It is above zero because the classes overlap in the population, so \(\max_j \Pr(Y = j \mid X = x_0) < 1\) for some \(x_0\).

This is binary detection. Suppose class 0 gives \(X \sim N(0, 1)\) and class 1 gives \(X \sim N(2, 1)\), equally likely. That is on–off keying with amplitude 2 in unit-variance Gaussian noise. The Bayes classifier is the maximum a posteriori detector: threshold at the midpoint, 1. Its error is \(Q(d/2\sigma) = Q(1) \approx 0.1587\), the familiar \(Q\)-function. The next cell checks it.

from scipy.stats import norm

Three routes to the same number, about 0.159: counting the Bayes classifier's mistakes, averaging \(1 - \max_j\Pr(Y = j\mid X)\) as in (2.11), and the closed form \(\Phi(-1)\). norm.pdf is the normal density; the probability of class 1 given \(x\) is its density divided by the sum of both (Bayes' rule with equal priors).

K-nearest neighbours

For real data we do not know \(\Pr(Y \mid X)\), so the Bayes classifier is an unattainable gold standard. Many methods estimate \(\Pr(Y \mid X)\) from the data and then pick the most probable class. The simplest is K-nearest neighbours (KNN). Given a positive integer \(K\) and a test point \(x_0\):

  1. find the \(K\) training points closest to \(x_0\); call this set \(\mathcal{N}_0\) (read “N-nought”, the neighbourhood);
  2. estimate the probability of each class as the fraction of those neighbours in that class;
  3. predict the class with the largest estimated probability (a majority vote).
KNN estimate of the class probability (ISLP 2.12)
\[\Pr(Y = j \mid X = x_0) = \frac{1}{K}\sum_{i \in \mathcal{N}_0} I(y_i = j)\]

Read: “the probability that Y is j, given X is x-nought, is one over K times the number of neighbours in \(\mathcal{N}_0\) whose class is j.” The sum over \(i \in \mathcal{N}_0\) (“i in N-nought”) runs over the \(K\) neighbours only. Example: \(K = 3\) neighbours with classes blue, blue, orange give \(\Pr(\text{blue}) = 2/3\), \(\Pr(\text{orange}) = 1/3\).

“Closest” means the ordinary Euclidean distance: for two points \(a = (a_1, a_2)\) and \(b = (b_1, b_2)\), \(\|a - b\| = \sqrt{(a_1-b_1)^2 + (a_2-b_2)^2}\), the straight-line distance (with \(p\) predictors, sum \(p\) squares).

KNN on the book's kind of data: the effect of \(K\)

KNN is very simple, yet it can come surprisingly close to the Bayes classifier. In the book, KNN with \(K = 10\) has test error rate 0.1363 against the Bayes error rate 0.1304 (Figure 2.15). The choice of \(K\) matters enormously:

  • \(K = 1\): the boundary is extremely flexible. It wraps around individual points and finds patterns that are not in the Bayes boundary. Low bias, very high variance. The training error is exactly 0 (every training point is its own nearest neighbour), but the test error is high (0.1695 in the book).
  • \(K = 100\): the boundary becomes nearly straight. Low variance, high bias. Test error 0.1925 in the book.
  • Somewhere in between (about \(K = 10\) in the book) the test error is smallest.

We now simulate data of the same kind as the book's (two classes, each a mixture of 10 small Gaussian blobs, like the example in the book's big sibling, ESL), so we also know the true probabilities and the Bayes error rate.

rng = np.random.default_rng(2)
centres = {0: rng.normal([1, 0], 1, (10, 2)), 1: rng.normal([0, 1], 1, (10, 2))}   # 0 = blue, 1 = orange
def sample_mix(n):
    y = np.repeat([0, 1], n // 2)
    X = np.array([centres[c][rng.integers(10)] + rng.normal(0, np.sqrt(0.2), 2) for c in y])
    return X, y
def p_orange(X):                       # the TRUE Pr(Y = orange | X), known because we simulated
    dens = lambda C: np.exp(-((X[:, None, :] - C[None]) ** 2).sum(axis=2) / (2 * 0.2)).mean(axis=1)
    a, b = dens(centres[1]), dens(centres[0])
    return a / (a + b)
X_tr, y_tr = sample_mix(200); X_te, y_te = sample_mix(5000)
pt = p_orange(X_te)
print("Bayes error rate (2.11), estimated:", np.mean(1 - np.maximum(pt, 1 - pt)).round(4))
print("Bayes classifier test error      :", np.mean((pt > 0.5) != y_te).round(4))
Our simulated world has a Bayes error rate of about 0.10 (the book's world: 0.13). No classifier can beat it on average. X[:, None, :] - C[None] uses broadcasting (see NumPy II) to subtract every centre from every point at once.

Why can the expected test MSE never be below \(\Var(\varepsilon)\)?

  1. Because the other two terms in (2.7), variance and squared bias, are never negative
  2. Because training MSE is always smaller than test MSE
  3. Because \(\varepsilon\) has mean zero
\(\Var(\hat f) \ge 0\) and \(\text{Bias}^2 \ge 0\), so their sum with \(\Var(\varepsilon)\) is at least \(\Var(\varepsilon)\).

It predicts orange (0.8 > 0.5) and is wrong when the true class is blue: \(1 - 0.8 = 0.2\).

A colleague picks the polynomial degree that gives the lowest training MSE. Explain to them, using bias and variance, why this is a mistake and what they should do instead.

Training MSE always falls as degree rises, so they will always pick the most flexible model. That model has low bias but high variance: it fits the noise of this particular training set, so its predictions on new data swing widely and its test MSE is high. Test MSE = variance + bias² + Var(ε) is minimised at an intermediate flexibility. They should estimate test error on data not used for fitting: a held-out test set or cross-validation (Chapter 5), and pick the degree with the lowest estimated test error.
MSE (ISLP 2.5)
\(\frac{1}{n}\sum_{i=1}^n (y_i - \hat f(x_i))^2\)
Training MSE vs test MSE
Same formula; training MSE uses the data the model was fitted on, test MSE uses previously unseen observations. We care about test MSE.
Shape of training and test MSE as flexibility rises
Training MSE decreases monotonically; test MSE is U-shaped.
Definition of overfitting (ISLP)
A method has small training MSE but large test MSE, and a less flexible method would have given a smaller test MSE.
Bias–variance decomposition (2.7)
\(\E(y_0-\hat f(x_0))^2 = \Var(\hat f(x_0)) + [\text{Bias}(\hat f(x_0))]^2 + \Var(\varepsilon)\)
Variance of a method
How much \(\hat f\) would change if fitted on a different training set. Rises with flexibility.
Bias of a method
Error from approximating a complicated truth by a simpler model: \(\E\hat f(x_0) - f(x_0)\). Falls with flexibility.
Error rate (2.8)
\(\frac{1}{n}\sum_i I(y_i \ne \hat y_i)\): the fraction misclassified.
Bayes classifier (2.10)
Assign \(x_0\) to the class \(j\) with the largest \(\Pr(Y=j\mid X=x_0)\). Lowest possible test error rate.
Bayes error rate (2.11)
\(1 - \E\big(\max_j \Pr(Y=j\mid X)\big)\); the classification analogue of irreducible error.
KNN probability estimate (2.12)
\(\Pr(Y=j\mid X=x_0) = \frac{1}{K}\sum_{i\in\mathcal N_0} I(y_i=j)\): the fraction of the \(K\) nearest neighbours in class \(j\).
KNN: small K vs large K
Small \(K\): flexible, low bias, high variance (K=1 has zero training error). Large \(K\): smooth, nearly linear boundary, low variance, high bias.
Why use odd K with two classes?
To avoid tied votes.
