Every dataset in machine learning ends up as a grid of numbers, and every model is arithmetic on those grids. NumPy is the Python library that stores such grids compactly and does maths on a whole grid in one line, at C speed. Every later lesson, every ISLP lab and every PyTorch tensor builds directly on what you learn here.

You'll use Python I (lists, indexing from 0) · Python II (loops, functions)

By the end of this lesson you can

  • explain why an array is faster and more convenient than a list for numbers, and time the difference yourself;
  • create arrays (from lists, zeros, ones, arange, linspace, eye, full) and read their dtype, shape, ndim and size;
  • pick out any element, row, column, block or pattern of a 1-D or 2-D array with integer indices, slices, lists and boolean masks, and say the shape of the result before you run it;
  • do arithmetic on whole arrays, and reduce them with sum, mean, std, min, max, argmax along a chosen axis;
  • reshape, transpose, flatten and stack arrays, and avoid the copy-versus-view trap that ISLP warns about.
In numpy, an array is a generic term for a multidimensional set of numbers.

1. Why not just use lists?

You already know Python lists. A list can hold numbers, so why do we need anything else? Let us try the most natural thing you would want to do with two lists of numbers: add them, element by element. This is exactly the experiment ISLP runs at the start of its lab.

Two lists, x = [3, 4, 5] and y = [4, 9, 7]. What does x + y give?

  1. [7, 13, 12]
  2. An error
  3. [3, 4, 5, 4, 9, 7]
For lists, + means join together (concatenate), just as "hello" + "world" joins two strings. Python lists can hold anything (numbers, text, other lists), so Python cannot assume you want arithmetic. The tempting answer [7, 13, 12] is what a mathematician means by adding two vectors, and it is what NumPy will give us.
x = [3, 4, 5]
y = [4, 9, 7]
x + y
Read the output: six numbers, the second list glued after the first. To add element by element with lists you would need a loop: [a + b for a, b in zip(x, y)]. That works, but it is wordy and, as you will see in a moment, slow.

Importing NumPy

NumPy is not part of plain Python. It is a package: a bundle of extra code that someone else wrote, which you switch on with import. Everybody in the world writes it the same way:

import numpy as np    # load NumPy and give it the short nickname np

x = np.array([3, 4, 5])
y = np.array([4, 9, 7])
x + y
Read the output: array([ 7, 13, 12]). Now + adds element by element: 3+4, 4+9, 5+7. The words as np mean “from now on, call this package np”, so np.array means “the function array that lives inside NumPy”. If you forget the import line you get a NameError saying that np is not defined.

You already think in arrays. In DSP a signal is a sequence of samples \(x[n]\), and you write \(y[n]=2x[n]+1\) to mean “do this for every \(n\)”. You never write a loop on paper. A NumPy array is exactly a sampled signal held in memory, and y = 2*x + 1 is exactly that equation. Working on a whole array at once is called vectorisation; it is the software version of processing a whole buffer of samples at once instead of handling one sample per interrupt.

How much faster? Time it yourself

Under the hood a list stores pointers to separate Python number objects scattered around memory, and the loop runs in slow, general-purpose Python. An array stores the raw numbers side by side in one block of memory, all of the same type, and the loop over them runs inside NumPy's compiled C code. Let us measure it. The standard module timeit is a stopwatch for code: timeit.repeat(f, number=1, repeat=5) runs the function f five times and returns the five durations in seconds. We keep the shortest, because the slower runs were only disturbed by other programs on your computer.

We compute \(2v+1\) for a million numbers, once with a Python loop and once with NumPy. Roughly how many times faster will NumPy be?

  1. About the same speed
  2. Around 10 to 100 times faster
  3. A million times faster
Typically 10 to 100 times, depending on the machine (the in-browser Python differs again). Not a million: NumPy still has to touch every number once. What it removes is the overhead Python pays for each element: looking up types, creating a new number object, running the interpreter loop.
import timeit

n = 1_000_000                 # underscores just make big numbers readable
data_list = list(range(n))
data_arr = np.arange(n)       # the array 0, 1, 2, ..., n-1 (explained below)

def with_list():
    return [2 * v + 1 for v in data_list]    # one element at a time

def with_numpy():
    return 2 * data_arr + 1                  # the whole array at once

# run each 5 times and keep the fastest run (the least disturbed by other programs)
t_list = min(timeit.repeat(with_list, number=1, repeat=5))
t_arr = min(timeit.repeat(with_numpy, number=1, repeat=5))
print(f"list loop : {t_list*1000:7.1f} ms")
print(f"NumPy     : {t_arr*1000:7.1f} ms")
print(f"speed-up  : about {t_list / t_arr:.0f}x")
print("same answers?", with_list()[:5], with_numpy()[:5])
Read the output: the exact times change on every run, but NumPy wins by a large factor (around 20× here; it varies by machine and is different again in the browser). In ML you will process millions of numbers thousands of times, so this factor is the difference between a model training in a minute and in an hour. Run the cell twice: the timings wobble, the conclusion does not.

The rule for the rest of this guide: if you are about to write a for loop over the numbers in an array, stop and ask “can NumPy do this on the whole array at once?” Almost always it can, and the result is shorter, clearer and faster.

2. Making an array and asking it about itself

np.array(...) turns a list (or a list of lists) into an array. Every array carries four facts about itself, called attributes, which you read with a dot and no brackets:

M = np.array([[1, 2, 3],
              [4, 5, 6]])     # a list of rows becomes a 2-D array
print(M)
print("dtype:", M.dtype)
print("shape:", M.shape)
print("ndim: ", M.ndim)
print("size: ", M.size)
Read the output: print(M) shows the numbers as a grid, row by row. Shape (2, 3) is read “two by three”: 2 rows, 3 columns, always rows first. Size is \(2\times3=6\).
New in this lesson · tuples

The shape (2, 3) is written with round brackets. That is a tuple: a sequence like a list, but it cannot be changed after it is made. You index it like a list: M.shape[0] is the number of rows (2) and M.shape[1] the number of columns (3). A tuple with one element needs a trailing comma: (5,). You will see (5,) as the shape of every 1-D array of length 5. ISLP shows that a tuple refuses changes:

my_tuple = (3, 4, 5)
my_tuple[0] = 2      # not allowed: tuples are read-only
This error is on purpose. Tuples are used for things that should not change by accident, like the shape of an array. A list would accept my_list[0] = 2 happily.

The dtype: every element has the same type

A list may mix numbers and text. An array may not: NumPy picks one type for all elements, the simplest one that can hold everything you gave it. All whole numbers give int64. A single decimal anywhere makes the whole array float64, because a float can hold an integer but not the other way round. This promotion is called upcasting.

What is np.array([[1, 2], [3.0, 4]]).dtype? (Look closely at the 3.)

  1. int64, because most of the numbers are whole
  2. float64
  3. It raises an error because the types are mixed
3.0 is a float. One float is enough: NumPy upcasts the whole array to float64, and prints the numbers with a dot (1., 2.…). This is ISLP's In[13]. No error, because a float can represent 1, 2 and 4 exactly.
a = np.array([[1, 2], [3.0, 4]])
print(a.dtype)
print(a)
b = np.array([[1, 2], [3, 4]], float)      # ask for floats (ISLP In[15])
print(b.dtype)
c = np.array([1, 2, 3], dtype=np.float32)  # half the memory of float64
print(c.dtype, c.itemsize, "bytes per element")
Read the output: the dots in [[1. 2.] [3. 4.]] are NumPy's way of saying “these are floats”. itemsize is bytes per element: float32 uses 4, float64 uses 8. Deep learning (PyTorch's default) uses float32 to halve memory; classical statistics uses float64.

Attributes versus methods

Some things you ask an array are facts it already knows (attributes, no brackets: x.shape). Others are jobs it does for you (methods, with brackets: x.sum()). A method is just a function attached to the object, so x.sum() and np.sum(x) do the same thing. ISLP uses both styles.

x = np.array([1, 2, 3, 4])
print(x.sum(), np.sum(x))      # the method and the function agree
x.sum()                         # shown as the cell's last value
Read the output: print shows 10 10, but the bare last line shows np.int64(10). This is NumPy 2 being honest about the type: it is the number 10, stored as a NumPy 64-bit integer. You can use it exactly like 10. (ISLP was printed with an older NumPy that just showed 10.)

Brackets matter. x.shape() fails with a TypeError (“'tuple' object is not callable”), because shape is a fact, not a job. And x.sum without brackets does not add anything: it shows you the method itself. When in doubt: attributes are nouns (shape, dtype, T), methods are verbs (sum, reshape, copy).

3. One dimension, two dimensions: vectors and matrices

A 1-D array is a row of numbers with one index: a vector, a signal, one column of a dataset. A 2-D array is a grid with two indices: a matrix, a greyscale image, a whole dataset with one row per observation and one column per variable. The first index always picks the row, the second the column, and both count from 0.

Here is ISLP's 4 × 4 example matrix, A = np.arange(16).reshape((4, 4)), with its row numbers down the left and column numbers along the top. The highlighted cell is A[1, 2]: row 1 (the second row), column 2 (the third column).

012300123145672891011312131415A[1, 2] → 6
Element of a matrix, maths versus NumPy
\[a_{ij}\ \text{(maths, counting from 1)} \;=\; \texttt{A[i-1, j-1]}\ \text{(NumPy, counting from 0)}\]

Read: “a sub i j”, the entry in row \(i\), column \(j\). Books count from 1, NumPy counts from 0, so the book's \(a_{23}\) (row 2, column 3) is A[1, 2], which is 6 here.

The words axis 0 and axis 1 name the two directions. Axis 0 runs down the rows (its length is the number of rows, A.shape[0]); axis 1 runs across the columns (A.shape[1]). Keep this picture; it is the key to section 10 on reductions.

A dataset is a matrix. In ISLP, the data matrix \(\bX\) (read “bold X”) has \(n\) rows, one per observation (a car, a patient, a day), and \(p\) columns, one per variable (horsepower, weight…). Its shape is (n, p). Row X[i] is everything we know about observation \(i\); column X[:, j] is variable \(j\) for everybody.

Three different “vectors”

Shapes (3,), (1, 3) and (3, 1) all hold three numbers, but they are different objects. (3,) is a plain 1-D array with no notion of row or column. (1, 3) is a 2-D array with one row (a row vector); (3, 1) is a 2-D array with one column (a column vector). This distinction will matter a lot for broadcasting in NumPy II.

789shape (3,)789shape (1, 3)789shape (3, 1)
v = np.array([7, 8, 9])
r = np.array([[7, 8, 9]])        # one row: note the double brackets
c = np.array([[7], [8], [9]])    # three rows of one element each
print(v.shape, r.shape, c.shape)
print(v.ndim, r.ndim, c.ndim)
Read the output: the number of square brackets at the start tells you ndim: one bracket for 1-D, two for 2-D.

More than two dimensions

Arrays can have any number of axes. A colour photo is a 3-D array of shape (height, width, 3): for every pixel, three numbers (red, green, blue). A batch of 32 such photos is 4-D, (32, height, width, 3). Everything in this lesson works the same way with more axes; we stay in 1-D and 2-D because those are what ISLP uses.

img = np.zeros((4, 6, 3))     # a tiny 4x6 colour image, all black
print(img.shape, img.ndim, img.size)
img[0, 0] = [1.0, 0.0, 0.0]   # make the top-left pixel pure red
print(img[0, 0])
Read the output: 4 × 6 × 3 = 72 numbers. img[0, 0] gives the three colour values of the top-left pixel, now red = 1, green = 0, blue = 0.

ISLP runs np.linspace(0, 10, 11) and np.arange(0, 10). Which statement is right?

  1. linspace gives 0, 1, …, 10 (eleven floats); arange gives 0, 1, …, 9 (ten integers)
  2. Both give 0 to 10
  3. Both give 0 to 9
linspace(a, b, n) gives exactly n evenly spaced points including both ends, so 11 points from 0 to 10, spacing 1. arange(a, b) follows Python's slice rule: start at a, stop before b. Same rule as range(0, 10) from Python II.
seq1 = np.linspace(0, 10, 11)
seq2 = np.arange(0, 10)
print(seq1)
print(seq2)
print(np.zeros((2, 3)))
print(np.eye(3))
print(np.full((2, 2), 7))
print(np.arange(5, 0, -1))       # counting down: the stop, 0, is excluded
Read the output: the floats from linspace, zeros and eye print with dots; arange and full with whole numbers give integers. The last line counts down 5, 4, 3, 2, 1 and stops before 0.

A time axis. To sample one second of a signal at \(f_s = 8\) Hz you want \(t = 0, \tfrac18, \tfrac28, \dots, \tfrac78\): eight samples, and not \(t=1\) (that is the first sample of the next second). Two equivalent ways: np.arange(8) / 8 or np.linspace(0, 1, 8, endpoint=False). Plain np.linspace(0, 1, 8) would include 1 and space the points by \(1/7\): a classic off-by-one.

fs = 8                                   # sampling frequency in Hz
t = np.arange(fs) / fs                   # 0, 1/8, ..., 7/8 seconds
x = np.sin(2 * np.pi * 1 * t)            # one cycle of a 1 Hz sine
print(t)
print(np.round(x, 3))                    # round to 3 decimals for reading
Read the output: np.sin worked on all eight times at once. np.round(x, 3) only tidies the display. The values go 0, 0.707, 1, 0.707, 0, −0.707, −1, −0.707: one full cycle.

5. Indexing and slicing a 1-D array

Indexing a 1-D array works exactly like a list. x[0] is the first element, x[-1] the last, x[-2] the second to last. A slice x[start:stop:step] takes elements from start up to but not including stop, jumping step at a time. Any of the three can be left out: start defaults to the beginning, stop to the end, step to 1.

Take x = np.arange(10, 20), the numbers 10 to 19. The faint top row of each picture shows the position (index), the boxes show the values; the highlighted cells are what the slice picks.

012345678910111213141516171819x[2:5] → [12 13 14]
012345678910111213141516171819x[::3] → [10 13 16 19]
012345678910111213141516171819x[-3:] → [17 18 19]
Worked example · reading a slice with a negative step
\(x\) = np.arange(10, 20). What is x[7:2:-2]?
  1. Start at index 7: value 17.The start is always included.
  2. The step is −2, so move left by 2: index 5, value 15.
  3. Left by 2 again: index 3, value 13.
  4. Next would be index 1. But we must stop before reaching index 2 (the stop), and 1 is already past it, so we stop.With a negative step, “before the stop” means “still to the right of it”.
x[7:2:-2] → array([17, 15, 13])

The single most useful negative step is x[::-1]: start at the end, go left one at a time, all the way. It reverses the array (time reversal, \(x[-n]\), in DSP language).

With x = np.arange(10, 20), what does x[-4:-1] give?

  1. [16 17 18 19]
  2. [19 18 17]
  3. [16 17 18]
−4 means “4 from the end”, which is index 6 (value 16). −1 is index 9 (value 19), and the stop is excluded, so we get indices 6, 7, 8: values 16, 17, 18. Option 1 forgot that the stop is excluded; option 2 went backwards, which only happens with a negative step.
x = np.arange(10, 20)
print(x[0], x[-1])        # first and last
print(x[2:5])             # positions 2, 3, 4
print(x[::3])             # every third element
print(x[-4:-1])
print(x[7:2:-2])
print(x[::-1])            # reversed
Read the output: each line matches a picture or the worked example above. Change x[::3] to x[1::3] and predict the result before running (13 is no longer there; 11, 14, 17 are).
Why is the stop excluded?

ISLP asks this too (p. 51, with "hello world"[3:6] giving 'lo '). Excluding the stop makes lengths easy: x[a:b] has exactly b - a elements, x[:k] is the first k elements and x[k:] is everything else, with no overlap and no gap. Inside square brackets, 3:6 is shorthand for the object slice(3, 6).

You can also assign to an index or a slice, and the array changes in place:

x = np.arange(10, 20)
x[0] = 99            # change one element
x[-3:] = 0           # one number fills the whole slice
print(x)
x[1:4] = [-1, -2, -3]   # or give exactly as many values as the slice has
print(x)
Read the output: first [99 11 12 13 14 15 16 0 0 0], then positions 1–3 replaced by −1, −2, −3. Giving the wrong number of values (say two values for a slice of three) raises a ValueError.

6. Indexing and slicing a 2-D array

For a 2-D array you put two indices inside one pair of brackets, separated by a comma: A[rows, columns]. Each part can be a single integer or a slice. A lone colon : means “all of them”. Here are the patterns you will use every day, on ISLP's 4 × 4 matrix A:

A[0:2, 1:3]rows 0–1, columns 1–2: a block0123456789101112131415(2, 2)
A[1:4:2, 0:3:2]rows 1 and 3, columns 0 and 2 (ISLP In[65])0123456789101112131415(2, 2)

The shape rule. Each integer index removes that axis from the result; each slice keeps it (possibly shorter). So A[1, :] (integer, slice) is 1-D of shape (4,), but A[1:2, :] (slice, slice) is 2-D of shape (1, 4): the same four numbers, kept as a one-row matrix.

What is A[1:3, 2:] for ISLP's A = np.arange(16).reshape(4, 4)?

  1. [[6, 7], [10, 11], [14, 15]]
  2. [[6, 7], [10, 11]]
  3. [[5, 6], [9, 10]]
Rows 1:3 are rows 1 and 2 (3 is excluded). Columns 2: are columns 2 and 3 (to the end). Row 1 is 4 5 6 7, so columns 2–3 give 6 7; row 2 gives 10 11. Option 1 included row 3; option 3 started at column 1.

Read the output: notice that a column, A[:, 2], prints sideways as [ 2 6 10 14]. It is 1-D, and a 1-D array has no “up–down”, so NumPy prints it in a line. If you want it as a real column, use A[:, 2:3] (shape (4, 1)).

7. Fancy indexing: picking with lists

Slices pick evenly spaced elements. To pick an arbitrary set, pass a list of indices. This is called fancy indexing (or integer-array indexing). ISLP uses it straight away:

0123456789101112131415A[[1, 3]]: rows 1 and 30123456789101112131415A[:, [0, 2]]: columns 0 and 2

But be careful when you give a list for both rows and columns. NumPy does not make a submatrix; it pairs the lists up, element by element, and picks single cells: A[[1, 3], [0, 2]] means “cell (1, 0) and cell (3, 2)”.

0123456789101112131415A[[1, 3], [0, 2]] → [4, 14]

What does A[[1, 3], [0, 2]] return?

  1. array([ 4, 14])
  2. array([[ 4, 6], [12, 14]])
  3. An error
The two lists are zipped into pairs (1, 0) and (3, 2), giving A[1, 0] = 4 and A[3, 2] = 14. ISLP says “Oops — what happened?” at exactly this point (In[60]). The 2 × 2 block in option 2 is what you probably wanted; the next cell shows three ways to get it.
print(A[[1, 3]])              # rows 1 and 3
print(A[:, [0, 2]])           # columns 0 and 2
print(A[[1, 3], [0, 2]])      # PAIRS: A[1,0] and A[3,2]
# three ways to get the 2x2 submatrix of rows 1,3 and columns 0,2:
print(A[[1, 3]][:, [0, 2]])   # rows first, then columns of the result
print(A[np.ix_([1, 3], [0, 2])])   # np.ix_ builds a "mesh" of rows x columns
print(A[1:4:2, 0:3:2])        # slices, when the pattern is regular
Read the output: the third line is the 1-D pair result [ 4 14]; the last three all print the same block [[ 4 6] [12 14]]. np.ix_ is the clearest when the rows and columns you want are not evenly spaced.

Because the lists are paired, they must have the same length. ISLP shows the error you get otherwise:

A[[1, 3], [0, 2, 3]]     # 2 row indices but 3 column indices: cannot pair them
The fix, if you wanted the submatrix of rows 1, 3 and columns 0, 2, 3: A[np.ix_([1, 3], [0, 2, 3])].

Fancy indexing can also repeat and reorder: x[[2, 0, 0]] picks element 2, then element 0 twice. This is how you will shuffle a dataset and draw bootstrap samples in later chapters.

8. Boolean masks: picking by a condition

Comparisons work elementwise too. x > 0 does not give one True or False; it gives an array of them, one per element. Such an array of True/False is called a boolean mask. Put a mask inside the brackets and you get exactly the elements where the mask is True.

3-14-15-92x→TFTFTFTx > 0 (T = True, F = False)→3452x[x > 0]
x = np.array([3, -1, 4, -1, 5, -9, 2])
mask = x > 0
print(mask)
print(x[mask])          # keep only the positive values
print(x[x > 0])        # the same, in one line
print(mask.sum(), "positives out of", x.size)   # True counts as 1
print(mask.mean())      # so the mean is the FRACTION that are True
Read the output: mask.sum() counts the Trues (True is 1, False is 0), and mask.mean() is the fraction of Trues, here 4/7 ≈ 0.571. You will use this trick constantly: “what fraction of predictions were correct?” is (y_pred == y_true).mean().

Combining conditions: &, |, ~ and brackets

To combine masks, use & (and), | (or), ~ (not). Python's words and/or/not do not work on arrays. Each condition must be in its own round brackets, because & binds more tightly than >.

x = np.array([3, -1, 4, -1, 5, -9, 2])
print(x[(x > 0) & (x < 5)])     # strictly between 0 and 5
print(x[(x < -5) | (x > 4)])    # very negative OR big
print(x[~(x > 0)])              # NOT positive
print(np.any(x < -5), np.all(x != 0))   # is any element < -5? are all non-zero?
Read the output: [3 4 2], then [ 5 -9], then [-1 -1 -9], then True True. np.any asks “is at least one True?”, np.all asks “are all True?”.
x[(x > 0) and (x < 5)]   # 'and' wants ONE True/False, but gets 7 of them
“The truth value of an array with more than one element is ambiguous”: Python's and asks “is this whole array True?”, which has no clear answer. Use &. Forgetting the brackets, x > 0 & x < 5, gives the same error, because Python reads it as x > (0 & x) < 5.

Changing values with a mask

A mask on the left of = changes only the selected elements. Setting negatives to zero is exactly the ReLU function of deep learning, and half-wave rectification in electronics:

z = np.array([3., -1., 4., -1., 5., -9., 2.])
z[z < 0] = 0          # rectify: every negative becomes 0 (changes z itself)
print(z)
print(np.where(x > 0, x, 0))     # np.where(condition, if_true, if_false): a NEW array
Read the output: both lines show the rectified signal. The difference: the first changed z in place, while np.where built a new array and left x untouched.

Booleans versus 0/1 integers: not the same index

ISLP (In[66]–[70]) makes an important point. A boolean array and an integer array of 0s and 1s are equal according to ==, but they index differently: booleans say “keep / don't keep” for each row, integers are row numbers.

print(A[keep_rows])                # booleans mean rows 1 and 3

Read the output: the integer version returns four rows (row 0 twice, row 1 twice); the boolean version returns two rows. The last line is ISLP's In[71]: rows 1, 3 and columns 0, 2, 3.

When the maths goes wrong: inf and nan

NumPy does not stop when you divide by zero. It prints a warning and gives inf (infinity) or nan (“not a number”, for things like 0/0). nan is also how missing data is stored, as you will see in pandas. Any arithmetic with nan gives nan, and nan == nan is False, so test for it with np.isnan.

What np.var and np.std compute
\[\texttt{var}(x)=\frac{1}{n}\sum_{i=1}^{n}(x_i-\bar x)^2,\qquad \texttt{std}(x)=\sqrt{\texttt{var}(x)}\]

Read: the variance is the average squared distance of each value from the mean \(\bar x\) (“x-bar”); the standard deviation is its square root, so it is back in the data's units. 11. Changing shape: reshape, transpose, flatten, stack

reshape and row-major order

x.reshape((2, 3)) gives the same numbers arranged in a new shape. NumPy reads the elements in order and fills the new shape row by row: the first row first, then the second. This is called row-major order (ISLP p. 44). The total size must stay the same: 6 elements can be (2, 3), (3, 2), (6, 1) or (1, 6), never (4, 2).

123456x, shape (6,)→123456x.reshape((2, 3))

One dimension may be given as -1, meaning “work it out for me”: x.reshape(-1, 1) turns any 1-D array into a column, and x.reshape(2, -1) makes 2 rows of whatever length fits. scikit-learn often asks for a 2-D input, and x.reshape(-1, 1) is the standard way to turn one feature into the matrix it wants.

The 12 numbers keep their colours (light for small, dark for large). Pick a shape: they always fill row by row. Then switch on .T and see rows become columns: the colours now run down the columns.

Transpose: rows become columns

A.T (an attribute, no brackets) is the transpose: element [i, j] moves to [j, i], so a (2, 3) array becomes (3, 2). In maths this is written \(\mathbf{A}\T\) (“A transpose”). Here is ISLP's x_reshape (after the change you will meet in section 12) and its transpose, In[24]:

12. The copy-versus-view trap

ISLP (p. 44) shows something that surprises everybody the first time. Change one element of x_reshape and the original x changes too:

x = np.array([1, 2, 3, 4, 5, 6]), x_reshape = x.reshape((2, 3)), then x_reshape[0, 0] = 5. What is x now?

  1. [1 2 3 4 5 6]: we changed x_reshape, not x
  2. [5 2 3 4 5 6]
  3. An error: you cannot change a reshaped array
reshape did not copy the numbers. It made a new view: a new way of looking at the same memory. Writing through the view writes into that memory, so x sees the change. ISLP: “the two objects occupy the same space in memory”.
x = np.array([1, 2, 3, 4, 5, 6])
x_reshape = x.reshape((2, 3))
x_reshape[0, 0] = 5
print("x_reshape:\n", x_reshape)
print("x:", x)          # changed too!
print(np.shares_memory(x, x_reshape))
Read the output: x now starts with 5, and np.shares_memory confirms True: one block of memory, two shapes.

A view is an array that borrows another array's memory. NumPy makes views whenever it can, because copying millions of numbers is slow. The rule:

OperationGives
basic slices x[2:5], A[:, 1], A[::2]; reshape; .Tview (shares memory)
fancy indexing x[[1, 3]]; boolean masks x[x > 0]; arithmetic x + 1; flatten; .copy()copy (new memory)
signal = np.arange(10)
first_half = signal[:5]          # a VIEW
first_half[:] = 0                # zero it... and the original changes
print(signal)

signal = np.arange(10)
safe = signal[:5].copy()         # an independent COPY
safe[:] = 0
print(signal)                    # untouched
picked = signal[[0, 1, 2]]       # fancy indexing always copies
picked[0] = 99
print(signal[0])
Read the output: the first print shows five zeros at the front of signal; the second shows signal intact; the last prints 0, because picked was a copy and changing it did nothing to signal.

The bug this causes. You write a function that “cleans” a slice of your data, and discover later that it silently changed the original dataset too. When you want to modify something without touching the source, call .copy() first. The same issue appears in pandas (see pandas).

Interview question: “What is the difference between a view and a copy in NumPy, and which operations return which?” Answer with the table above, plus the reason: views avoid copying memory, so slicing a huge array is instant.

D = design(np.array([1, 2, 3]))
assert D.shape == (3, 2), f"shape should be (3, 2), got {D.shape}"
assert np.allclose(D, [[1, 1], [1, 2], [1, 3]]), f"got\n{D}"
D2 = design(np.linspace(0, 1, 5))
assert D2.shape == (5, 2) and np.all(D2[:, 0] == 1) and np.allclose(D2[:, 1], np.linspace(0, 1, 5)), "first column ones, second column x"

vstack stacks as rows, giving shape (2, n). You want each array as a column.

np.column_stack([np.ones(len(x)), x]), or take the transpose of the vstack.

def design(x):
    return np.column_stack([np.ones(len(x)), x])

column_stack turns each 1-D input into a column. The ones are floats, so the whole matrix is upcast to float. You will build exactly this matrix by hand in Project 1.

In DSP the first difference is \(d[n]=x[n+1]-x[n]\). Write diff(x) returning it for a 1-D array, using two slices (no loop, and don't call np.diff). For [1, 4, 9, 16] it gives [3, 5, 7].

def diff(x):
    out = []
    for n in range(len(x)):        # a loop, and off by one
        out.append(x[n + 1] - x[n])
    return np.array(out)

assert np.array_equal(diff(np.array([1, 4, 9, 16])), [3, 5, 7]), f"expected [3 5 7], got {diff(np.array([1, 4, 9, 16]))}"
xs = np.random.default_rng(0).normal(size=50)
assert np.allclose(diff(xs), np.diff(xs)), "should match np.diff on random data"
assert diff(np.array([5.])).size == 0, "one sample has no differences: return an empty array"

Line up two shifted copies: x[1:] is \(x[n+1]\), and x[:-1] is \(x[n]\). They have the same length.

def diff(x):
    return x[1:] - x[:-1]

Two views of the same signal, offset by one sample, subtracted elementwise. This “shifted slices” trick is how you vectorise anything of the form \(f(x[n], x[n+1])\).

Write rms(x) returning the root-mean-square \(\sqrt{\tfrac1n\sum x_n^2}\) of a 1-D array, and peak_index(x) returning the index of the sample with the largest absolute value. For a full cycle of a unit sine sampled at 8 points, RMS is \(1/\sqrt2\approx0.7071\).

def rms(x):
    return np.sqrt(x.mean())

def peak_index(x):
    return x.argmax()

s = np.sin(2 * np.pi * np.arange(8) / 8)
assert abs(rms(s) - 2**-0.5) < 1e-9, f"RMS of a sampled unit sine should be 0.7071, got {rms(s)}"
assert abs(rms(np.array([3., -4.])) - np.sqrt(12.5)) < 1e-12, "rms([3,-4]) = sqrt((9+16)/2)"
assert peak_index(np.array([1., -7., 5.])) == 1, f"the biggest magnitude is -7 at index 1, got {peak_index(np.array([1., -7., 5.]))}"

Square first, then mean, then square root: read the name backwards (root of the mean of the squares).

np.abs(x).argmax() for the peak.

def rms(x):
    return np.sqrt(np.mean(x**2))

def peak_index(x):
    return np.abs(x).argmax()

x**2 squares each sample, np.mean averages them, np.sqrt takes the root. For the peak, the absolute value turns −7 into 7 before searching.

14. Quiz

What is a + b for a = np.array([1, 2, 3]) and b = np.array([10, 20, 30])?

  1. [1, 2, 3, 10, 20, 30]
  2. array([11, 22, 33])
  3. 66
Arrays add element by element. Option 1 is what lists do (concatenation). Option 3 would be (a + b).sum().

A has shape (5, 6). What is the shape of A[2:4, :]?

  1. (2,)
  2. (6,)
  3. (2, 6)
  4. (3, 6)
Two slices keep both axes. Rows 2:4 are rows 2 and 3 (two rows), all 6 columns. (3, 6) forgets that the stop is excluded; (6,) would be A[2, :], an integer index.

For ISLP's A = np.arange(16).reshape(4, 4), what is A[1, 2]?

Row 1 is 4 5 6 7; column 2 of it is 6. In general here A[i, j] = 4*i + j.

What does A[[0, 2], [1, 3]] return for the same A?

  1. array([ 1, 11])
  2. the 2 × 2 block [[1, 3], [9, 11]]
  3. an IndexError
Two index lists are paired: cells (0, 1) = 1 and (2, 3) = 11. For the block you need A[np.ix_([0, 2], [1, 3])]. No error because both lists have length 2.

X has shape (100, 4). How many numbers does X.std(axis=0) return?

Axis 0 (the 100 rows) disappears; one standard deviation per column: 4 numbers.

Which line correctly keeps the values of x that are between 1 and 5 (exclusive)?

  1. x[x > 1 and x < 5]
  2. x[(x > 1) & (x < 5)]
  3. x[x > 1 & x < 5]
and needs a single True/False and raises a ValueError on arrays. Without brackets, & is applied first, to 1 & x, which is not what you meant. Option 2 is the only correct one.

y = x[2:6], then y[0] = -1. Which statement is true?

  1. x is unchanged because y is a copy
  2. Python raises an error
  3. x[2] is now −1, because a basic slice is a view
Basic slices share memory with the original. Use x[2:6].copy() to get an independent array.

What is (np.array([3, -1, 4, -2]) > 0).mean()?

The mask is [True, False, True, False]; True counts as 1, so the mean is 2/4 = 0.5, the fraction of positive values.

Explain to a friend, in two or three sentences, what axis=0 means in X.mean(axis=0), and how you remember it.

Axis 0 is the row direction (down the matrix). Taking the mean along axis 0 combines all the rows, so that axis disappears and you get one mean per column. The rule I use: the axis you name is the one that disappears; for a data matrix with observations in rows, axis=0 gives one summary per variable.

15. Flashcards

What does [1, 2] + [3, 4] give for lists, and for NumPy arrays?
Lists: [1, 2, 3, 4] (concatenation). Arrays: [4, 6] (elementwise).
The four basic attributes of an array?
dtype (element type), shape (tuple of lengths), ndim (number of axes), size (total elements).
np.arange(a, b) vs np.linspace(a, b, n)?
arange: step 1 from a, stop b excluded. linspace: exactly n points, both ends included.
Shape of A[1, :] vs A[1:2, :] for A of shape (4, 4)?
(4,) vs (1, 4). An integer index removes the axis; a slice keeps it.
What does A[[1, 3], [0, 2]] select?
The pairs (1, 0) and (3, 2): two single cells. For the submatrix use A[np.ix_([1, 3], [0, 2])].
How do you combine two conditions on arrays?
(x > a) & (x < b); or |; not ~. Brackets around each condition. Never and/or.
What does axis=0 do in X.sum(axis=0)?
Sums down the rows; axis 0 disappears; one result per column.
Default divisor of np.var?
\(n\). Use ddof=1 for \(n-1\). pandas defaults to \(n-1\).
What is row-major order?
Elements are laid out (and reshaped) row by row: the last index changes fastest.
np.vstack([a, b]) vs np.column_stack([a, b]) for two 1-D arrays of length n?
vstack: shape (2, n), arrays as rows. column_stack: shape (n, 2), arrays as columns.
Which indexing operations give a view, which a copy?
View: basic slices, reshape, .T. Copy: fancy (list) indexing, boolean masks, arithmetic, .copy().
Fraction of elements of x that are positive, in one expression?
(x > 0).mean(): True counts as 1.
